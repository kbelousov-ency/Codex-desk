Сжать свою проектную память: индекс и тяжёлые заметки. Ничего не терять, резать только объём.

Память копится дописыванием и никогда не убывает. Индекс (`MEMORY.md`) едет в КАЖДОМ запросе — у разросшегося проекта это 6–8 тысяч токенов до первой строки задачи. Тела заметок всплывают выборочно, но крупная заметка бьёт больно, когда всплывает.

## Правило номер один

**Не удаляй заметки и не выбрасывай записи из индекса.** «Мёртвое» по тексту определить нельзя: слова «ПОХОРОНЕН», «ЗАКРЫТ», «заменено» описывают принятое решение, а не состояние кода. Проверка на реальном примере: индекс уверял, что god-object распилен — файл вырос с 1685 до 2306 строк; уверял, что Trello вытеснена — в коде 977 упоминаний в 101 файле. Три догадки подряд оказались неверны.

Если всё же считаешь запись мёртвой — **сначала сверься с кодом**: `Grep` по упомянутым идентификаторам, `Read` файла, `git log` по коммиту. Не подтвердилось — оставляй и сжимай как остальное.

## Шаги

### 1. Найти свою память

Слаг проекта = путь текущей папки, где `:`, `\` и `/` заменены на `-`. Литерал обратного слэша в однострочнике не пиши — он рвётся в шелле, бери `chr(92)`:

```
python -c "import os;cwd=os.getcwd();s=''.join('-' if c in ':/'+chr(92) else c for c in cwd);d=os.path.expanduser('~/.claude/projects/')+s+'/memory';print(s,d,os.path.isdir(d))"
```

Не нашлось — ищи по имени репы среди `~/.claude/projects/*/memory`. Памяти нет вообще — скажи об этом и закончи.

Про `~/.claude-acct-*`: там `projects` — junction на ту же папку. Это ОДНА память, видимая по двум путям, а не две; чинить надо один раз.

### 2. Снять мерку и сделать копию

Скопируй папку памяти рядом в `projects/<slug>/memory.bak-<ГГГГММДД>` (не во временный каталог — его чистят между вызовами). Затем посчитай: размер `MEMORY.md`, число заметок, размеры тел по убыванию, накопленный процент, файлы без строки в индексе и строки индекса без файла.

Ориентир: строка индекса длиннее ~150 символов и медиана тел больше ~4 КБ — работа нужна. Половина всех байт обычно лежит в первых 10–16 заметках.

### 3. Переписать индекс

Каждая запись остаётся, включая осиротевшие файлы — им строку **добавить**. Цель: ≤110 символов на строку.

Вынеси статусы в метки, легендой одной строкой сверху:

```
Метки: ⛔ не задеплоено · 🔨 не построено · ✖ отменено · ⚠ грабли
```

Убери: хеши коммитов (их держит git), даты, если не несут смысла, номера тестовых прогонов, повторы вроде «НЕ закоммичено/нужен рестарт» в каждой второй строке.
Сохрани: ⚠-грабли, имена компонентов и идентификаторы в точном написании, ссылки на файлы.

```
БЫЛО:  - [Token economics / ledger](x.md) — EconomicsService+spend.jsonl (!spend, дашборды); срезка
       queryable через record_strip. ⚠️ total_cost_usd = кумулятив ⇒ старые $ ×2.9; починено 28.08,
       историю чинить tools/repair_cumulative_spend.py --apply. Компакт: 🪙 0 в футере, реально $0.4–0.85.
СТАЛО: - [Token economics](x.md) — леджер+!spend; ⚠ total_cost_usd кумулятив, чинить repair_cumulative_spend.py
```

### 4. Сжать тяжёлый хвост тел

Иди по размеру сверху вниз, пока не наберёшь ~половину всех байт. Остальные не трогай — там уже нечего вынимать.

Крупная заметка почти всегда журнал сборки: два десятка абзацев «коммит X, TDD, сетка 1174, НЕ закоммичено, нужен рестарт». Это и есть материал для реза.

**Сохраняй:**
- решения и почему они приняты, особенно «решили НЕ делать, потому что…» — их переигрывают чаще всего
- ⚠-грабли целиком: чем дороже далась находка, тем дословнее
- имена модулей, ключи конфига, id, скоупы, пороги, регулярки
- утверждения, подтверждённые замером или живой пробой

**Выбрасывай:**
- хронику по коммитам и счётчики тестов
- пересказ того, как шло обсуждение с человеком
- промежуточные состояния, отменённые следующим абзацем
- то, что и так читается из кода: структуру пакета, списки файлов, сигнатуры

Язык заметки не меняй: русскую оставляй русской, английскую английской. Идентификаторы — латиницей в точном написании. `[[ссылки]]` сохраняй и добавляй недостающие.

Остановись, когда очередная заметка жмётся меньше чем на треть, — значит пошли плотные живые факты.

### 5. Проверить целостность

Число заметок на диске = числу ссылок в индексе; битых ссылок нет; дублей нет; осиротевших нет. Отдельно проверь, что все `[[имена]]` в телах разрешаются в существующие файлы (висячая — не ошибка, это метка «написать потом», но новых плодить не надо).

Сошлось — удали копию из шага 2.

### 6. Отчитаться

Коротко и числами: индекс было/стало в символах и токенах, сколько заметок сжато и на сколько процентов, что сохранено дословно, какие утверждения проверял по коду и что нашёл. Если нашёл расхождение памяти с кодом — назови его отдельной строкой, это самое ценное в заходе.
