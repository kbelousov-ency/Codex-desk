# Установка приложения и настройка агентов

Запрос 2026-09-21: полноценный Windows-установщик в оформлении Codex Desk, выбор Codex/Claude CLI галочками, импорт конфигурации Codex с портала и предложение войти в Claude. Согласован сценарий «Setup → мастер внутри приложения → рабочее место»: повторное открытие мастера доступно в настройках. Причина выбора встроенного мастера — повторное использование авторизации, возможность вернуться после отмены и добавить второго агента позже.

## Установщик и компоненты

`scripts/installer.mjs` собирает NSIS для текущего пользователя; `installer-branding.mjs` и `installer.nsh` задают оформление и страницы. Установка оболочки не требует Node.js или прав администратора. `release:installer` использует утверждённые байты Release; `--nightly` собирает отдельный пробный установщик из текущего либо ожидающего применения Nightly в `artifacts/installer-nightly`. Пробный установщик не продвигает Nightly в Release; правила поставки — [RELEASES.md](RELEASES.md).

2026-09-22: исправлен контраст «Открыть Codex Desk» на последней странице Setup. Windows visual styles игнорировали `SetCtlColors` у checkbox (известный MUI bug #443), оставляя чёрную подпись на тёмном фоне. `DeskFinishPageShow`, подключённый через `MUI_PAGE_CUSTOMFUNCTION_SHOW`, отключает тему только у `$mui.FinishPage.Run` после создания элемента и задаёт `MUI_TEXTCOLOR` `E3E5E5` / `MUI_BGCOLOR` `181A1C`. Сохранены штатная галочка и запуск приложения; ветка с требованием перезагрузки не обращается к отсутствующему Run. Одной смены общей палитры недостаточно: themed checkbox её игнорирует.

`SetupWizard.tsx` показывает шаги «Агенты», «Конфигурация», «Вход в аккаунт», «Память», «Готово». Шаг [«Память»](MEMORY_RULES.md) предлагает явно подключить общие правила отдельно для Codex и Claude; тот же раздел доступен в настройках. Текст включён в поставку, просмотр не меняет файлы. `SetupService` в host различает `installed`, `missing`, `error`; наличие CLI подтверждает `--version`. Работающий компонент не переустанавливается автоматически. Для Codex CLI в настройках доступно отдельное действие «Обновить CLI», использующее штатную команду codex update; после проверки версии вкладки подключаются заново. Ошибочный сохранённый путь требует «Указать путь»; выбранный `.exe` проверяется перед сохранением. Ошибка одного компонента не мешает продолжить с другим. Git — дополнительная галочка, отсутствие Git не блокирует чат.

Установка запускается только по действию пользователя и только в Windows:

- Codex: `https://chatgpt.com/codex/install.ps1`, `CODEX_NON_INTERACTIVE=1` подавляет вопросы и предложение запустить Codex в конце.
- Claude: `https://claude.ai/install.ps1`; самостоятельная установка не требует Node.js.
- Git: `winget install --id Git.Git --exact --source winget` с принятием соглашений и без интерактивного ввода; при отсутствии winget показывается ссылка на сайт Git. Windows может запросить права для стороннего компонента.

Скрипты выполняются отдельным скрытым PowerShell с `-NoProfile`, `-NonInteractive`, `-EncodedCommand`, таймаутом 15 минут. Аргументы и URL фиксированы host; произвольные команды от renderer не исполняются. Неуспешный exit не объявляется успехом; финальная проверка снова запускает `--version`. stdout/stderr установщиков не публикуются в UI или диагностике ошибок.

Обнаружение учитывает ещё не обновившийся `PATH`: Codex в `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin`, `CODEX_INSTALL_DIR`, `CODEX_HOME\packages\standalone\current`, npm native x64/ARM64 и расширения VS Code; Claude в `%USERPROFILE%\.local\bin` и современных npm native-пакетах. `.cmd`-обёртки не запускаются. После установки каталог найденного бинарника добавляется в окружение текущего приложения; постоянный пользовательский `PATH` обновляет официальный установщик. Старые npm-варианты Claude без native `.exe` требуют самостоятельной миграции либо выбора установленного native CLI.

## Импорт конфигурации Codex

Основной путь — [подключение через браузер](ROUTER_CONNECT.md): мастер создаёт device-заявку, открывает подтверждение с кодом и получает provider/defaults без скачивания файла. После предпросмотра «Применить настройки» сохраняет отдельные поля через native `config/batchWrite` с backup и `expectedVersion`; другие настройки, MCP и effort сохраняются. Ключ записывается в `experimental_bearer_token` стандартного конфига и используется также терминальным Codex. Первоначальный вывод о несовместимости API по web-bundle был ошибочным: старый web download и внешний device API могут сосуществовать. Ниже описан сохранённый ручной импорт, заменяющий файл целиком.

Мастер предлагает открыть `https://coder-portal.encycam.com` и выбрать скачанный `.toml` через системный диалог. Код не скачивает пользовательский конфиг сам и не хранит учётные данные портала. Стандартный путь — `%USERPROFILE%\.codex\config.toml`. При абсолютном `CODEX_HOME` используется `<CODEX_HOME>\config.toml`; UI отдельно объясняет фактический и стандартный пути. Относительный `CODEX_HOME` отклоняется.

Это полный пользовательский конфиг Codex, общий с терминалом. Явный импорт может изменить провайдера, модель, effort, MCP и другие настройки терминального Codex. Автоматическое объединение отвергнуто: смешанные настройки провайдеров/MCP могут быть несовместимы. Применение заменяет файл целиком, сохраняя точные байты выбранного файла, комментарии и окончания строк.

Preview допускает обычный непустой TOML в UTF-8 до 2 МБ, использует `@iarna/toml`; symlink-файл отклоняется. UI получает только имя файла, пути, признак существующего конфига и одноразовый `previewId` на 10 минут. Текст, ключи и значения остаются в памяти host; parser errors не цитируют содержимое. Это проверка синтаксиса TOML, не гарантия поддержки всех параметров установленной версией Codex. Применимость проверяется последующим подключением CLI.

Существующий конфиг заменяется только с `replaceExisting:true`. До записи сохраняется `config.toml.backup-<timestamp>-<uuid>` через `wx`, mode `0600`, с точными исходными байтами; ошибка backup прекращает импорт. Резервные копии не удаляются автоматически и могут содержать секреты. Источник и назначение проверяются по SHA-256 и метаданным перед подготовкой и непосредственно перед commit; устаревший preview отклоняется. Новый файл появляется через эксклюзивное создание ссылки, существующий — через атомарный `rename` подготовленного файла. Межпроцессного CAS для существующего файла нет: между последней проверкой и `rename` остаётся короткое окно внешней записи. Поэтому при импорте не следует одновременно редактировать этот config другим процессом.

Для ручного возврата завершите задачи Codex и закройте внешние редакторы конфигурации; сохраните текущий `config.toml` отдельно и скопируйте нужный `config.toml.backup-…` на показанный мастером путь `config.toml`. Не перемещайте файлы авторизации и историю. Затем переподключите вкладки Codex либо перезапустите CLI, чтобы он перечитал конфигурацию. Сам импорт не удаляет историю, навыки, авторизацию или SQLite-базы.

## Авторизация и параллельная работа

`setup-auth.mjs` проверяет Claude штатным `claude auth status` в окружении приложения, включая сохранённый постоянный токен; подробности — [CLAUDE.md](CLAUDE.md). Codex проверяется через служебный App Server `account/read` с `refreshToken:false`; состояние провайдера без требования OpenAI auth отображается отдельно. Вход запускает видимое штатное окно CLI и браузер; пользователь завершает его самостоятельно. Проверка статуса и закрытие окна не подменяют подтверждение успешного входа. Настройка и проверки не отправляют запрос модели.

Host последовательно резервирует установку, выбор бинарника и импорт; активные задачи выбранного агента должны завершиться до изменения настройки. Мастер не закрывает пользовательские терминалы. При завершении приложения ожидается текущая операция; `dispose()` не убивает сторонние процессы или окно авторизации. Состояние мастера хранится отдельно в `setup.json`: `started`, `completed`, `deferred`; незавершённая первая настройка возобновляется после перезапуска, даже если установка CLI уже создала `settings.json`.

## Проверки и пределы

`tests/setup-service.test.mjs` и `tests/host-utils.test.mjs` проверяют обнаружение CLI, официальные команды через подставные процессы, отсутствие переустановки, выбор другого бинарника, последовательность операций, TOML/секреты, точность backup, устаревшие/повторные/конкурирующие preview, ошибки записи и продолжение первой настройки. Реальные установщики CLI в разработке не запускались; сценарий на чистой Windows требует отдельной проверки. Чтением текущих `--version` подтверждено обнаружение Codex `0.154.0`, Claude `2.1.278`, Git `2.52.0.windows.1`; пользовательский config при этом не читался по содержимому и не изменялся. Финальные проверки UI/IPC и идентификаторы поставки фиксируются в [RELEASES.md](RELEASES.md).
