# Codex Desk: контекст для следующего ИИ

Состояние сверено с исходниками 2026-09-17. Это документация проекта, а не обещание автоматической загрузки файла каждым ИИ-клиентом. Точка входа — [AGENTS.md](../AGENTS.md); инструкция пользователя — [README.md](../README.md).

Последующее исправление первой версии: [авторежим, прокрутка, пояснения](UI_FIXES.md). Ниже сохранены проверенные факты исходной реализации; изменения поведения перечислены в этой заметке.

Поддержка параллельной работы: [независимые окна и сессии](SESSIONS.md). Прежний единственный App Server заменён отдельным процессом для каждого окна; смена папки и закрытие затрагивают только это окно. Остальные контракты протокола ниже сохраняются.

Последующее уточнение пользователя: отдельные окна неудобны. Текущий интерфейс — [рабочие папки и вкладки диалогов](TABS.md), отдельный процесс теперь принадлежит вкладке. Решение с несколькими окнами и причины его замены сохранены в [SESSIONS.md](SESSIONS.md).

Добавлены [оценка кэша и автопинг](CACHE.md): реальные cache token counters, настраиваемый срок и обычное видимое сообщение в существующую беседу. В новых вкладках автопинг выключен.

Добавлены [команды оболочки и штатный compact](COMMANDS.md): меню по `/`, локальные действия и `thread/compact/start` в текущей беседе. В окне токенов кнопка сжатия заменила пояснение о возможной экономии.

Кнопка [«Терминал»](TERMINAL.md) под чатом продолжает текущую беседу через `codex resume <threadId>` в видимой консоли. На время работы в терминале вкладка приостанавливает App Server; после закрытия перечитывает историю.

[Управление диалогами и архив](ARCHIVE.md): меню ⋮, штатные name/archive/delete/unarchive, архив по папкам и отдельные вкладки только для чтения. Под чатом доступ расположен перед терминалом.

[Настройки MCP](MCP.md): импорт вставленного TOML или JSON `mcpServers` через штатный config/batchWrite с preview, backup и защитой от конкурирующей записи. Прежнее правило «оболочка не пишет конфиг Codex» уточнено: MCP сохраняется только по явному действию пользователя; остальные настройки остаются прежними.

[Чат как в мессенджере и поиск](CHAT_SEARCH.md): сообщения пользователя справа, Codex слева, поиск внутри диалога и по названиям бесед, включая архив.

[Диагностика](DIAGNOSTICS.md): автоматические ограниченные локальные журналы, ошибки host/renderer/App Server и экспорт одного JSON через кнопку внизу слева. Никакие данные автоматически не отправляются. Сборка получает отпечаток исходников, чтобы различать поставки одной версии.

[Три режима доступа](ACCESS.md): «Спрашивать разрешение», «Одобрять за меня», «Полный доступ». Новый default — ручные подтверждения; явно сохранённые legacy режимы продолжают действовать до явного переключения. Прежнее устройство ниже сохранено как история решений.

[Release/Nightly](RELEASES.md): два постоянных каталога, отдельные ярлыки/профили; обычная сборка обновляет только Nightly. Продвижение в Release после явного подтверждения копирует проверенную сборку без перекомпиляции. Старые тематические release пути ниже относятся к прежним поставкам и больше не задают процесс сборки.

Nightly принимает сборку через очередь; после уточнения пользователя закрывается только по кнопке «Закрыть» в чате или вручную после «Отмена». Подробности и прежнее разрешение автоперезапуска сохранены в [каналах](RELEASES.md#автоматическое-применение-nightly). Не ждать своего закрытия синхронно внутри model turn; package возвращается после запуска помощника.

## Принятое устройство и причины

```text
React UI → window.codex (preload) → Electron IPC → CodexClient
                                                   ↓
                              codex app-server --listen stdio://
                                                   ↓
                              существующие настройки и провайдер Codex
```

Выбран App Server: он отдаёт структурированные события, историю и запросы подтверждений. Обсуждавшийся вариант встраивания терминального экрана и разбора его перерисовок не выбран: он сложнее для полноценного чата, вложений и diff. Это собственный клиент установленного Codex, а не терминальный экран внутри окна.

Прямой API модели вместо Codex не используется. Не задаются новые `baseInstructions`, `developerInstructions`, `personality`; по возможности наследуются CLI-настройки. Одинаковые настройки не гарантируют идентичные ответы.

В проверенной локальной конфигурации использовались `model=gpt-6-astra`, `model_reasoning_effort=ultra`, `model_reasoning_summary=detailed`, `model_provider=router`. Это наблюдение на этом компьютере, не значения для жёсткого кодирования. Каталог моделей читается из `model/list`, включая страницы `nextCursor`.

## Контракты и места, где легко ошибиться

### Подключение и конфигурация

- При создании использован `codex-cli 0.154.0-alpha.6.2`; схемы `protocol/` получены этой версией. При проверке глубины 2026-09-17 установленный бинарник сообщил `0.154.0`; схемы не перегенерированы. После обновления сравнивать реальный протокол, а не полагаться только на новые веб-примеры.
- Инициализация: `initialize`, затем `initialized`; `experimentalApi:true`, `requestAttestation:false`. Процесс запускается без shell и со скрытым служебным окном.
- События моста: `notification`, `serverRequest`, `status`, `diagnostic`. В статусе поле **`data.state`**, не `data.status`.
- `window.codex.start()` возвращает `initialize`, `models`, `account`, `config`, `cwd`, `executable`. `config` — очищенный объект; `account` — ответ `account/read`.
- `account:null` вместе с `requiresOpenaiAuth:false` допустим для настроенного провайдера. Не объявлять такой сеанс неавторизованным.
- Настройки оболочки `model`/`effort` имеют приоритет при следующем запуске; без них используются значения Codex. При resume восстанавливаются фактические модель и effort беседы.
- `publicConfig()` пропускает только выбранные ключи. Полная конфигурация может содержать секреты провайдера/MCP; не отправлять её в renderer.
- При смене рабочей папки перезапускается собственный App Server. Повторный start для того же executable/cwd использует готовое соединение.

### Доступ

- `inherited` опускает override. Новая беседа наследует Codex; возобновлённая может сохранить доступ ранее открытого диалога.
- Явные режимы: `read-only`, `workspace-write`, `danger-full-access`. На `thread/start` используется строка `sandbox`, на `turn/start` — объект `sandboxPolicy`.
- Для read/workspace: `approvalPolicy:'on-request'`, `approvalsReviewer:'user'`, сеть выключена. Для full: `approvalPolicy:'never'`, `sandboxPolicy.type:'dangerFullAccess'`.
- `workspaceWrite` содержит `writableRoots:[cwd]`, `networkAccess:false`, `excludeTmpdirEnvVar:false`, `excludeSlashTmp:false`. Это оставляет стандартные временные каталоги; название «Папка проекта» не означает абсолютного запрета записи во временные файлы.
- Выбор full требует подтверждения в интерфейсе; сохранённый full не активируется автоматически при запуске окна. Но inherited может получить полный доступ из CLI-конфигурации или resume старой беседы. Общая фраза README об обязательном подтверждении полного доступа не описывает эти случаи; это расхождение документации и кода.
- Возврат с явного режима в inherited при открытой беседе создаёт новый диалог, чтобы старые overrides не остались незаметно.
- Во время выполнения смена проекта/модели/effort/доступа заблокирована. Новые настройки применяются к следующему запросу.

### События, подтверждения и история

- `turn/started`, `turn/completed`, `item/started`, `item/completed` задают жизненный цикл. Текст приходит через `item/agentMessage/delta`; команды — `item/commandExecution/outputDelta`.
- Пояснения приходят через `item/reasoning/summaryTextDelta` и поддерживаемые reasoning items. UI показывает только реально полученное. Простая живая тестовая задача не прислала reasoning вообще — это допустимо.
- Изменения: `fileChange` items и `turn/diff/updated`. Это события Codex, не полный Git-статус всех изменений пользователя.
- В `thread/list` явно указаны `sourceKinds:['appServer','cli','vscode']`: значения по умолчанию могут скрыть собственные диалоги клиента. Фильтр `cwd` точный.
- Для `legacy` используется `thread/resume` с полной историей. Для `paginated` — `excludeTurns:true`, `thread/items/list` и `thread/turns/list`.
- При первой проверке новые беседы были `legacy`, а `thread/items/list` вернул `not supported yet`. 2026-09-18 настоящий CLI `0.154.0` успешно прочитал paginated-историю и возобновил её изолированную копию: [сбой открытия и восстановление](THREAD_RECOVERY.md).
- События могут прийти во время загрузки истории. Не перезаписывать свежие сообщения или завершение хода более старым результатом resume.
- Подтверждения команд/файлов: `{decision:'accept'|'decline'|...}`. Для permissions — `{permissions:{...},scope:'turn'|'session'}`, отказ — пустой `permissions`.
- Ответ на вопросы: `{answers:{[questionId]:{answers:string[]}}}`. `isSecret` требует password input.
- `serverRequest/resolved` удаляет ожидающий запрос и в UI, и в транспорте. `client.respond()` асинхронен: обязательно `await`, затем убрать запрос.
- Не отправлять универсальное «accept» неизвестному serverRequest. Формы MCP пока можно отклонять; неподдерживаемый dynamic tool получает ответ об ошибке.

### Изображения и данные

- PNG/JPEG/WebP/GIF; UI — до 10 вложений, до 20 МБ каждое. Host — до 12 за вызов, до 20 МБ каждое и до 60 МБ суммарно. Host проверяет сигнатуру файла.
- В `turn/start` отправляются `localImage` с локальным путём; текст содержит `text_elements:[]`.
- При замене оптимистичного `userMessage` серверным сохранять `previews` по `clientId`, иначе картинка исчезнет после отправки.
- `readAttachment(path)` восстанавливает data URL только из собственного каталога attachments после проверки realpath; внешний/отсутствующий файл даёт `null`.
- Настройки оболочки: `settings.json` в `app.getPath('userData')`, ключи `cwd`, `model`, `effort`, `access`, `executable`. Вложения: `attachments/` там же. При диагностике узнавать фактический userData у Electron, не рассчитывать только на приблизительный путь из README.
- История/авторизация принадлежат Codex. Не редактировать SQLite напрямую. Вложения не очищаются автоматически: на них ссылается история.
- Renderer: `contextIsolation:true`, `nodeIntegration:false`, `sandbox:true`, CSP; IPC проверяет отправителя и allowlist. Изначально `openPath` только показывал файл в проводнике. По запросу пользователя это заменено на [открытие по клику и меню ПКМ](FILE_LINKS.md); границы проекта по-прежнему проверяются.

## Запуск, сборка и проверки

Рабочая папка: `E:/My projects/CodexDesk`. Windows PowerShell на этой машине запрещает запуск `.ps1`; использовать `npm.cmd`, а не `npm.ps1`. `Create Shortcut.ps1` как файл был заблокирован ExecutionPolicy; ярлык создан эквивалентными командами через `WScript.Shell` без изменения системной политики.

Нужен Node.js **22.12+** для установленного Electron 44.4.1. При создании использовался Node.js 24.16.0. README пишет более общее «22+»; точный нижний предел здесь указан по `node_modules/electron/package.json`.

| Команда | Что проверяет/делает |
| --- | --- |
| `npm.cmd install` | Зависимости по package.json/lock. |
| `npm.cmd run dev` | Vite на `127.0.0.1:5178` + Electron. |
| `npm.cmd run build` | TypeScript без emit + production Vite bundle. |
| `npm.cmd start` | Запуск текущего dist через Electron. |
| `npm.cmd test` | Node-тесты транспорта/host; без модели. |
| `npm.cmd run smoke` | Настоящий App Server, чтение моделей/конфига/истории, без turn. |
| `npm.cmd run test:ui` | Настоящее окно и соединение, вставка PNG; без model turn. Требует dist. |
| `npm.cmd run test:scenarios` | Подставной bridge в Edge: streaming, доступ, diff, approvals, stop. Требует dist и Edge. |
| `node scripts/live-smoke.mjs` | Короткий реальный запрос модели в ephemeral read-only беседе. Расходует лимит. |
| `node scripts/live-ui-smoke.mjs` | Реальная картинка + ответ + перезапуск и resume. Расходует лимит; требует `artifacts/red-square.png`. |
| `npm.cmd run package` | Build + electron-builder, результат `release/win-unpacked/Codex Desk.exe`. |

`live-ui-smoke` использует заранее созданный красный PNG 128×128 и отдельную папку `artifacts/live-test`; сам PNG скрипт не генерирует. Живая беседа этого теста сохраняется в истории Codex. Не запускать реальные запросы только ради правки документации.

Переменные: `CODEX_DESK_DEV_URL` (локальный Vite), `CODEX_DESK_DATA_DIR` (отдельный userData), `CODEX_DESK_TEST=1` (обойти single-instance для тестов), `CODEX_DESK_PACKAGED` (путь к проверяемому exe в ui-smoke). `scripts/start.mjs`, `scripts/dev.mjs` и тестовые запуски удаляют унаследованный `ELECTRON_RUN_AS_NODE`; иначе окно может не запуститься.

У пользователя запускается **сборка**, поэтому изменение только `src/` не обновляет ярлык. После поставки кода пересобрать package и проверить exe. Перед упаковкой закрыть своё окно приложения. ## Известные ограничения и дальнейшие изменения

Нет отдельного редактора, Git staging/rollback, мастера входа, автообновления, полной поддержки MCP-форм и очистки вложений. Закрытие окна останавливает собственный процесс Codex; фоновая работа после закрытия не реализована. Прежнее ограничение проверки paginated history уточнено в [THREAD_RECOVERY.md](THREAD_RECOVERY.md).

В первой версии не открывались относительные Markdown-ссылки, Windows drive после стандартной фильтрации ReactMarkdown и пути с суффиксом `:line`. Исправлено в [файловых ссылках](FILE_LINKS.md): прежний regex и стандартный urlTransform блокировали эти форматы, а ошибки openPath скрывались. Причина сохранена для будущих изменений.

Рабочая среда агента периодически давала `helper_sandbox_lock_failed` / `SetNamedSecurityInfoW ... 5` даже для чтения. Это ограничение инструментальной среды, не доказательство ошибки приложения. В исходной сессии узкие разрешённые команды выполнялись через отдельную проверку разрешений; системные ACL/политики не менялись.

При обновлении протокола сверять схемы установленного бинарника и [официальную документацию App Server](https://developers.openai.com/codex/app-server). Не переносить в код секреты, абсолютный путь конкретной версии VS Code extension или наблюдавшийся каталог моделей.
