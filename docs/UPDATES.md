# Онлайн-обновления приложения

## Проверка через каталог портала роутера — 2026-10-15

Проверка обновлений переведена с GitHub Releases на каталог «Приложения» портала
роутера: `GET https://coder-portal.encycam.com/api/apps/codex-desk` (карточка
`codex-desk`). Установщик туда заливает Jenkins при каждом изменении `master` в
Gerrit ([JENKINS.md](JENKINS.md)); версия каталога — `X.Y.Z.<номер сборки>`, и в
каталоге хранится только последний установщик. Контракт, правила сравнения версий
и границы ошибок — [ROUTER_UPDATES_CONTRACT.md](ROUTER_UPDATES_CONTRACT.md).

Что изменилось против прежнего механизма (он описан ниже и сохранён как история):

- Карточку и файл авторизует существующая Portal-сессия приложения (cookie в
  partition `persist:kuzmich-portal`, `credentials: include`, redirect отвергается).
  Без входа в Portal, одобренного ключа и действующего допуска к продукту каталог
  не запрашивается — проверка просит войти. Работает только из сети компании или
  через её VPN; ключ роутера и данные диалогов в запросы не попадают.
- «Скачать обновление» больше не открывает браузер: host сам скачивает установщик
  Portal-сессией во временный файл в папке загрузок, сверяет размер и SHA-256 из
  карточки, атомарно кладёт под свободным именем (существующие файлы не
  перезаписываются) и показывает в папке. Пользователь по-прежнему сам закрывает
  приложение и запускает установщик; автоматической установки нет.
- Версии каталога сравниваются численно по X.Y.Z, при равенстве — по номеру сборки
  Jenkins: установка без номера обновляется на ту же X.Y.Z с известным номером,
  кандидат без номера никого не вытесняет, `0.11.0.10` новее `0.11.0.9` именно как
  числа, не строки. Сборка запоминает свой номер в `build-info.json` (`buildNumber`,
  пишет `scripts/package.mjs` из `BUILD_NUMBER` Jenkins; локальные сборки поля не
  имеют, его проверяет и пропускает дальше `resolveReleaseChannel`).
- Записи каталога с чужим `channel` пропускаются; записи без `channel` допустимы —
  их публикует текущий Jenkins, additive-поля каталога ещё на ревью
  ([ROUTER_UPDATES_CONTRACT.md](ROUTER_UPDATES_CONTRACT.md), ветка
  `feature/codexdesk-update-metadata` в `Python/Coder-Portal`). Пустой каталог —
  «актуальная версия»; 404 карточки — ошибка контракта, не «обновлений нет».
  `skippedVersion` принимает и четырёхкомпонентные версии каталога.
- GitHub Releases больше не опрашивается. По решению владельца 2026-10-15 GitHub
  закрывается после выпуска версии, которая обновляется с роутера: установленные
  сейчас копии смотрят только на GitHub, поэтому переходная версия публикуется и
  там, дальше — только каталог роутера.

Проверки: `tests/app-updates.test.mjs` переписан под каталог — 13 тестов: правила
версий и каналов, allowlist пути файла, авторизационные отказы, ограниченные
сообщения ошибок, скачивание со сверкой SHA-256, повреждённый файл без следов на
диске, объединение запросов, timeout. `test:app-updates` обновлён под новые тексты;
`test:app-updates-host` сохраняет прежние границы: изолированный профиль без сети,
браузера и запросов модели.

## Прежний механизм GitHub — история до 2026-10-15

С версии `0.2.0` Windows x64 Release проверяет публичные выпуски [kbelousov-ency/Codex-desk](https://github.com/kbelousov-ency/Codex-desk/releases/latest). Отдельный сервер и токен GitHub не нужны. Пользователи ранее установленной `0.1.0` должны один раз вручную установить версию с этим механизмом: старый exe не может получить проверку обновлений без обновления самого приложения.

## Поведение

- Первая автоматическая проверка — через 15 секунд после открытия окна, следующие — через 6 часов, пока приложение работает. Между попытками при быстрых перезапусках выдерживается минимум минута. После полного выхода фоновых процессов проверки нет.
- Более новая стабильная версия с готовым Setup вызывает общий баннер над рабочим местом. «Скачать обновление» открывает загрузку официального Setup в браузере; пользователь закрывает приложение и запускает скачанный установщик. Автоматической установки, закрытия и прерывания задачи нет.
- «Позже» скрывает предложение до следующего запуска; «Пропустить эту версию» сохраняется в профиле и не подавляет последующие версии. Пропущенный выпуск доступен для ручного скачивания в окне обновлений.
- Окно «Обновления приложения» открывается значком в верхней панели, нажатием на бейдж сборки или командой палитры. Показывает текущую версию/канал, последнюю успешную проверку, описание выпуска, результат/ошибку, повторную проверку и переключатель автопроверки. Описание — обычный текст.
- Ручная проверка работает и при выключенной автоматической. Успешный результат повторных кликов используется в течение минуты; ошибка позволяет повторить сразу. Недоступный интернет, GitHub rate limit или неполный выпуск показываются внутри окна, без блокировки чата. (Поведение этого списка сохранено и в портальном механизме, кроме загрузки браузером.)
- Nightly/Development не загружают публичный Release поверх своего канала. Существующая локальная очередь Nightly и правило «Закрыть» / «Отмена» сохранены. Тестовые и изолированные профили тоже не делают сетевых проверок.

## Страница «Что нового?»

После обновления стабильного Release приложение один раз показывает локальную страницу «Что нового?». Версия и предыдущий запуск хранятся в отдельном `release-state.json`; настройки, авторизация, история и `updates.json` не изменяются.

Заметки берутся из пользовательских разделов `CHANGELOG.md` и при упаковке попадают в `electron/release-notes.json`, поэтому страница работает без сети. При переходе через несколько выпусков показываются все версии после сохранённой до текущей; для первого запуска существующего профиля показывается текущий выпуск с пометкой, что точная предыдущая версия неизвестна.

Nightly и Development не открывают страницу автоматически. Команда «Что нового?» доступна из Ctrl+K после запуска.

## Устройство и границы

`electron/app-updates.mjs` содержит `AppUpdateService` и отдельный `AppUpdateStore`; `electron/main.mjs` подключает Electron `net.fetch` и IPC с проверкой главного frame/владения окном. Методы preload: `getAppUpdateStatus`, `checkAppUpdates`, `setAppUpdatePreferences`, `openAppUpdateDownload`, подписка `onAppUpdateStatus`.

Запрос только к `https://api.github.com/repos/kbelousov-ency/Codex-desk/releases/latest`, без cookies/credentials, токенов и данных проектов/диалогов. GitHub видит обычное сетевое обращение. Timeout 15 секунд, ответ до 1 МиБ, описание до 12 000 символов, redirects API отвергаются. Одновременные проверки объединяются. Выключение автопроверки и выход отменяют запрос; запоздалый ответ не показывает новое предложение.

Принимается обычный выпуск (`draft:false`, `prerelease:false`) с тегом `vMAJOR.MINOR.PATCH`. Сравнение компонентов числовое, не строковое; равная и более старая версии не предлагаются. Нужен asset `state:uploaded`, положительный целый размер и имя `Codex-Desk-Setup-X.Y.Z.exe`; поддержаны исторические `Codex.Desk.Setup.X.Y.Z.exe` и `Codex Desk Setup X.Y.Z.exe`. HTTPS URL обязан указывать на тот же repository/tag/filename, без credentials, query и fragment. Renderer не может передать свой URL в действие загрузки. Загрузка выполняется браузером; приложение не скачивает и не запускает exe и не проверяет его checksum. Контроль размера/SHA-256 для автора выполняется при [подготовке публикации](VERSIONING.md); подпись издателя отсутствует, как и у прежнего Setup.

`updates.json` в профиле канала содержит `enabled` (по умолчанию true), необязательные `skippedVersion`, `checkedAt`, `attemptedAt`. Запись атомарная через существующий JSON store. Параметры Codex/Claude, credentials и история не меняются. При ошибке чтения/записи настройка не считается сохранённой; ошибка загрузки этого файла не мешает запуску приложения.

Версия выпуска определяется `package.json` и упакованным `build-info.json`; правила и команды — [VERSIONING.md](VERSIONING.md), изменения — [CHANGELOG.md](../CHANGELOG.md). Одного нового коммита в Git недостаточно: пользователи получают предложение после публикации обычного GitHub Release с готовым Setup. Публикация, tag и перенос в Release остаются отдельными явно разрешёнными действиями.

## Проверки

`tests/app-updates.test.mjs` проверяет версии, allowlist, ошибки/timeout, ограничение ответа, периодичность, отмену, сохранение настроек, ручную проверку и объединение запросов на подставных ответах. `scripts/ui-app-updates.mjs` — production renderer с fixture. `scripts/ui-app-updates-host.mjs` — настоящий Electron/preload/IPC, чужое окно/frame, сохранение и restart в отдельном профиле, отсутствие запросов сети/моделей. Реальная read-only проверка GitHub API 2026-09-21 обнаружила опубликованный `v0.1.0` и его `Codex.Desk.Setup.0.1.0.exe` с искусственно заданной текущей версией `0.0.0`; браузер/загрузка/установка не запускались.

Проверка того же неизменённого сервиса внутри готового Electron 44.4.1 через `net.fetch` также прошла: `artifacts/app-updates-live-electron-XOgS25/live-electron-result.json`, один публичный metadata-запрос, обнаружен `0.1.0`, браузер/скачивание/модель не запускались. Production-сервис тестового Nightly оставался отключённым; отдельный проверочный сервис и тестовый процесс штатно закрыты.

## Компактная плашка версии — 2026-09-21

Размер постоянного badge сохранён. Вместо native title при наведении или клавиатурном фокусе показывается оформленная компактная подсказка: канал, версия, короткий build ID и дата. Escape её закрывает, клик/Enter по-прежнему открывают окно обновлений. Portal не даёт sidebar обрезать подсказку. Общий cache/IPC метаданных и BuildDetails сохранены. `scripts/ui-build-channel.mjs` проверяет hover/focus/Escape, переход к обновлениям, компактность, независимые вкладки/архив и fallback недоступных метаданных.
