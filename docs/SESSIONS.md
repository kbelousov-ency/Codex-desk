# Независимые окна и сессии — 2026-09-17

Историческое решение. Пользователь попробовал отдельные окна и счёл их неудобными: заменено на [папки и вкладки в одном окне](TABS.md). Изоляция процессов сохранена на уровне вкладок. Ниже сохранено устройство предыдущей версии и его причины.

Задача пользователя: одновременно разрабатывать проект в одной папке и исправлять постпроцессор в другой, как в двух окнах терминала.

## Устройство и причины

Выбраны отдельные окна Electron с собственным App Server для каждого. Это сохраняет существующий интерфейс беседы, черновики, вложения и прокрутку в своём renderer. Переключение одной общей рабочей папки не обеспечивает параллельность: прежде `boot()` останавливал единственный client. Новое окно создаёт отдельный процесс, а смена папки перезапускает только процесс этого окна.

- `electron/main.mjs` хранит записи `{window, session}` по `webContents.id`; IPC проверяет sender и mainFrame и выбирает соответствующую запись. Renderer не передаёт идентификатор чужого окна.
- `electron/window-session.mjs`: `WindowSession` владеет client, cwd, bootstrap, очередью boot, ожидающими approvals и снимком настроек. События доставляются только в своё окно. Совпадающие ID запросов в разных процессах допустимы.
- `stop()` инвалидирует незавершённые и отложенные boot через generation; `dispose()` запрещает повторный запуск после закрытия. Ошибки и закрытие одного окна не затрагивают остальные.
- `SettingsStore` сериализует запись прежнего `settings.json`. Уже открытое окно при reconnect читает свой снимок, поэтому не подхватывает настройки другого окна. Последние записанные значения остаются defaults для запуска из ярлыка.
- Кнопка «Новая сессия» вызывает `host:newWindow`: выбор папки, snapshot настроек исходного окна, новое независимое окно. Доступна во время выполнения. Отмена выбора папки не создаёт окно. Перед вызовом UI сохраняет фактические model/effort/access: после resume они могут отличаться от ранее сохранённых defaults.
- Повторный запуск ярлыка/приложения создаёт ещё одно окно через `second-instance`. Single-instance lock сохраняет один Electron host; число окон и процессов Codex этим не ограничивается.
- Заголовок окна содержит имя папки. «Новый диалог» по-прежнему работает в текущем окне и недоступен во время выполнения.

## Сохранённые контракты и ограничения

Модель/effort и инструкции Codex не переопределяются скрытыми значениями. Полный доступ в новом окне по-прежнему сбрасывается в `inherited` при connect; `inherited` может наследовать полный доступ из конфигурации Codex. Режим `auto` сохраняет `auto_review` и workspaceWrite, как описано в [UI_FIXES.md](UI_FIXES.md).

Общими остаются авторизация, конфигурация и история Codex, лимиты провайдера и каталог attachments в Electron userData. Изоляция сессий не создаёт отдельные аккаунты или копии файлов. Предназначено для разных задач/папок; открытие одной и той же исторической беседы в двух окнах не создаёт две копии беседы. Автовосстановление набора открытых окон не реализовано, беседы продолжаются через историю.

Закрытие окна завершает его App Server; закрытие последнего завершает приложение. Старое ограничение фоновой работы после закрытия остаётся. Внутренние SQLite-базы не изменяются.

## Проверки

`npm.cmd run test:sessions` использует настоящее окно Electron, preload и IPC, но запускает отдельные Node-процессы с подставным JSONL App Server в тестовых папках. Проверяет параллельные ходы, изоляцию одинаковых ID, настроек, подтверждений и остановки. Не отправляет запросы модели. `CODEX_DESK_PACKAGED` позволяет проверить готовый exe. Unit-тесты сессий входят в `npm.cmd test`.

Проверки реального Codex выполняются отдельно: чтение моделей, конфигурации и истории без model turn. Результаты сборки и окончательной проверки фиксируются после выполнения.
