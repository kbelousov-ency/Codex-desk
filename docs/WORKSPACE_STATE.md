# Восстановление рабочего места

Поручено 2026-09-19, пункт 1 [списка идей](ROADMAP.md). Реализация расширяет существующий снимок Nightly на обычное закрытие и аварийное завершение. Рабочие вкладки и черновики принадлежат оболочке; история, авторизация и конфигурация по-прежнему принадлежат Codex.

## Поведение

Сохраняются порядок и активная вкладка, выбранные обычные/архивные беседы, пустые новые вкладки, текст и изображения composer, модель/effort/доступ, очередь и позиция чтения. Если пользователь редактирует отправленное сообщение, `preservedDraft` отдельно удерживает прежний черновик: «Отмена» после перезапуска возвращает его. Закрытие всех вкладок сохраняет пустой список, следующий запуск не создаёт лишнюю вкладку.

С 2026-09-20 `pinned:true` сохраняется для обычных и архивных вкладок; перетаскивание меняет сохраняемый порядок. `pendingMessage:{threadId,clientUserMessageId,kind:'start'|'steer',text,attachments}` удерживает неподтверждённую отправку после RPC timeout для сверки её ID после перезапуска. Validator проверяет соответствие threadId выбранному диалогу, длины полей и вложения; лишние поля отбрасываются. Возврат закрытой вкладки через Ctrl+Shift+T использует такой же UI-снимок в памяти текущего запуска, подробнее [TABS.md](TABS.md).

Автосохранение в renderer: debounce 400 мс, проверка изменившегося состояния каждые 2 с при непрерывном вводе. Состояние снимается и при busy/terminal, без ожидания окончания задачи. История загружается штатным resume/read; ни продолжение задачи, ни сообщения очереди автоматически не отправляются. Очередь после любого восстановления на паузе; автопинг остаётся выключенным.

Обычный restart переводит явный `danger-full-access` в `workspace-write`. Специальный подтверждённый перезапуск Nightly сохраняет прежнюю семантику доступа. Legacy `inherited` не переопределяется. Вкладки терминала возвращаются к обычному подключению, внешний терминал не закрывается; занятый thread остаётся защищён штатным writer-lock.

Прокрутка хранит `scrollTop` и `scrollAnchor:{itemId,offset}` ближайшего сообщения. При наличии anchor предыдущие страницы истории догружаются до сообщения; если оно недоступно/удалено или чтение завершилось ошибкой, остаётся координатный fallback. Восстанавливается место чтения, а не открытость каждого внутреннего блока инструментов. Скрытая вкладка не перезаписывает свою позицию нулём.

## Хранение и завершение

- `electron/workspace-state.mjs` и общий validator `electron/update-checkpoint.mjs`: `workspace-state.json` в фактическом Electron userData текущего канала. История, токены провайдера, полная config и внутренние SQLite не копируются. Сам файл содержит пользовательские черновики и картинки; в диагностику они не включаются.
- Атомарная запись через уникальный временный файл/rename, сериализация save/read/flush. Проверяются до 100 вкладок, до 50 сообщений очереди на вкладку, до 10 изображений в сообщении, сигнатуры изображений, 2 000 000 символов текста, предел снимка 256 МиБ. cwd/executable берутся из host-сессии, не из произвольных renderer-полей.
- IPC: `saveWorkspaceState(snapshot)`, событие `onWorkspaceSave({requestId})`, ответ `completeWorkspaceSave({requestId,snapshot?})`. Перед штатным close/before-quit запрашивается финальный снимок; renderer блокирует ввод/очередь, host отклоняет поздние изменения. Ответ ограничен 2500 мс, затем используется последнее сохранённое состояние. Незавершённое чтение изображения не гарантированно попадёт в снимок; при аварии возможна потеря ввода после последнего успешного сохранения.
- Сбой renderer не вызывает сохранение пустого состояния. Ошибка записи показывается с «Повторить сохранение». Повреждённый файл сохраняется отдельно как `workspace-state.json.invalid-<timestamp>-<uuid>`; если резервирование невозможно, дальнейшая перезапись блокируется.
- `nightly-update-workspace.json` имеет приоритет. `restore.kind` различает `workspace`/`update`; подтверждение восстановления удаляет только одноразовый Nightly checkpoint. Подготовка Nightly также сохраняет постоянный снимок. Ранее восстановление существовало только для специального Nightly restart; старые ограничения в [TABS.md](TABS.md) и [RELEASES.md](RELEASES.md) относятся к прежней реализации.

## Проверки

`tests/workspace-state.test.mjs` проверяет ограничения, атомарность, повреждённые файлы, очередь/доступ, close handshake и изоляцию от Nightly checkpoint. `scripts/ui-workspace-state.mjs` — настоящий production renderer с mock bridge: несколько вкладок, busy autosave, изображения, preservedDraft, delayed/paginated history и anchor, ошибка/retry, close freeze, пустое рабочее место, отсутствие model calls.

`scripts/ui-workspace-state-host.mjs` использует настоящий Electron/preload/IPC, отдельные тестовые профили и fixture App Server: штатное закрытие/перезапуск, renderer crash, восстановление вкладок/черновиков/очереди/архива, сброс полного доступа, запрет позднего autosave/turn/start после close. Пользовательское окно не закрывается, реальных запросов модели нет.
