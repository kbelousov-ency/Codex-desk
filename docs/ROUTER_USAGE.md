# Статистика роутера

С 0.10.0 индикатор также доступен для [явного источника «Роутер»](CONNECTION_SOURCES.md) в Claude и Codex. Запросы используют ключ активного профиля конкретной вкладки; замена сохранённого подключения не подменяет статистику продолжающей работать старой сессии. Личный источник не запрашивает router usage. Описанный ниже поиск ключа сохраняется для наследуемой конфигурации Codex.

Кузьмич умеет читать личную статистику роутера через `GET /v1/me/overview` и
`GET /v1/me/limit` на `https://router.encycam.com`. Это отдельные read-only запросы для вкладки Codex с
`model_provider = "router"`; он не заменяет Codex App Server и не участвует в отправке
сообщений модели.

Ключ сначала берётся из `ANTHROPIC_AUTH_TOKEN` в процессе Electron. Если переменной нет,
используется уже существующий `model_providers.<model_provider>.experimental_bearer_token`
из Codex `config.toml`. В обоих случаях ключ передаётся только в заголовке
`Authorization: Bearer ...`; renderer получает только обезличенный результат запроса.
Ключ не записывается в настройки, URL, историю или диагностику. Если ключа нет, чат и
подключение Codex продолжают работать, а индикатор сообщает, что статистика недоступна.

Индикатор «Роутер» появляется в нижней строке composer. По нажатию он показывает поля
лимит по каждому ключу с отдельными «Потрачено», «Всего», «Осталось» и «Сброс», время
обновления и `coverage`/`sources`, если они возвращены сервером. Null-поля показываются
как «—»: суточный расход не подставляется вместо лимита, а лимиты разных ключей не
складываются. Ошибка или частичный ответ не превращаются в нулевой расход.

## Расход текущего периода из ledger — 2026-09-24

Пользователь сверил расход с доступным ему счётчиком: около 18 658 кредитов из 37 000 до
28.09.2026 соответствует `ledger_used_credits`, а не `used_credits`. Живой ответ
`GET /v1/me/limit` в 07:51:50 UTC: `ledger_used_credits=18635.923965`,
`used_credits=4243.930034`, `limit_credits=37000`, `remaining_credits=32756.069966`,
`used_percent=11.470081`, `bonus_credits=5000`, `reset_at=2026-09-28T03:00:00+00:00`.
В `/v1/me/overview` квота и `used_credits` совпали, а `last_24h.credits=1864.27921`.
Это опровергает актуальность прежнего вывода о пустых числах API; проверка от 23.09 ниже
и [исходный отчёт](../router-limit-null-report.md) сохранены как исторические факты.

Раньше клиент отбрасывал `ledger_used_credits`, а UI доверял `used_credits`,
`remaining_credits` и `used_percent`. Прежний тест запрещал подстановку ledger вместе
с суточным расходом; это решение пересмотрено после сверки пользователя. Теперь IPC
сохраняет оба исходных счётчика, а UI предпочитает конечное числовое
`ledger_used_credits`, включая 0. При его наличии остаток равен
`max(0, limit_credits - ledger_used_credits)`, процент —
`ledger_used_credits / limit_credits * 100` при положительной квоте. Процент не обрезается
на 100 при перерасходе. Серверные `remaining_credits`/`used_percent` в этом случае
не используются: в проверенном ответе они относятся к меньшему `used_credits`.
К `limit_credits` не прибавляется `bonus_credits`: подтверждённый пользователем итог — 37 000.

Если ledger отсутствует, `null` или некорректен, сохраняется прежний fallback на
`used_credits`/`remaining_credits`/`used_percent`. Если ledger известен, а квота нет,
показывается расход, остаток и процент остаются неизвестными; при нулевой квоте процент
тоже неизвестен. Суточный расход не подменяет расход периода, разные ключи не суммируются.
Подсчёта кредитов по токенам или ценам моделей нет. Точный серверный смысл расхождения
между `used_credits` и ledger в предоставленной документации API не определён.

Обновление снимка — при активации вкладки, открытии карточки и по кнопке «Обновить».
Минутный таймер карточки меняет только отсчёт до сброса; периодического опроса сумм нет.

Проверки: `node --test tests/router-usage.test.mjs` — 8/8; `npm.cmd run build` и
`npm.cmd run test:router-usage` прошли. UI проверен на подставных ответах: ledger против
несовпадающих полей API, 0, неизвестная/нулевая квота, перерасход, fallback, отдельные ключи.
Реальные запросы API выше были только read-only, модельные запросы для проверки не отправлялись.
`npm.cmd run package` собрал Nightly `1f866d7f8a95b0ac0cf3aff1318a78a8616aa18593736ce0cea4050f4669ecfc`
в 08:01:15 UTC; очередь создана 08:01:29 UTC и ждёт пользовательского закрытия приложения.
Клиент роутера и все ресурсы renderer в ASAR побайтно сверены с исходной сборкой (8 файлов).
Release не изменён.

## Почему процент лимита не показывается — 2026-09-23

Проверено живым запросом с ключом `coder-k.belousov@encycam.com`: `GET /v1/me/limit` отвечает
`200 OK`, но в единственном элементе `limits[]` поля `limit_credits`, `used_credits`,
`remaining_credits`, `ledger_used_credits`, `bonus_credits`, `used_percent` и `requests`
равны `null`. Заполнены только `key`, `available: true`, `tier: "TierA"`, `state: "ACTIVE"` и
`reset_at`. То же самое в `GET /v1/me/overview`: `limit_credits`/`used_credits`/`remaining_credits`
там тоже `null`.

Отсюда и наблюдение «кредиты и дата сброса видны, а лимит — нет»: видимые кредиты берутся из
`overview.last_24h.credits` (на момент проверки 10 273,08 за сутки, 2973 запроса) — это расход за
окно 24 часа, а не потраченная доля квоты. Дата сброса приходит отдельным полем `reset_at`
(`2026-09-28T03:00:00Z`). Квоты сервер по этому ключу не отдаёт, поэтому процент считать не из
чего; ни `/v1/me/usage`, ни `/v1/me/limit/series` числа квоты тоже не содержат — только расход.
Это ограничение роутера, а не клиента: подставлять суточный расход вместо лимита нельзя.

Индикатор из-за этого не показывает пустое «Роутер · —»: при известной квоте на кнопке стоит
«Роутер · N %», иначе — измеренный суточный расход «Роутер · N кр./сут», а всплывающая карточка
прямо называет `null`-поля причиной отсутствия процента. Чтобы процент появился, роутер должен
начать отдавать `limit_credits`/`used_credits` для тарифа TierA.

Клиент и IPC находятся в `electron/router-usage.mjs`, `electron/main.mjs` и
`electron/preload.cjs`; renderer — в `src/RouterUsage.tsx`. Полный набор исторических,
модельных и вызовных endpoint'ов из `router-me-api.md` пока оставлен для следующего этапа.

## Единое окно кредитов: исследование API — 2026-10-12

Пользователь запросил одинаковые компактные окна Codex/Claude: остаток, общий лимит,
обновление, расход за сессию и сегодня; только Claude имеет дополнительный Fable.
Уточнил: все суммы **в кредитах**, не токенах. Пока подготовлены макеты, рабочий UI
не переделан. Первоначальный вывод, что для Claude и расхода сессии обязательно нужен
новый API, оказался неверен: старый `router-me-api.md` перечисляет не все текущие ручки.

Живые read-only запросы 12.10.2026 в 06:04 UTC (09:04 Asia/Nicosia) подтвердили:

- `/api/relay/limits` портала всё ещё отдаёт проценты/reset/Fable без абсолютных сумм.
  Однако текущий локальный `Coder-Portal/backend/src/boatswainsvc.py:346` уже передаёт
  `limitCredits/usedCredits/remainingCredits`, включая Claude и полосы. Локальный код
  и рабочий ответ расходятся; фактическая версия деплоя не установлена.
- `GET /v1/me/limit/agents?provider=codex|claude` роутера возвращает `available`,
  `limit_credits`, `used_credits`, `reset_at`. Живые квоты: Codex 32000, Claude 24000;
  расход во второй проверке 347.672908 и 0 соответственно. Остаток вычисляется
  `max(0, limit_credits - used_credits)`. Это отдельный проверенный источник для Claude;
  исторический `usage/models: credits:null` не означает отсутствия кредитного учёта.
- `GET /v1/me/turns?provider=codex|claude&since=...&until=...&limit=1` возвращает
  `totals.credits` **по всей выборке**, не только странице. Для «Сегодня» использовать
  явную местную полночь: в проверке `2026-10-11T21:00:00.000Z` соответствует 12.10,
  00:00 Asia/Nicosia. Живой расход: Codex 347.672908, Claude 0; `sources.core/ledger=true`.
  Старый `/usage?period=today` использует UTC и Codex ledger, поэтому не подходит как
  единый источник обоих агентов. Область расхода — ключи аккаунта с фильтром провайдера.
- Тот же `/turns?provider=...&session=<nativeId>&limit=1` даёт расход сессии;
  без `since/until` семидневный фильтр при заданной сессии не применяется. Живые запросы
  по двум существующим серверным сессиям вернули Codex 0.729048 и Claude 194.585709.
  Это проверка возможности API, не суммы активных вкладок пользователя.

Привязка в текущем `AI-tool-cli-proxy`: Codex `core/legs/codex.py:207` предпочитает
`thread-id`, затем `x-codex-window-id/session-id`; Claude `core/legs/claude.py:297`
читает `x-claude-code-session-id`. `core/app.py:1055` сохраняет `CoreCall.session_id`.
В Кузьмиче Codex использует native `thread.id`; Claude — UUID без UI-префикса `claude:`.
Сопоставление конкретной активной вкладки с живыми строками ещё не проверено.

Расчёт серверных кредитов: Codex — `CoreCall.credits_micros`; Claude — взвешенные
токены / серверный `CreditRate.weighted_per_credit` (`me_api/turns.py:95`). Тарифы
не нужно копировать в клиент. Разница общего баланса не даёт расход диалога: включает
другие вкладки/устройства, сбросы и бонусы. Нативные USD/токены CLI не заменяют эти кредиты.

Для реализации проверить полноту `sources`, отсутствие тарифа и глубину журнала:
не превращать неполный ответ в достоверный ноль. Подагенты Codex имеют отдельные
`thread-id`; если «за сессию» включает их, агрегировать известные дочерние ID без
повторного учёта. Сохранить различие HOME-квоты/ledger у Codex, описанное выше:
новый источник не отменяет прежние проверенные правила автоматически.

## Компактное окно реализовано — 2026-10-12

Пользователь утвердил макет и отдельно убрал «Подробнее». `RouterUsage` теперь один
для обоих агентов: ширина 340 px, процент **остатка**, доступно/всего в кредитах,
дата обновления лимита, расход сессии/дня и время получения данных. Только Claude
имеет Fable. Аккаунт, FREE_POOL, тариф и пустой заголовок «24 часа» убраны из окна.

`electron/router-credit-summary.mjs` объединяет `/limit/agents`, `/turns` и Fable
портала. Основная квота `/limit/agents` использует текущую отсечку ядра:
`CoreSeat.limit_micros` и `SUM(CoreCall.credits_micros)` в том же окне, что
`core_budget_views`/`key_budget_views` и `core/seats.py`. Это осознанная замена
исторического приоритета диагностического ledger в основном запросе. Legacy-ответы
рендерер по-прежнему читает по прежним правилам, а при недоступной новой квоте
может использовать абсолютную квоту своего продукта с портала. Суммы разных ключей
и квота другого продукта не подставляются. Сумма дня — по аккаунту с фильтром
провайдера, от местной полуночи; серверные тарифы в клиент не копируются.

`electron/session-router-usage.mjs` выбирает ключ именно работающего профиля вкладки;
для inherited Codex сохранён прежний поиск ключа. IPC `getRouterUsage({threadId})`
получает **отображаемый** native ID: `WindowSession.currentThreadId` может временно
указывать на подагента после `thread/started`. Claude-префикс `claude:` снимается.
Codex штатно читает обычные и архивные `thread/list` со `sourceKinds`/`cwd` без
`useStateDbOnly`, собирает транзитивных потомков по `parentThreadId` или native
`source.subAgent|subagent.thread_spawn|threadSpawn`; fork/ручные связи не считаются

Новая вкладка без ID имеет расход 0. Для существующего UUID пустой серверный журнал
не доказывает отсутствие расходов: показано «Нет данных». Подтверждённые вызовы
с нулевой ценой и подтверждённый пустой календарный день остаются 0. Частичная
ненулевая сумма подписана «Учтено частично»; причина доступна в подсказке.
API не сообщает число неизвестных цен по всей выборке: возвращаемый пример `limit=1`
и `sources` обнаруживают часть проблем, но не гарантируют полную историческую
сохранность/наличие тарифа у каждой не показанной строки. Это серверное ограничение.
