# Источник подключения в диалоге

2026-10-05, Nightly 0.10.0. В composer Codex и Claude добавлен выбор `connectionSource`: `inherited` («Настройки CLI»), `account` («Личный аккаунт»), `router` («Роутер»). Отсутствующее поле сохраняет прежнее наследование CLI; существующие вкладки автоматически не переводятся на другой источник. Поле сохраняется в settings/defaults каждого агента и в снимках рабочего места/Nightly. При восстановлении снимка источник берётся из подтверждённых host-настроек.

## Переключение

Меняется подключение текущей вкладки. Host синхронно резервирует переключение, отклоняет его при активной задаче, approvals, compact, терминале или незавершённых RPC; сначала разрешает новый профиль, затем ждёт реального завершения прежнего процесса. Неудачная предварительная проверка сохраняет прежний процесс. Переподключение возобновляет тот же thread/session ID; переписка и черновик сохраняются. Очередь приостанавливается, автопинг блокируется на время смены, старая оценка кэша очищается. Само переключение не отправляет model turn. Модель и effort сохраняются без скрытой замены; выбор модели остаётся у пользователя.

`electron/connection-source.mjs` собирает полный env отдельного Claude-процесса и очищает конфликтующие OAuth/API/provider переменные и model aliases. `--settings` перекрывает env из обычных CLI settings, сохраняя instructions/MCP/permissions и `CLAUDE_CONFIG_DIR`. Секретные overrides передаются через временный settings-файл, не через argv; файл удаляется после действительного выхода процесса. Постоянное хранение router credentials — отдельный `router-connections.json`, полностью зашифрованные записи через Electron safeStorage/Windows DPAPI. Снимки вкладок, renderer и диагностические события не получают ключи. Managed routing, если CLI показывает конфликт в effective env, приводит к ошибке вместо отправки через другой источник.

Для Codex `electron/codex-connections.mjs` выбирает штатные provider IDs `openai` / `router` через процессный `-c model_provider`, не переписывая provider tables. Router берётся из существующей native конфигурации, account сохраняет штатный OpenAI-auth. Перед использованием проверяется эффективная конфигурация: custom first-party routing/auth и несовпадение router URL/ключа отклоняются без запроса модели. Host явно передаёт выбранный modelProvider в thread/start/resume/fork. Глобальный config.toml не изменяется; «Продолжить в терминале» из Desk передаёт соответствующий профиль.

Отвергнутые подходы проверены настоящим Codex 0.156.1 на изолированной конфигурации. Фиксированная отдельная provider table глубоко объединялась со старой и сохраняла прежние base_url/bearer. Случайное имя устранило конфликт, но native metadata сохранила его, и обычный внешний `thread/resume` без временной таблицы отказал с `Model provider ... not found`. Поэтому случайные providers заменены штатными именами и проверкой effective config. История для проверки сохранена через `thread/inject_items` с синтетическими сообщениями; model turn не выполнялся, SQLite не редактировалась.

## Claude через портал

Публичный портал `https://coder-portal.encycam.com` уже выдаёт установщик Claude. По переданному пользователем файлу статически проверена схема: имя `claude-connect-<43 символа>.exe`, download URL `/api/connect/claude/<ticket>.exe`; оболочка скачивает `/api/connect/claude/<ticket>.ps1` и запускает PowerShell. С явного разрешения пользователя сценарий скачан и прочитан; он не выполнялся. Найден JSON here-string `$envJson`: `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, typed aliases/names opus/fable/sonnet/haiku с router-именами `cc/...`. Остальные команды установщика (обновление CLI, установка Claude app, реестр, перезапуски, перенос навыков) не относятся к подключению Desk.

Desk открывает изолированное sandbox-окно портала без Node/preload. Пользователь входит штатно и нажимает «Подключить Claude». `will-download` принимает только загрузку этого окна с точного HTTPS origin/path и соответствующим именем файла, отменяет скачивание exe и получает связанный сценарий в host. `claude-portal-import.mjs` только извлекает JSON here-string; PowerShell/код не выполняются, произвольные env не применяются. Redirect/cookies запрещены, таймаут 15 с, лимит ответа 128 КиБ. Ключ и ticket не появляются в ошибках. При неподдерживаемом/истёкшем ответе требуется новый установщик. Исходный билет после исследования перестал выдавать конфигурацию — повторное чтение готового preview не скачивает сценарий заново.

Альтернатива — обычный браузер и выбор уже скачанного установщика в системном диалоге. Оба пути дают одинаковый host-only preview на 10 минут; «Сохранить и использовать» сохраняет зашифрованную запись и переключает текущую вкладку. Закрытие окна/отмена инвалидируют поздние ответы. Чужая вкладка не может применить preview. Общие файлы авторизации и настройки терминального Claude не переписываются.

Нельзя подменять это выдуманным Claude device flow: проверенные `/api/device/claude`, `/api/claude/provider`, `/api/claude/defaults` вернули 404. `GET /api/config/claude` с разрешённым пользователем существующим router bearer вернул 401. Из этого не следует отсутствие иных серверных API; реализован подтверждённый контракт установщика. Старый Codex device flow и его native preview/backup/CAS остаются прежними.

## Проверки и пределы

Unit-тесты проверяют изоляцию credentials, шифрование, истечение preview, статический разбор сценария, ограничения сети, ожидание выхода CLI и сохранение UUID. UI `test:connection-sources` проверяет переключение в прежнем диалоге, другую независимую вкладку, сохранение черновиков/настроек, занятость, отмену и явный Apply. Эти проверки используют подставные данные и не отправляют запросы модели.

Полный цикл личный аккаунт → настоящий роутер → личный аккаунт с model turn пока не проверен. Нативное восстановление истории не гарантирует совместимость thinking signatures между источниками. Новое SSO в окне портала выполняет пользователь; проверка окна/перехвата загрузки на fixtures не заменяет успешный реальный вход.

Несовместимая модель помечается `unavailable`; отправка/очередь/compact блокируются до явного выбора доступной модели. Claude initialize может сам вставлять текущую модель в каталог и вытеснять соответствующий alias, поэтому наличие строки не доказывает поддержку. Для router используются подтверждённые aliases из портала; недостающие точные IDs добавляются без выдуманных возможностей effort. `cc/...` нельзя отправлять личному Anthropic. UI сохраняет прежнее имя и показывает «Выбрать модель», не подменяя модель скрыто. Это проверено на CLI 2.1.278 и synthetic UI.

При замене сохранённого ключа другие открытые router-вкладки сохраняют свой уже работающий профиль до переподключения. Их статистика запрашивается именно с ключом активного процесса, а не с новым ключом из общего хранилища. Личный login через мастер явно использует account независимо от сохранённого default source.
