# Правила ведения памяти для пользователей Codex Desk

Запрос 2026-09-21: распространить принципы из `memory-compact (1).md` на новые сессии во всех проектах пользователей приложения. Прежний `C:/Users/LEGION-PC/.codex/AGENTS.md` и его reference-файл были только личной настройкой разработчика; проектный `AGENTS.md` и файл в корне репозитория не входили в поставку. Этот личный блок сохраняется отдельно и не мигрируется автоматически.

## Пользовательское действие и область

В мастере после входа добавлен шаг «Память». В настройках доступен тот же раздел для существующих пользователей. Пользователь просматривает короткие правила и полную процедуру, затем отдельно включает или отключает блок Codex Desk для Codex и Claude. Открытие мастера, обновление приложения и просмотр текста ничего не записывают.

Правила действуют через штатные глобальные инструкции выбранного агента во всех проектах, включая терминал с тем же профилем. После применения нужно начать новый диалог; внешний терминальный агент следует перезапустить. Приложение переподключает свои простаивающие процессы выбранного агента. Текущие задачи, подтверждения и открытый терминал блокируют изменение. Release и Nightly с одним профилем CLI видят одни глобальные инструкции.

Включение задаёт правила сохранения решений, причин, точных идентификаторов, измеренных фактов и ссылок. Оно не запускает сжатие автоматически и не создаёт память там, где её нет. Полная процедура адаптирована для обоих агентов: пути Claude и поведение `MEMORY.md` не приписываются Codex, внутренние SQLite-базы не редактируются.

## Хранение и сохранность

Короткие правила и полная процедура поставляются в `electron/instructions/`, который входит в `app.asar` через обычную сборку. `MemoryRulesService` вычисляет пути из окружения текущего пользователя:

- Codex: абсолютный `CODEX_HOME` либо `~/.codex`; непустой `AGENTS.override.md` имеет приоритет, иначе используется `AGENTS.md`.
- Claude: абсолютный `CLAUDE_CONFIG_DIR` либо `~/.claude`; инструкции — `CLAUDE.md`.
- Копия полной процедуры: `codex-desk/memory-compact.md` внутри каталога соответствующего агента.

Путь компьютера разработчика не используется. Неподдерживаемые пути и повреждённые файлы дают видимую ошибку. Управляемый блок имеет границы; текст пользователя вне него сохраняется. Статус «включено» относится только к блоку Codex Desk: вручную написанные аналогичные правила могут существовать независимо от него.

Перед изменением существующего файла сохраняется точная резервная копия; путь показывается после применения. Отключение удаляет только управляемый блок, сохраняя пользовательский текст и файл полной процедуры. Изменённый вручную или повреждённый блок нельзя молча перезаписать. Предпросмотр привязан к содержимому и путям; внешнее изменение требует обновить просмотр. Записи разных экземпляров Codex Desk сериализуются файлом блокировки. Состояние проверяется непосредственно перед commit; атомарный rename не даёт межпроцессного CAS с внешним редактором, поэтому остаётся короткое окно внешней записи. После аварийного завершения остаточная блокировка даёт явную ошибку с путём; автоматически удалять её сервис не будет. Если управляемый AGENTS.md оказался скрыт новым override, требуется проверка, а не создание второго блока.

## Решения

Скрытые `baseInstructions`, `developerInstructions` и system prompt не добавляются. Выбран явный просмотр и штатные файлы агентов: это сохраняет их настройки и делает правило доступным терминальным сессиям. Авторизация, модель, effort, MCP, конфигурация и история не меняются. Штатные приоритеты локальных инструкций и ограничения объёма контекста продолжают действовать; настройку лимита Codex приложение не переписывает. Автоматическая массовая компакция в каждой сессии отвергнута: это отдельная операция с резервной копией и проверкой целостности.
