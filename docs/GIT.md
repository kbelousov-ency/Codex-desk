# Просмотр Git — 2026-09-19

Следующий этап пункта 4 [плана развития](ROADMAP.md), после [просмотра патчей из диалога](CHANGES.md). Пользователь поручил показать фактическое состояние Git: ветку, изменённые/новые/удалённые файлы и отдельно staged/unstaged.

## Интерфейс

В «Изменениях» переключатель «Из диалога / Git», по умолчанию прежние правки диалога. Git показывает ветку или detached HEAD, состояние до первого коммита и путь корня. Список ограничен выбранной папкой, даже если найденный репозиторий расположен выше неё. Разделы: «Конфликты», «Подготовлено к коммиту», «Не подготовлено», «Новые файлы». Файл с изменениями и в индексе, и после подготовки показан в обоих соответствующих разделах.

Нажатие открывает существующее большое сравнение до/после: HEAD → индекс для staged, индекс → рабочий файл для unstaged, отсутствующий файл → содержимое для untracked. Для удалённого файла кнопка открытия отсутствует. Переименование показывает старое имя и открывает новое. Конфликт, подмодуль, binary/не-UTF8 и превышение размера получают явное пояснение, обычный diff не подделывается.

Поиск учитывает текущий и прежний путь. Обновление вручную кнопкой, при возврате во вкладку, изменении fileChange и переходах busy/idle. Автоматического таймера опроса нет. Во время обновления или после ошибки прошлый список помечен устаревшим, сравнение заблокировано до успешного чтения. Задержавшиеся ответы другой cwd/вкладки/источника не открывают старое сравнение. Открытое сравнение остаётся снимком на момент чтения.

Папка без Git, bare-репозиторий и отсутствующий git.exe имеют отдельные сообщения. Shell команды, staging, commit, reset/restore, fetch/push UI не выполняет; выборочный откат остаётся следующим этапом.

## Host

Дополнение: отдельные явные действия [отката файла](ROLLBACK.md) меняют рабочий файл только после предпросмотра/подтверждения и сохраняют backup. Описанные здесь getGitStatus/getGitDiff остаются только чтением. Прежнее утверждение об отсутствии restore относится к первоначальному этапу viewer.

`electron/git-reader.mjs` запускает Git без shell, со скрытым служебным окном и ограничением времени. IPC `getGitStatus()` и `getGitDiff({path,area})` принадлежат конкретной сессии через preload; cwd и generation берутся у host. Перед возвратом проверяется, что сессия и папка ещё действуют.

Status: `--porcelain=v2 -z --branch`, разбор имён по NUL сохраняет пробелы/Unicode. Литеральные pathspecs, без shell interpolation; запрос diff дополнительно должен совпасть с текущей записью status и областью. Пути за пределами выбранной папки, `.git`, чужие/закрытые сессии не читаются через renderer.

Команды используют `--no-optional-locks`, `GIT_OPTIONAL_LOCKS=0`, отключённый fsmonitor/untrackedCache/autoRefreshIndex, `--no-ext-diff`, `--no-textconv`, запрет протоколов/lazy fetch. Унаследованные GIT_* не могут перенаправить чтение в другой repo/index. Внешние clean/process/smudge filters отключаются только для дочернего процесса; если они настроены, UI сообщает, что представление может отличаться от обычного Git с фильтрами (например LFS). Config, индекс и файлы не переписываются. Dirty-содержимое подмодулей не обходится; виден gitlink, подмодуль можно открыть отдельным проектом.

Пределы: 15 с на команду, 2 МиБ stdout для status/diff, 5000 записей status, 512 КиБ untracked. Обрезанная последняя NUL-запись отбрасывается; обрезанный diff заканчивается на границе строки и явно помечен. Символические ссылки/junction не раскрываются. Статус и diff читаются отдельными командами, поэтому конкурирующая работа может изменить файл между чтениями; при отсутствии прежней записи требуется обновить список.
