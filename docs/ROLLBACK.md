# Откат файла и отмена отката — 2026-09-19

Пользователь согласовал следующий этап после [Git viewer](GIT.md): откат одного файла с предпросмотром, резервной копией и возможностью отменить сам откат.

## Семантика

В разделе «Не подготовлено» кнопка «Откатить <path>» доступна для обычных tracked файлов M/D. Рабочий файл возвращается к **индексу**, не к HEAD: уже подготовленные к коммиту правки сохраняются. Предпросмотр явно предупреждает, что отменяются **все** неподготовленные изменения файла, включая ручные правки пользователя. Приложение не определяет авторство каждой строки. Применение происходит только по «Отменить изменения файла».

«Недавние откаты» читает сохранённые записи после перезапуска. «Отменить откат» сначала показывает обратное сравнение, «Вернуть изменения» восстанавливает точные первоначальные байты либо отсутствие файла (если до отката он был удалён). Если после отката файл/индекс/ветка изменились, автоматическое undo отклоняется; резервная копия остаётся для ручного восстановления.

Подготовленные, untracked, renamed/copied/type-changed, конфликты, подмодули, символьные/жёсткие ссылки и файлы с внешними Git filters/working-tree-encoding не откатываются этой кнопкой.

## Откат отдельных фрагментов — 2026-09-19

Предпросмотр строит построчный diff «рабочий файл → индекс» (точный LCS после отсечения общего префикса/суффикса; при более чем 16 млн ячеек таблицы — один общий фрагмент) и группирует изменения в hunks с контекстом 3 строки, как `git diff`. Если фрагментов больше одного, файл текстовый, присутствует на диске и операция — restore, ответ содержит `hunks` (номер, заголовок `@@`, диапазон строк, счётчики −/+ и первая изменённая строка), а в окне появляется список с отметками. По умолчанию выбраны все; снятая отметка означает «оставить этот фрагмент как есть». Кнопка меняет подпись на «Отменить выбранные фрагменты (k из n)» и передаёт `hunks: number[]` в `applyGitRollback`.

Частичное содержимое собирается из текущих строк файла: для выбранных фрагментов подставляется сторона индекса, остальные строки остаются байт в байт (UTF-8 декодируется с `ignoreBOM`, переводы строк и отсутствие финального перевода сохраняются). Выбор всех фрагментов эквивалентен точным байтам индекса. Резервная копия `.before` по-прежнему хранит весь файл, поэтому «Отменить откат» возвращает исходное состояние целиком; журнал записывает выбранные индексы. Пустой, повторяющийся или выходящий за диапазон выбор отклоняется до использования preview-token; host дополнительно ограничивает массив 10 000 элементов. Для удалённых файлов, бинарных/крупных сравнений и undo фрагменты не предлагаются. Не выполняются git reset/restore/checkout, изменение index/config/history или отправка скрытого запроса Codex.

## Проверки перед записью и хранение

`electron/git-rollback.mjs`: preview-token живёт 5 минут, хранится в памяти и используется один раз. Host дополнительно привязывает его к сессии, generation, cwd и виду операции. Source snapshot хранит хэш/identity/режим/родительский каталог, index snapshot — blob/mode/атрибуты/HEAD/преобразованные байты. Перед применением и непосредственно перед атомарным rename всё проверяется повторно. Встроенные CRLF/ident-преобразования Git учитываются; внешние helpers не выполняются. Файл до 8 МиБ, текстовое сравнение до 2 МиБ; binary/другая кодировка получают явное предупреждение о замене целиком с backup.

В `userData/git-rollback` сохраняются `.before`, `.after` и JSON-журнал с серверным UUID. Обе версии записываются и fsync выполняется до замены рабочего файла. Рабочая запись готовится в уникальном соседнем `.codex-restore-*.tmp`, затем переименовывается; undo удаления использует unlink только после проверки текущего результата отката. Ошибки не запускают слепое обратное восстановление поверх возможных новых правок. Backup и журнал сохраняются также при сбое финальной записи журнала; они не попадают в диагностику/репозиторий и автоматически не очищаются.

Host запрещает откат при busy, pending approvals, compact, MCP-refresh или открытом терминале любой сессии с совпадающей/вложенной cwd. На время apply/undo резервируется папка, блокируются новые изменяющие IPC и смена/закрытие сессий. Nightly-update ждёт операции, обычный close/before-quit дожидается текущих jobs. Чтение Git остаётся доступным. Режим legacy read-only запрещает откат.

Это оптимистическая защита от конкуренции: внешний редактор или другой экземпляр CLI не участвует в блокировке оболочки. Если он изменит файл между последней проверкой и rename, атомарной межпроцессной compare-and-swap гарантии нет; прежние байты backup остаются. Не обещать абсолютную защиту от любой гонки Windows.
