# Рабочие папки и вкладки — 2026-09-17

Пользователь уточнил интерфейс: «Новая сессия» добавляет ещё одну папку под текущей слева; у каждой папки своя история; активные диалоги переключаются вкладками сверху, как в браузере. Предыдущая реализация с отдельными окнами признана неудобной, её устройство сохранено в [SESSIONS.md](SESSIONS.md).

## Текущая реализация

- `src/Workspace.tsx` управляет списком папок, открытыми вкладками, выбранной вкладкой, индикаторами работы/подтверждений и закрытием. `App` каждой вкладки остаётся смонтированным внутри скрываемого `.session-view`: сообщения, черновик, изображения, состояния панелей и позиция чтения не переносятся в другой диалог.
- `src/App.tsx` получает `bridge`, `sessionId`, `active`, `initialThread` и `workspace`. `useCodex(bridge)` использует только свой bridge. Markdown получает scoped openPath через `BridgeContext`.
- `Новая сессия` выбирает папку, добавляет её в список и открывает вкладку. Повторный выбор уже открытой папки переключает на её вкладку. `Новый диалог` и `+` открывают новую вкладку текущей папки, даже когда другой диалог работает.
- По уточнению пользователя полоса вкладок начинается после левой панели: отступ 240px, ≥1700px — 260px, ≤1200px — 205px, ≤1000px — 190px. При скрытой панели активной вкладки, ширине ≤700px или отсутствии вкладок — 10px. CSS `:has()` учитывает только видимую `.session-view`. `session-tabs` использует `flex:0 1 auto`: кнопка `+` идёт сразу за вкладками, при переполнении остаётся доступна справа от прокручиваемого списка.
- Открытие истории ищет уже открытую вкладку по cwd + threadId, включая ожидающий resume. После очистки/переподключения прежний initialThread больше не считается открытым диалогом. Заголовок вкладки берётся из текущей истории или первого сообщения пользователя.
- Закрытие активной или ожидающей подтверждения вкладки требует подтверждения «Остановить и закрыть». Закрытие останавливает только её процесс. Последнюю вкладку можно закрыть: остаются сохранённые папки и кнопка создания. Переключение вкладки не останавливает процессы.

## Host и хранение

С 2026-09-19 [постоянный снимок рабочего места](WORKSPACE_STATE.md) восстанавливает вкладки, черновики/изображения, очередь на паузе и место чтения после обычного закрытия или сбоя. Ниже сохранены первоначальные ограничения и причины прежнего устройства; фраза об отсутствии восстановления относится к версии до этой доработки.

С 2026-09-18 проект можно убрать через ⋮ у названия / ПКМ / Shift+F10 → «Закрыть проект». Без открытых вкладок закрытие сразу; при любых вкладках этой cwd (включая readonly архив) запрашивается подтверждение с предупреждением об остановке и черновиках. Открытый терминал надо сначала закрыть. Удаляется только запись в workspace и закрываются локальные сессии, файлы и история Codex остаются. Повторное добавление возвращает прежнюю историю. Пустой список проектов — нормальное сохранённое состояние.

`WorkspaceStore.removeProject` сериализован с добавлением; `initializeProjects` переносит legacy settings.cwd только при отсутствующем массиве projects, поэтому boot не воскрешает удалённую папку. Main выбирает начальную cwd только из сохранённого списка; если список пуст, сессии не создаются. `host:closeProject(cwd,{force})` требует явного force при сессиях, проверяет терминал/текущие операции, резервирует закрываемую папку и останавливает только её процессы. Renderer отбрасывает поздние отчёты/списки удалённых вкладок.

Артефакты: `artifacts/close-project-confirm.png`, `artifacts/close-project-host-HEcPXf`.

`electron/main.mjs` хранит Map окон; каждое окно хранит Map sessionId → `WindowSession` и defaultSessionId. Имя класса `WindowSession` сохранено для совместимости модулей/тестов, но экземпляр теперь принадлежит вкладке. У каждой вкладки свой CodexClient, cwd, настройки, bootQueue и pending approvals. `thread/list`, как thread/start/resume и turn/start, привязан к cwd сессии.

Preload: `getWorkspace() → {projects:string[],sessions:[{id,cwd}]}`, `createSession({cwd?,fromSessionId?,settings?}) → {id,cwd}|null`, `closeSession(id)`, `forSession(id) → CodexBridge`. Без cwd createSession вызывает native picker; null означает отмену. Из UI settings принимаются только model/effort/access; executable наследуется из снимка источника. Legacy root bridge обслуживает default-сессию для совместимости проверок.

События содержат `sessionId`, `defaultSession`, `type`, `data`; scoped listeners фильтруют по sessionId. Host проверяет sender, mainFrame и принадлежность сессии окну. Одинаковые protocol IDs разных процессов не смешиваются. При закрытии/падении renderer завершаются процессы всех вкладок этого окна. Повторный запуск приложения фокусирует текущее окно, `newWindow` удалён.

`workspace.json` в Electron userData хранит упорядоченный список папок отдельно от прежнего `settings.json`. Сохранение атомарное через уникальный временный файл и rename; shutdown дожидается очередей обоих файлов. История и авторизация остаются у Codex, SQLite не изменяется. Полный доступ по-прежнему не включается автоматически в новой вкладке, `inherited` сохраняет прежнюю семантику. Список открытых диалогов между перезапусками не восстанавливается автоматически; они доступны в истории папок.
