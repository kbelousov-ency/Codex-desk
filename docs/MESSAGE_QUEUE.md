# Уточнения и очередь сообщений

Поручено 2026-09-19, пункт 2 [списка идей](ROADMAP.md). Уточнение текущего хода и следующий запрос — отдельные видимые действия. После восстановления рабочего места очередь ставится на паузу; неподтверждённая отправка не повторяется автоматически.

## Интерфейс

При выполнении задачи composer показывает «Уточнить текущую задачу» и «Отправить после завершения». Уточнение передаёт только видимый текст/изображения пользователя через `turn/steer` с точными `threadId`, `expectedTurnId`, `clientUserMessageId`. Изображения сохраняются штатным `saveImages`. После их подготовки активный ход проверяется снова; если он уже завершился, текст остаётся в composer, автоматического перехода к `turn/start` нет. Серверный echo заменяет оптимистичное сообщение, сохраняя preview. Ошибка steer сохраняет черновик и сообщает о неподтверждённой отправке.

Очередь видна как компактная полоска, пристыкованная к верхнему краю поля ввода (2026-09-19 по замечанию пользователя вместо отдельного крупного блока): заголовок «Очередь · N» со статусом и иконкой паузы/продолжения, затем по одной строке на сообщение — номер, текст в одну строку с обрезкой (полный текст в подсказке), счётчик вложений со скрепкой и иконки «Изменить»/«Удалить из очереди». Названия действий сохранены в aria-label, поэтому прежние сценарии работают без изменений. Причина паузы показывается только в состоянии паузы. Список выше трёх строк прокручивается. Редактирование отдельной записи подтверждается «Сохранить сообщение», «Отменить правку» возвращает сохранённый вариант. Максимум 50 сообщений. Добавление переносит текущий composer в очередь; отправка очереди не забирает новый текст или изображения из composer.

Следующий запрос отправляется после подтверждённого успешного `turn/completed`; обычный текст идёт через существующий `send`/`turn/start` с текущими настройками вкладки. Обычные slash-команды отклоняются в уточнении/очереди сообщением «Команды выполняются отдельно…»; при редактировании прежнего сообщения slash остаётся буквальным текстом. Существующие slash-команды обычной отправки сохраняются. Прежняя заметка ошибочно обещала literal slash для всех очередей; расхождение с `steerCurrent`/`enqueueMessage` проверено 2026-09-19, семантика кода не менялась.

По замечанию пользователя к снимку экрана переработан composer: «Уточнить» и «В очередь» находятся в одной нижней toolbar с выбором модели, рядом со stop; прежний дополнительный ряд убран. При пустом/пробельном busy черновике виден только stop, текст или изображение показывает действия. «Уточнить» выделено как основное действие, queue — вторичное, stop отделён. При узкой центральной колонке queue становится иконкой с полными aria-label/title. Enter и существующие блокировки не изменены. Проверка `scripts/ui-composer-layout.mjs`: ширины 1440/1100/1001/940/650, пустой/текст/картинка/approval, idle очередь, одна строка без перекрытия. Скриншоты: `artifacts/composer-1440-draft.png`, `artifacts/composer-1001-draft.png`, `artifacts/composer-940-empty.png`.

## Остановка и восстановление

Последующее уточнение пользователя: кнопки воспринимались как пропавшие при пустом поле. Условие непустого текста удалено из видимости: во время работы «Уточнить» и «В очередь» всегда на месте, пустой/пробельный текст без картинки делает их disabled. При idle и непустой очереди её кнопка также остаётся видимой. Предыдущее решение скрывать их при пустом composer было инициативой ИИ при уплотнении, пользователь его отверг. Одна строка, компактность, Enter и guards сохранены; `ui-composer-layout` обновлён под видимость+disabled на всех пяти ширинах.

- Подтверждения, загрузка истории, передача терминалу, редактирование сообщения/очереди и операции workspace блокируют отправку. Stop/error/disconnect ставят очередь на паузу. Для продолжения пользователь нажимает кнопку очереди; обработка события паузы защищена синхронным revision ref.
- Очередь принадлежит вкладке и сохранённым `threadId`/`cwd`. После смены диалога она не отправляется в другую беседу. Возобновление требует вернуться к её диалогу либо удалить прежние записи. При создании новой беседы пустая очередь начинает новую привязку.
- Автопинг не запускается при непустой очереди, включая paused. Неподтверждённые отправки не повторяются по таймеру.
- До RPC запись получает `state:'uncertain'`, затем `flushSessionState` дожидается постоянного снимка. Если сохранение не удалось, RPC не вызывается и запись возвращается в waiting на паузе. Подтверждённый RPC удаляет запись из очереди. При неопределённом исходе остаются текст/картинки и отметка «Отправка не подтверждена»; после проверки истории можно удалить запись либо выбрать «Проверено: повторить» и затем «Продолжить очередь».
- После перезапуска очередь всегда paused, включая ранее исполнявшуюся. История не подменяется и «Продолжай» автоматически не отправляется. Абсолютная exactly-once гарантия при crash/потере ACK не заявляется; ручная сверка предотвращает скрытый повтор.

## Код и проверки

`src/useCodex.ts` — steer, lifecycle и синхронные guards; `src/useMessageQueue.ts` — последовательность/пауза/неподтверждённое состояние; `src/MessageQueue.tsx` и `src/message-queue.css` — отображение; `src/App.tsx` — composer и снимок. Сохранение описано в [WORKSPACE_STATE.md](WORKSPACE_STATE.md).

`scripts/ui-message-queue.mjs` проверяет production renderer с mock bridge: exact steer/text/images/echo, окончание хода во время подготовки картинки, отказ steer, FIFO/edit/delete, черновик, durable uncertain snapshot, ошибка сохранения до RPC, отсутствие retry, stop/error/disconnect/approval, pause после восстановления, изоляцию вкладок и узкий интерфейс. Это протокольные fixture-события, не реальные model turns. Регрессии включают редактирование сообщений, вкладки, resume, cache/autoping, команды/compact и прокрутку.

`scripts/ui-message-queue-host.mjs` дополнительно проверяет настоящий Electron/preload/WindowSession и частный JSONL fixture. При получении очередного turn/start сервер сам читает `workspace-state.json` и проверяет уже сохранённый uncertain; также проверяются steer/PNG/echo, прежние thread/model/effort/access, последовательность без нового процесса и независимый composer.
