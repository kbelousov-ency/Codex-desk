Опубликованная `0.2.0` добавила уведомления о новых выпусках и обновление через GitHub Releases; её байты и тег сохраняются. Опубликованный ранее [v0.1.0](https://github.com/kbelousov-ency/Codex-desk/releases/tag/v0.1.0) остаётся первым публичным выпуском; множество прежних локальных сборок `0.1.0` различаются build ID, как зафиксировано в [RELEASES.md](RELEASES.md).

| Изменение | Правило | Пример |
| --- | --- | --- |
| Исправление ошибки, совместимая доработка без новой функции | Увеличить PATCH | `0.2.0` → `0.2.1` |
| Новая совместимая возможность | Увеличить MINOR, обнулить PATCH | `0.2.1` → `0.3.0` |
| Несовместимое изменение пользовательского поведения, формата или требований | Увеличить MAJOR, обнулить MINOR/PATCH | `1.4.2` → `2.0.0` |

До `1.0.0` продукт находится в развитии: существенные несовместимые изменения допустимы в MINOR и отдельно описываются в заметках выпуска вместе с миграцией. Переход на `1.0.0` — явное решение о готовности стабильного продукта, а не автоматическое следствие количества функций.

Версия выбирается один раз для следующего публичного выпуска по наиболее значимому изменению. Не повышать её при каждой правке или сборке Nightly. Nightly и будущий Release имеют одинаковый номер; точную сборку задаёт SHA-256 build ID. Перенос проверенного Nightly в Release сохраняет эти байты и номер. Публичные номера и git tags не переиспользуются: после публикации любой исправленный установщик получает следующий номер.

## Команды

```powershell
npm.cmd run version:patch
npm.cmd run version:minor
npm.cmd run version:major
```

Каждая команда изменяет `package.json` и `package-lock.json` штатным `npm version --no-git-tag-version --ignore-scripts`. Она не создаёт commit/tag, не запускает сборку, не публикует пакет и не отправляет изменения в Git. После команды обновить [CHANGELOG.md](../CHANGELOG.md), затем выполнять обычные проверки и сборку Nightly. Только стабильная форма `X.Y.Z` без ведущих нулей и суффиксов разрешена при упаковке; канал хранится отдельно.

## Подготовка GitHub Release

1. Указать следующий номер в исходниках и описать пользовательские изменения в разделе `## [X.Y.Z]` файла `CHANGELOG.md`.
2. Выполнить проверки и `npm.cmd run package`, проверить готовый Nightly. Работающий Nightly закрывается только штатной кнопкой «Закрыть» в чате или вручную; автоматического завершения нет.
3. После явного подтверждения пользователя выполнить `npm.cmd run release:promote`: Release получает проверенную сборку без перекомпиляции.
4. Выполнить `npm.cmd run release:installer`, проверить Setup, затем `npm.cmd run release:prepare`.
5. Перед отдельной, явно разрешённой публикацией проверить `artifacts/github-release`. Тег должен быть `vX.Y.Z`, обычный GitHub Release в `kbelousov-ency/Codex-desk`, без `draft` и `prerelease`. В описание выпуска перенести `RELEASE_NOTES.md`; прикрепить Setup, `SHA256SUMS.txt`, `release-info.json` и `README.txt`.

`release:prepare` не обращается в сеть. Он проверяет manifest утверждённого stable и соответствие installer metadata, размера и SHA-256, затем готовит постоянный каталог `artifacts/github-release`. Старые локальные имена с пробелами/точками принимаются, но копия для публикации всегда называется `Codex-Desk-Setup-X.Y.Z.exe`. Nightly Setup имеет отдельное имя `Codex-Desk-Nightly-Setup-X.Y.Z.exe` и не предлагается пользователям Release.

`release-info.json` содержит `format: 1`, `channel: "stable"`, `version`, `buildId`, `builtAt`, `installer`, `sha256`, `size`. Версия берётся из утверждённого app.asar; более новая версия в рабочем `package.json` не подменяет её. `latest.yml` и отдельный сервер не нужны: [проверка обновлений](UPDATES.md) использует GitHub Releases API и предлагает открыть официальный Setup в браузере. Установщик выполняет обновление приложения, сохраняя пользовательские настройки и историю.

Версия `0.1.0` ещё не содержит проверки обновлений. Её пользователям потребуется один раз вручную скачать выпуск с этой функцией; дальнейшие новые выпуски обнаруживаются приложением.
