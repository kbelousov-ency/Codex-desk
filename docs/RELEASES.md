# Release и Nightly

С 2026-09-18 вместо отдельной папки под каждый запрос используются два постоянных канала:

- `release/stable/Codex Desk.exe` — проверенная версия. Обычный `Codex Desk.lnk` / `Start Codex Desk.vbs` всегда запускает её.
- `release/nightly/Codex Desk.exe` — новые изменения. Отдельный `Codex Desk Nightly.lnk` / `Start Codex Desk Nightly.vbs`.
- `release/stable-previous/` — максимум одна предыдущая стабильная сборка для отката, появляется после следующего продвижения.

`active-build.txt` больше не выбирает запускаемую версию. Сборка Nightly не переключает обычный ярлык. Прежние тематические пути в заметках описывают историю проверок; удаление старых exe не делает эти решения устаревшими.

Исходники ведутся в Git: `https://github.com/kbelousov-ency/Codex-desk`, ветка `main`, remote `origin`. Репозиторий инициализирован по запросу пользователя после первого подтверждённого продвижения Nightly в Release. Прежние заметки об отсутствии `.git` описывают состояние до 2026-09-18. Сборки, зависимости, тестовые профили/артефакты, журналы и персональные ярлыки в Git не включаются; канал Release обновляется отдельно от отправки исходников.

## Обязательный рабочий процесс

1. Изменить исходники и выполнить проверки.
2. `npm.cmd run package` (или `package:nightly`) обновляет **только Nightly**. Произвольный `--config.directories.output=...` отклоняется.
3. Проверить Nightly, включая packaged smoke с `CODEX_DESK_PACKAGED` равным абсолютному пути Nightly exe. Проверка UI/протокола без модели отделена от реальных model turns.
4. Пользователь проверяет изменения. **Продвигать в Release только после явного подтверждения пользователя.** Разрешение на обычную задачу или сборку Nightly не означает разрешение продвигать её в Release.
5. `npm.cmd run release:promote` проверяет целостность и копирует проверенные байты Nightly в Release; renderer/host не пересобираются. Меняется только внешний marker канала. Старая Release становится единственной `stable-previous`.
6. При необходимости `npm.cmd run release:rollback` возвращает предыдущую Release; требует закрытого стабильного приложения.

При первоначальном переходе создание первого Release разрешено самим запросом пользователя внедрить два канала. Последующие изменения идут только в Nightly до отдельного подтверждения.

Для замены Release нужно закрыть его приложение. Первоначально это требовалось и для Nightly; по следующему запросу добавлено [автоматическое применение Nightly](#автоматическое-применение-nightly). Временная упаковка находится под `artifacts/channel-build` и очищается после успешной публикации. Блокировка и транзакционное переименование защищают от одновременных операций и неполной замены; неподтверждённые изменения не должны попадать в stable.

**Текущее правило с 2026-09-18:** пользователь отменил автоматическое закрытие. При готовой сборке в чате над composer показывается notice как сообщение об остановке: «Закрыть» / «Отмена». «Закрыть» разрешает прежний цикл ожидания задач, checkpoint, закрытия, применения и запуска; «Отмена» откладывает до ручного выхода, без автоматического запуска. Первая поставка этого изменения ждёт ручного закрытия старой версии, поскольку та ещё не умеет показать вопрос. История предыдущего разрешения и механизма ниже сохранена; автоматическая готовность больше не является согласием закрыть окно.

`electron/nightly-update.mjs` регистрирует `updateProtocol:2`. Первый pipe `prepare` только создаёт `awaiting`, даже если приложение простаивает. Локальный workspace IPC `decideUpdate('close'|'later')` вызывает `updater.decide`; решений в named pipe нет. close → waiting → idle checkpoint → preparing/ready; later → manual и инвалидирует незавершённый checkpoint. `getUpdateStatus` восстанавливает пропущенное UI-уведомление; `UpdateNoticeContext` показывает одно текущее предложение в активной вкладке, архиве или пустом workspace. Скрытие manual notice не меняет решение. Активное редактирование сообщения откладывает checkpoint вместе с диалогами и чтением изображений.

Helper принимает awaiting/waiting/manual и перезапускает только после полученного ready. Старой регистрации без updateProtocol:2 он **не отправляет prepare**, потому что старый host считал его разрешением закрыться; журнал `host_manual_legacy`, ожидание ручного выхода. При manual/plain exit checkpoint не создаётся, применяются обычные правила ручного закрытия (несохранённые черновики не восстанавливаются); сохранение вкладок/черновиков гарантирует кнопка «Закрыть». Это необходимо, когда сам Codex выполняет сборку внутри обновляемого приложения: нельзя синхронно ждать завершения собственного model turn.

Helper ждёт завершения задач во всех вкладках, запросов разрешений, compact, операций MCP/истории и закрытия переданного терминала. Renderer дополнительно откладывает снимок до окончания чтения картинок/отправки и незавершённых диалогов настроек/переименования. Пока работа продолжается, показывается уведомление. После готовности окно временно блокируется, сохраняет вкладки/порядок/активную вкладку, выбранные диалоги, черновики, вложения и настройки; Nightly завершается штатно. Helper ждёт завершения main и остальных Electron-процессов, проверяет кандидат повторно, транзакционно заменяет nightly и запускает новый exe с прежними cwd/userData. Работающий пользовательский процесс принудительно не завершается. Release не участвует.

Восстановление читает обычную историю через App Server и не отправляет «Продолжай» либо другой скрытый prompt. Ранее выбранные модель/effort/access сохраняются для этого специального перезапуска, включая уже подтверждённый full access. При обычном запуске прежнее правило подтверждения full остаётся. Автопинг после перезапуска выключен; оценка кэша восстанавливается обычным чтением истории. Новая пустая вкладка и несохранённое сообщение сохраняются без создания model turn.

В `electron/nightly-update.mjs` — локальный Windows named pipe со случайным токеном и owner-pipe для защиты регистрации, без HTTP listener. `release/.nightly-instance.json` принадлежит только запущенному Nightly; `mode:0600` на POSIX, Windows наследует разрешения папки, системные ACL не меняются. Сообщения status/prepare/cancel ограничены и не принимают пути или команды. Срок подготовленного снимка без подтверждения помощника — 30 секунд; исчезновение helper освобождает интерфейс. При запуске нескольких тестовых профилей один не перехватывает регистрацию другого.

`electron/main.mjs` резервирует операции на время подготовки, проверяет sender/окно/ID и принимает снимок только в ожидаемом запросе. `electron/update-checkpoint.mjs` атомарно сохраняет `nightly-update-workspace.json` в данных Nightly; сведения о cwd/executable берёт из host сессий. Снимок содержит несохранённые пользовательские черновики/картинки (они могут содержать личную информацию), но не экспортируется в диагностику. Загруженная переписка и config туда не копируются.
