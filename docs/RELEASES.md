## Две копии: GitHub и Gerrit — решение 2026-09-22

По указанию пользователя команда **«Заливай»** означает отправку готовых изменений в **оба репозитория**: GitHub `https://github.com/kbelousov-ency/Codex-desk` (копия `E:\My projects\CodexDesk`, ветка `main`) и Gerrit `https://gerrit1.hq.encycam.com/a/CodexDesk` (копия `E:\CodexDesk`, ветка `master`). Сохранять обе истории и несвязанные рабочие изменения; перед отправкой согласовывать содержимое копий, не применять force-push для их выравнивания. При выпуске исходники и публикуемые теги дублируются в оба репозитория.

Приложение пока продолжает проверять **GitHub Releases**; Setup и метаданные обновлений остаются там. Пользователь первоначально выбрал хранить установщики в том же Gerrit `CodexDesk`, затем отложил переход до решения о способе хранения. Перенастройка updater на Gerrit остановлена до изменения кода. Одна смена Git remote источник обновлений не меняет. Переход полностью на Gerrit выполняется по будущему указанию пользователя; сейчас поддерживаются две копии исходников. Правило явного подтверждения переноса Nightly в Release сохраняется; само определение команды не является поручением немедленно выполнить push или публикацию.

## Обязательный рабочий процесс

1. Изменить исходники и выполнить проверки.
2. `npm.cmd run package` (или `package:nightly`) обновляет **только Nightly**. Произвольный `--config.directories.output=...` отклоняется.
3. Проверить Nightly, включая packaged smoke с `CODEX_DESK_PACKAGED` равным абсолютному пути Nightly exe. Проверка UI/протокола без модели отделена от реальных model turns.
4. Пользователь проверяет изменения. **Продвигать в Release только после явного подтверждения пользователя.** Разрешение на обычную задачу или сборку Nightly не означает разрешение продвигать её в Release.
5. `npm.cmd run release:promote` проверяет целостность и копирует проверенные байты Nightly в Release; renderer/host не пересобираются. При существующей очереди используется её кандидат `artifacts/nightly-update/app` с проверкой `state.json` и совпадения build ID; повреждённая очередь блокирует перенос, без отката к старому Nightly. Без очереди используется `release/nightly`. Это позволяет после разрешения пользователя продвигать проверенный кандидат без закрытия рабочего Nightly; сама очередь остаётся прежней. Меняется только внешний marker канала. Старая Release становится единственной `stable-previous`.
6. При необходимости `npm.cmd run release:rollback` возвращает предыдущую Release; требует закрытого стабильного приложения.

При первоначальном переходе создание первого Release разрешено самим запросом пользователя внедрить два канала. Последующие изменения идут только в Nightly до отдельного подтверждения.

Для замены Release нужно закрыть его приложение. Первоначально это требовалось и для Nightly; по следующему запросу добавлено [автоматическое применение Nightly](#автоматическое-применение-nightly). Временная упаковка находится под `artifacts/channel-build` и очищается после успешной публикации. Блокировка и транзакционное переименование защищают от одновременных операций и неполной замены; неподтверждённые изменения не должны попадать в stable.
