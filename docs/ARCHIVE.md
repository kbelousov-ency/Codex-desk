# Диалоги и архив

Запрос: вертикальное ⋮ в конце строки активного диалога с переименованием, архивацией и удалением; нижняя кнопка архива, панель поверх проектов и «Новый проект», группировка по папкам, чтение без отправки, удаление/восстановление. Дополнительно доступ и терминал поменяны местами.

## Интерфейс

`ProjectSidebar.tsx` объединяет кнопку нового проекта, `ProjectTree` и нижний toggle архива. Включённый архив скрывает проекты и перекрывает их панелью; логотип остаётся. Группы строятся по фактическим cwd архивных thread, отсутствующие в workspace папки тоже видны. Перечисление имеет nextCursor; новые страницы объединяются по ID. Меню `ThreadMenu.tsx` размещается portal-ом в пределах viewport, закрывается при Escape/клике снаружи/смене вкладки. Основная `.folder-thread[data-thread-id]` сохранена, ⋮ — соседняя кнопка, не вложенная.

`Workspace.tsx` вызывает действия, хранит modal переименования/подтверждения удаления, обновляет заголовки и оба списка. Название trim, 1…200 символов, одна строка. Удаление сообщает о необратимости и удалении дочерних диалогов. Неуспех RPC сохраняет вкладки и строки; успех закрывает затронутые обычные и архивные вкладки. Ошибка закрытия соединения после успешного RPC показывается отдельно, не отменяет факт удаления/архивации. `historyRevision` не позволяет старому ответу загрузки истории вернуть удалённые строки. Операция блокирует повторные клики/отправку/автопинг до завершения; занятый/ожидающий approval/открытый в терминале диалог изменять нельзя.

`ArchiveView.tsx` — отдельная вкладка без `useCodex`, `createSession`, `thread/resume` и composer. Использует готовые `Conversation` / `WorkLog`, показывает только полученные сообщения. Чтение/пагинация не запускают модель, compact, пинг или TUI. Legacy получает turns с таймингом; paginated читает items desc, разворачивает страницу в хронологический порядок, более старые страницы добавляет спереди. Для paginated здесь пока не запрашиваются дополнительные turn timing pages: длительность без данных не выдумывается. При восстановлении архивная вкладка закрывается; обычная история позволяет продолжить тот же thread ID.

Порядок footer обычного чата: доступ → терминал → кэш → токены. Архивная вкладка показывает footer только для чтения и кнопку восстановления. Её нижний sidebar сообщает «Архив Codex», без настроек активной модели.

## Протокол и границы host

Сверены локальные `protocol/v2/ThreadArchiveParams.ts`, `ThreadDeleteParams.ts`, `ThreadUnarchiveParams.ts`, `ThreadListParams.ts`, `ThreadReadParams.ts` и официальная страница https://developers.openai.com/codex/app-server/ (артефакт `artifacts/app-server-archive-doc.html`).

- `thread/name/set` → `{threadId,name}`.
- `thread/archive`, `thread/delete`, `thread/unarchive` → `{threadId}`.
- `thread/list` с `archived:true`, `modelProviders:[]`, `sourceKinds:['appServer','cli','vscode']` без cwd-фильтра — весь интерактивный архив текущего Codex.
- `thread/read` без resume; legacy includeTurns:true, paginated `thread/items/list`.

`electron/thread-management.mjs` содержит выделенный `ThreadManagement` App Server и общий для окон `ThreadActionCoordinator`. Root preload предоставляет только фиксированные `listArchivedThreads`, `readArchivedThread`, `manageThread`, `openArchivedPath`, без расширения generic mutation allowlist. UUID, cwd и имя валидируются; реальный thread/read должен совпасть с ID и cwd. Для чтения и восстановления принадлежность архиву перепроверяется серверным списком: поле archived у Thread отсутствует, устаревшему UI нельзя доверять.

Служебная сессия не меняет пользовательские настройки/модель и не вызывает turn/start. При недоступной сохранённой папке запускается в существующей fallback cwd. Восстановить историю можно и после удаления рабочей папки; открыть её для работы получится, когда папка существует. Существующая cwd восстановленного диалога добавляется в workspace.

Coordinator резервирует действие до async-чтения; собственные session RPC/terminal проверяют lock, `pendingThreadIds`, `currentThreadId`, `activeThreadTurns`, `compactingThreads` закрывают промежутки ACK и гонки. Связи parentThreadId проверяют занятых дочерних агентов. `thread/archived`/`thread/deleted` дают affected IDs; stale writers блокируются после успеха до восстановления. Другие независимые вкладки не останавливаются. При закрытии/crash renderer manager dispose инвалидирует очередь.

Ссылки архива открываются отдельным host handler: archived membership + cwd читаются из Codex, затем используются прежние `openLink`/`showLocalPathMenu` с проверкой границ проекта. Вложения восстанавливаются `electron/attachments.mjs`: только собственный attachments каталог userData, realpath, поддерживаемый image type, предел 20 МБ. Чужой localImage путь не читается.

Не меняются SQLite, rollout JSONL и глобальная конфигурация напрямую. При неподдерживаемом `thread/delete` UI показывает ошибку; скрытого файлового удаления или локального псевдоархива нет. По документации archive/delete затрагивают spawned descendants; пользовательский диалог подтверждения удаления это учитывает.

## Архив диалогов Claude Code — 2026-09-22

Пользователь сообщил, что диалоги Claude нельзя положить в архив. Прежнее решение (пункт «В архив» скрыт, `manageThread` отклоняет archive/restore) было принято потому, что у нативной истории Claude Code нет состояния «архивирован»: официальный SDK 0.3.278 даёт `listSessions`/`renameSession`/`deleteSession`, но не архив. По явному выбору пользователя добавлен **локальный архив оболочки**; отвергнутый ранее подход «не делать псевдоархив» заменён, причина сохранена здесь.

`electron/claude-archive.mjs` (`ClaudeArchiveStore`) хранит `claude-archive.json` в userData: `{version:1, threads:[{id,cwd,name,preview,updatedAt,createdAt,archivedAt}]}`. Запись атомарная (`wx` + rename, режим 0600), очередь операций последовательная, идентификатор обязан начинаться с `claude:` — голый UUID мог бы принадлежать Codex. Повреждённый или чужой по версии файл не перезаписывается и не считается пустым: операция сообщает об ошибке с именем файла. Предел — 5000 записей и 8 МиБ.

Транскрипты, SQLite и конфигурация Claude Code **не изменяются**. Следствие, о котором нужно помнить: в терминальном `claude --resume` архивный диалог остаётся обычным, архив виден только в Кузьмиче.

`ClaudeThreadManagement` принимает `archive`/`restore` теми же путями, что rename/delete: `assertIdle` (занятая вкладка, ожидающее подтверждение, открытый терминал и compact блокируют), `coordinator.reserve`, затем `blocked='archive'` для последующих писателей. Архивация читает нативную историю, чтобы доказать принадлежность диалога папке, и останавливает простаивающие процессы CLI этой вкладки. Восстановление **не** читает транскрипт: запись обязана удаляться и тогда, когда папка перемещена или диалог удалён в самом CLI, иначе панель архива зависла бы. Восстановленная папка добавляется в рабочую область тем же `onRestore`, что у Codex. Удаление диалога попутно снимает его запись из архива.

Границы host в `electron/main.mjs`: `host:listArchivedThreads` добавляет список Claude один раз, вместе с первой страницей архива Codex (это конечный локальный список, а не серверная пагинация), и сортирует объединение по времени. `host:readArchivedThread` и `host:openArchivedPath` маршрутизируются по префиксу `claude:`; чтение идёт через `ClaudeHistory.read` без запуска CLI, папка берётся из записи архива, следующей страницы нет. `host:listProjectThreads` скрывает архивные ID из обычной истории папки, поиск по сообщениям помечает их `archived:true`, ссылка закладки возвращает фактическое состояние архива. `ArchiveView` подписывает агента по диалогу («Архив Claude Code»), закладка и экспорт получают правильного провайдера. Возможность `archive` в «Действующих настройках» Claude теперь доступна.

Поиск по названиям в боковой панели по-прежнему обращается только к Codex (`thread/list` с `searchTerm`), поэтому архивные диалоги Claude в нём не находятся; подпись поля это указывает.

Проверки: `tests/claude-archive.test.mjs` (пустой и повреждённый файл, чужая версия схемы, сохранение и повторное чтение, область папки с учётом регистра Windows, повторная архивация, порядок, отказ голым UUID и относительной папке, отсутствие временных файлов), новые случаи в `tests/claude-threads.test.mjs` (остановка процессов, запись, блокировка писателей, занятые вкладки, отсутствие хранилища, восстановление без чтения транскрипта, удаление архивного диалога). `test:archive` дополнен диалогом Claude: меню с «В архив», уход из истории папки, панель архива, «Архив Claude Code», только чтение и восстановление. 547 Node-тестов, `build`, `test:archive`, `test:archive-host`, `test:providers`, `test:project-tree` прошли.

Два исправления в самих сценариях, не связанных с функцией: `scripts/ui-archive.mjs` открывает меню ⋮ с клавиатуры, потому что всплывающая подсказка предыдущей строки перекрывает кнопку и глотает клик (воспроизводится и без этих изменений); `scripts/ui-archive-host.mjs` учитывает кнопку «В закладки» в тексте сообщения.

## Массовая архивация — 2026-10-09

Запрос: архивировать несколько диалогов сразу. Добавлен **явный режим выбора** в боковой панели; одиночные ⋮-действия, удаление, переименование и восстановление не изменены.

Область выбора всегда одна и названа в интерфейсе: либо **загруженная история одной папки**, либо **загруженные результаты одного поиска**. Выделение принадлежит ключу области (`src/bulk-archive.ts`, `bulkScopeKey`: папка — нормализованный cwd, поиск — запрос в нижнем регистре). Смена области (другая папка, правка запроса, свёрнутая/закрытая папка, переход в панель архива) выделение **сбрасывает**, а не переносит молча. В самой панели архива режима выбора нет: массово архивируются только неархивные диалоги, обратной массовой операции и массового удаления нет.

Кнопка «Выбрать несколько» стоит над списком диалогов области. В режиме выбора строка заменяется на `label.folder-thread` с чекбоксом (`aria-label` «Выбрать диалог …»), меню ⋮ в этих строках не показывается. Панель показывает «Выбрано: N», «Область: …», «Выбрать все (N)» / «Снять выделение», «Отмена» и «В архив». `BulkArchiveBar` берёт только **загруженные** строки: при наличии `nextCursor` под кнопками выводится явное примечание, что остальные страницы войдут лишь после «Загрузить ещё». Это сознательный отказ от «выбрать все на сервере»: протокол не даёт массовой операции, а скрытый обход страниц архивировал бы невидимое пользователю.

Нельзя выбрать диалог, который `bulkBlockReason` отклоняет: `уже в архиве`, `нет рабочей папки` (в результатах поиска бывает группа «Без рабочей папки», а `manageThread` требует абсолютный путь) или `идёт работа, ожидается подтверждение или открыт терминал` (тот же `threadLocked`, что блокирует ⋮). Чекбокс таких строк отключён с подсказкой причины; если диалог был отмечен раньше, `keepSelectable`/`planBulkArchive` его отбрасывают, поэтому устаревший выбор не доходит до RPC.

Подтверждение одно: диалог с заголовком «Архивировать N диалога(ов)?», строкой «Область: …», списком названий (первые 8 и «и ещё K»), перечнем пропущенных с причинами и напоминанием, что диалоги не удаляются, а черновики/вкладки/настройки/история сохраняются. «Отмена» не выполняет ни одного вызова.

Выполнение — **последовательные обычные вызовы `host:manageThread` с `action:'archive'`** по одному диалогу. Отдельного массового host API и новой границы preload нет: каждый диалог проходит прежние `assertIdle`, `coordinator.reserve`, проверку cwd и `active(thread)`, нативный `thread/archive` для Codex и локальный `ClaudeArchiveStore` для Claude. SQLite, транскрипты, rollout JSONL и конфигурация не затрагиваются; `delete` при массовой операции не вызывается никогда. Занятость перепроверяется перед каждым элементом: вкладка могла начать работу после подтверждения.

Виден прогресс («Обработано N из M», текущее название, `role="progressbar"`) и кнопка «Остановить»: она прекращает переход к следующему диалогу, уже выполненные остаются в архиве. Итог сообщает «Архивировано: N из M», отдельно «Не удалось» со текстом ошибки каждого диалога, «Не обработано»/«Остановлено» и «Пропущено как занятые или неподдерживаемые». Успех каждого элемента применяется сразу: `closeAffectedTabs` (общий с одиночным действием) закрывает подтверждённые вкладки, убирает строки из истории папок и панели архива, обновляет `historyRevision`; ошибка следующего диалога это не отменяет. После итога неудавшиеся диалоги остаются выделенными для повтора, при полном успехе режим выбора закрывается. Открытый диалог операции откладывает подготовку обновления Nightly и автосохранение рабочего места так же, как прежние модальные окна.

Проверки: `tests/bulk-archive.test.mjs` (17 случаев: ключи и подписи области, русские числительные, причины блокировки, «выбрать все» только по загруженным и разрешённым, устаревший выбор, порядок и дедупликация плана, частичный отказ, остановка, нулевой успех). `test:bulk-archive` — `scripts/ui-bulk-archive.mjs`, production renderer в Edge с подставными scoped bridges: вход в режим и исчезновение ⋮, одиночный и полный выбор папки, отложенная вторая страница вне области, незанятый выбор при работающем диалоге, подтверждение с числом и областью, «Отмена» без вызовов, удержанный первый вызов и прогресс, частичный отказ с сохранением успехов, уход строк из папки и появление в архиве, сохранённый черновик другой вкладки, отсутствие режима в панели архива, область поиска и сброс выделения при правке запроса, отсутствие delete/rename/restore и модельных запросов; отдельно проверены «Остановить» (выполненный диалог остаётся в архиве, остаток не обрабатывается, режим выбора сохраняется) и перечень «Не будут затронуты» в подтверждении. Скриншоты: `artifacts/bulk-archive-confirm.png`, `artifacts/bulk-archive-progress.png`, `artifacts/bulk-archive-report.png`.

Прогон 2026-10-09: 921 Node-тест прошёл, 2 платформенных пропущены; `tsc --noEmit`, `vite build`, `test:bulk-archive`, `test:archive`, `test:project-tree`, `test:chat-search`, `test:tabs` прошли. Реальные диалоги пользователя не архивировались, модель не вызывалась, сборка Nightly/Release не выполнялась.

Замечание из этой работы: `ProjectSidebar` монтируется по одному экземпляру на вкладку, поэтому эффект, сверяющий поисковый запрос с областью выбора, обязан проверять `active` — иначе пустое поле скрытой вкладки немедленно сбрасывало выделение видимой.
