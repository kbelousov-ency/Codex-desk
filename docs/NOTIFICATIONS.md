# Уведомления и непрочитанные результаты — 2026-09-19

Пункт 3 [плана развития](ROADMAP.md), выполненный после согласия пользователя продолжить разработку в выбранном ИИ порядке. Цель — замечать результаты и вопросы при параллельной работе.

## Поведение

- Windows-уведомления для завершения задачи, вопросов (`requestUserInput`, MCP elicitation), запросов разрешения и ошибок/потери связи. Заголовок фиксированный по виду события, текст — название диалога; ответ модели, команды, полная ошибка и пути в уведомление не включаются. Название само может содержать пользовательский текст.
- При чтении активной вкладки сфокусированного окна системное уведомление не показывается. Фоновая вкладка или неактивное окно допускают показ. Нажатие разворачивает/фокусирует окно и активирует точную сессию; закрытая сессия не создаётся заново.
- Отметка непрочитанного появляется у фоновой/непросматриваемой вкладки. Просмотр вкладки или возвращение фокуса окна снимает её. Кнопка колокольчика со счётчиком открывает «Требуют внимания»: непрочитанные события и все текущие вопросы/разрешения. Просмотр вопроса снимает отметку, но диалог остаётся в списке, пока не получен ответ.
- Настройки доступны второй кнопкой колокольчика с меню: общий переключатель Windows-уведомлений, звук, четыре категории. По умолчанию все категории включены, звук выключен. Настройки Windows могут дополнительно подавить показ/звук. Отметки и список внимания работают независимо от переключателя системных уведомлений.
- События из загруженной истории, повторные completion, прерывание пользователем, retryable error, успешный compact и автопинг не создают уведомления о завершении. Обычная отправка и очередь используют реальные lifecycle-события. Восстановление истории не создаёт фиктивные новые результаты.
- Отметки непрочитанного относятся к текущему запуску и не сохраняются в workspace snapshot; настройки уведомлений сохраняются отдельно. Это сознательно ограничивает первый этап, не меняя историю Codex.

## Реализация и границы

`src/useCodex.ts` сообщает `SessionAttentionEvent` только после проверки thread/turn и lifecycle. `src/App.tsx` передаёт событие с названием в `Workspace`. `Workspace` хранит отметки и открывает вкладки, учитывает focus IPC и прячет устаревшие записи закрытых вкладок. Native focus проверяется host повторно, даже если renderer ещё не получил последнее событие. Окно настроек откладывает подготовку Nightly checkpoint.

`electron/notification-service.mjs`: `NotificationSettingsStore` атомарно сохраняет `notifications.json` в userData канала; Codex config и model/effort/access не меняются. `NotificationService` проверяет window/session ownership, разрешённые поля и длины (`title<=160`, одна строка; `eventId<=256`), повторные события (512 ключей на окно), частоту (2 с на session/kind), максимум 32 удерживаемых native уведомления. При новом событии того же вида предыдущее уведомление заменяется. Close, crash, update, terminal handoff и disposed session прекращают доставку/активацию. Снимок настроек после async чтения не отменяет повторную проверку владения/фокуса.

IPC: `getNotificationSettings`, `setNotificationSettings`, `setNotificationContext`, `notifySession`, `getWindowFocus`; события `onWindowFocus` и `onNotificationActivated`. Данные уведомлений не добавляются в диагностику; разрешены только технические названия каналов и `notification.failed`.

## Проверки

`tests/notification-service.test.mjs` проверяет показ/click через подставной `FakeNotification`, звук, фильтры, ограничения, focus/close races, terminal и межоконную изоляцию. В `CODEX_DESK_TEST=1` native Notification отключён, поэтому автоматические Electron тесты не создают системных всплывающих сообщений.

`scripts/ui-notifications.mjs` — production renderer с fixture bridge: реальные события lifecycle, фон/фокус/непрочитанное, список внимания, вопросы/разрешения, settings load/save/retry, unsupported OS, keyboard/focus и узкое окно. `scripts/ui-notifications-host.mjs` — настоящий Electron/preload/IPC, отдельные профиль/fixture child: сохранение настроек после restart, scopes/validation, неизвестный renderer, focus/activation/unsubscribe, неизменность CLI defaults. Ни модельных запросов, ни записей Codex config.

Нативный toast Windows визуально и вручную кликом не проверялся: API проверен с FakeNotification, IPC — в настоящем Electron. Скриншоты интерфейса: `artifacts/notifications-attention.png`, `artifacts/notifications-settings-940.png`.
