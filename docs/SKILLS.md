# Список установленных навыков

2026-10-02: по просьбе пользователя в окно настроек добавлена вкладка **«Навыки»** со списком установленных навыков (`SKILL.md`). Внутри вкладки свои подвкладки для **Codex** и **Claude Code**: наборы у агентов разные, и сравнивать их удобно в одном месте.

Список только показывает то, что лежит на диске. Приложение не включает, не выключает, не копирует и не изменяет навыки, не передаёт их модели и не меняет конфигурацию агента: какие навыки загрузить, по-прежнему решает сам CLI по своим настройкам.

## Что показано

- Группы по источнику: **проектные** (рабочая папка вкладки), **пользовательские** (каталог агента в профиле), **общие для агентов** (`~/.agents/skills`), **синхронизированные** (`skills/synced/<bucket>`) и **из плагинов**.
- Для каждого навыка — имя и описание из front matter `SKILL.md`, путь к файлу и кнопка «Скопировать путь». Если имени в front matter нет, берётся имя каталога.
- Поиск по названию и описанию фильтрует уже прочитанный список и не обращается к диску снова.
- Блок «Где искали» перечисляет все каталоги с числом найденных навыков и отмечает отсутствующие; нечитаемые файлы и каталоги показаны отдельным списком с кодом ошибки.

Один и тот же навык часто записан сразу в два каталога (синхронизация кладёт копии и в `~/.claude/skills`, и в `~/.agents/skills`). Такие копии сворачиваются в одну строку с пометкой «копий ещё: N»; полный список путей виден во всплывающей подсказке. Одноимённый навык из **другого** источника остаётся отдельной строкой: именно он перекрывает общий или синхронизированный.

## Устройство и ограничения

`electron/agent-skills.mjs` (`AgentSkillsService.list({ provider, cwd })`) читает каталоги напрямую, без запуска CLI и без запроса к модели, поэтому список доступен для обоих агентов независимо от того, какой агент открыт во вкладке и подключён ли он. Каталоги агента берутся из `CODEX_HOME` и `CLAUDE_CONFIG_DIR`, иначе из `~/.codex` и `~/.claude`; проектные — из рабочей папки вкладки.

Каждое чтение в `SkillsSettings` имеет уникальный идентификатор. При смене `cwd` (включая завершение подключения с открытыми настройками) запоздалый ответ или ошибка предыдущего чтения не заменяет список новой папки; сценарий проверяется в `test:skills`.

Проверенные корни: `<дом агента>/skills`, `~/.agents/skills`, `<проект>/.codex|.claude/skills`, `<проект>/.agents/skills` и `<дом агента>/plugins` (каталоги `skills` внутри плагинов ищутся с ограничением глубины 4). Эти пути подтверждены строками установленных CLI Codex 0.156.1 и Claude Code 2.1.278.

Ограничения чтения: 128 КиБ на `SKILL.md`, 500 навыков на ответ (дальше ответ помечается `truncated`), 1000 записей на каталог, 120 символов на имя и 600 на описание. Каталоги и файлы, начинающиеся с точки, пропускаются. Разбор front matter минимальный: `ключ: значение`, кавычки и перенос значения на следующую строку с отступом; остальной YAML не интерпретируется.

Чего список **не** делает: не показывает, включён ли навык в настройках агента (у Codex это отдельная конфигурация, у Claude — фильтры сессии), не учитывает корпоративные/управляемые каталоги и `--add-dir`, не запрашивает `skills/list` у app-server Codex и не вызывает `reload_skills` у Claude Code — оба запроса требуют живой сессии именно этого агента, а `reload_skills` ещё и перечитывает каталоги у работающего CLI. Поэтому возможно расхождение: навык может лежать на диске, но быть отключён в настройках агента.

Путь к `SKILL.md` нельзя открыть кнопкой: `host:openPath` сознательно разрешает только файлы внутри выбранного проекта (см. [Ссылки](FILE_LINKS.md)), а навыки лежат в профиле пользователя. Вместо этого путь копируется в буфер обмена.

## Проверки

`tests/agent-skills.test.mjs` (8 сценариев на временных каталогах): разделение агентов, общий `~/.agents/skills`, проектные навыки, работа без рабочей папки, `CODEX_HOME`/`CLAUDE_CONFIG_DIR`, синхронизированные корзины, навыки плагинов с именем плагина, свёртка копий с приоритетом каталога самого агента, пропуск каталогов без `SKILL.md` и скрытых, ограничения длины, отказ для неизвестного агента.

`npm.cmd run test:skills` (`scripts/ui-skills.mjs`, Playwright + настоящий React): чтение только открытой подвкладки, переключение стрелками, счётчики у подвкладок, группировка и порядок источников, пометка копий, фильтр без повторного чтения, блок «Где искали» с отсутствующим каталогом, ошибки чтения и повтор по кнопке «Обновить», выбор агента вкладки, отсутствие моста, а также настоящая `SettingsDialog`: стрелки внутренних подвкладок не переключают разделы настроек, Escape закрывает окно, при 940×620 и 420×760 нет горизонтальной прокрутки.

`npm.cmd run test:setup-host` дополнительно проверяет настоящий Electron с изолированным профилем: через preload и IPC `skills:list` каждый агент получает свой список (`host-codex`, `host-claude`, общий `host-shared`, проектный `host-project`), чужие навыки не попадают в чужой список, каталоги после чтения не меняются, неизвестный агент и запрос мимо окна отклоняются, относительная рабочая папка не добавляет проектный корень. Прогон прошёл.

На этом компьютере реальное чтение (без запуска CLI) дало без ошибок 34 строки у Codex (14 пользовательских, 11 синхронизированных, 8 из плагинов, 1 общая) и 31 у Claude Code (19 пользовательских, 11 синхронизированных, 1 общая). В каталогах найдено навыков: `~/.codex/skills` 14, `~/.claude/skills` 30, `~/.agents/skills` 12, плагины Codex 8; разница с числом строк — свёрнутые копии. Проектных каталогов навыков в `CodexDesk` нет. Это наблюдение, а не ожидаемое значение теста.
