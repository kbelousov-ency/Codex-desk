# Просмотр файлов в приложении

2026-09-21: добавлены [закрепление рядом с чатом и обновление файла](CONVERSATION_UX.md#результат-рядом-с-чатом). Прежнее модальное окно сохранено; закреплённая панель не захватывает фокус.

`Ctrl+P` и «Найти файл» в панели «Файлы» открывают поиск по имени/пути внутри рабочей папки активной вкладки. Выбор стрелками, Enter открывает файл, Escape закрывает окно. В дереве файлов просмотр доступен отдельной кнопкой; обычное открытие файла во внешней программе сохранено.

Текст и код показаны только для чтения, с номерами строк. Markdown имеет режимы «Предпросмотр» и «Исходник», PNG/JPEG/WebP/GIF — изображение. HTML/SVG показываются исходным текстом. HTML в Markdown не выполняется; существующий `Markdown` заменяет изображения текстом, поэтому просмотр не загружает внешние ресурсы. Кнопка внешней программы использует прежний `openPath` с проверкой границ проекта.

С 2026-09-20 исходник имеет подсветку ключевых слов, строк, чисел, комментариев, JSON-ключей и тегов для распространённых языков по расширению. `source-highlight.ts` — простой лексический разбор без новой зависимости; это не полноценный языковой парсер. Цветной слой содержит только примерно 100 видимых строк; прозрачный `readonly textarea` сохраняет выделение/копирование, прокрутку и существующее «Спросить о выделении». Многострочные токены учитываются до viewport; React выводит исходник текстовыми узлами, HTML не исполняется. В режиме Windows forced-colors показывается обычный текст. Подсветка ограничена первыми 300 000 символов или 40 000 токенов с явным предупреждением; весь загруженный текст остаётся доступен. CRLF/CR нормализуются в LF только для отображения, файл не изменяется.

Поле «Строка» и `Ctrl+G` переводят к номеру в пределах загруженного файла; строка выделяется и оказывается в центре просмотра. Из предпросмотра Markdown переход включает «Исходник». Пустые/отрицательные/дробные и выходящие за пределы номера дают сообщение с доступным диапазоном, без неявного обрезания номера.

«Спросить о выделении» добавляет видимые абсолютный путь, строки (для исходного текста) и выделенный фрагмент в существующий черновик. Для выделения в отрисованном Markdown строки не придумываются. «Добавить путь» добавляет только путь. Вложения и прежний черновик сохраняются; пользователь сам дописывает вопрос и отправляет сообщение. Никаких скрытых инструкций или автоматического модельного запроса нет.

## Контракты и ограничения

- `electron/file-viewer.mjs`: `searchProjectFiles({cwd,query,cursor?,assertActive})` и `readProjectFile({cwd,path,assertActive})`. IPC закреплён за сессией; renderer использует scoped `useBridge`.
- Поиск буквальный, без regex, нечувствителен к регистру; слова запроса сопоставляются с путём. Страницы по 200 файлов. Не обходятся `.git`, `node_modules`, symlink/junction. Остальные каталоги, включая `dist`, доступны.
- Один поиск ограничен 40 000 entries, 3 000 каталогами и глубиной 32; при достижении ограничения показано предупреждение. Обход не создаёт постоянный индекс. Страницы отражают текущее содержимое папки; renderer устраняет дубли, если дерево изменилось между страницами. Недоступные каталоги дают частичный результат.
- Текст: первый 1 МиБ с явным предупреждением для большего файла. UTF-8 и UTF-16 LE/BE с BOM; двоичные данные и неподдерживаемая кодировка дают понятное сообщение. Оборванный в конце UTF-8 символ не превращается в ошибочный текст.
- Изображения: до 20 МиБ, тип определяется по сигнатуре; SVG не превращается в исполняемое изображение.
- Пути только относительно проекта, без `..`, absolute/UNC/device/ADS. Проверяются компоненты `lstat`, canonical `realpath`, обычный файл и открытый handle; ссылки не обходятся даже внутрь проекта. Файл открывается только на чтение, чтение ограничено заранее выделенным буфером. Отложенные ответы не подменяют файл/поиск после смены запроса, вкладки, папки или закрытия окна.

## Проверки

`node --test tests/file-viewer.test.mjs`: временные отдельные папки, поиск/пагинация, UTF-8/UTF-16/Markdown/PNG, неизменность файла, HTML/SVG и бинарные данные, лимиты, traversal/ADS/device, junction/loop и отмена устаревшей сессии.

`node scripts/ui-file-viewer.mjs`: production renderer с подставными scoped bridges; Ctrl+P/Enter, выделение в существующий черновик, Markdown/исходник/изображение/бинарный файл, ошибки/retry/страницы, запоздалые ответы, независимые вкладки и размеры 1440/940. Запросы модели и пользовательские файлы не используются. Скриншоты: `artifacts/file-viewer-1440.png`, `artifacts/file-viewer-940.png`.

Дополнительно сценарий проверяет цветные токены, Ctrl+G из Markdown, ошибочный номер, переход к строке 700 из 800 с CRLF, вертикальную и горизонтальную синхронизацию подсветки. `tests/source-highlight.test.mjs` проверяет сохранение текста, многострочные комментарии на границе viewport, номера/пустую последнюю строку, ограничение больших файлов.

`test:file-viewer-host`: настоящий Electron/preload/IPC и временные fixture файлы; изоляция двух сессий, запрет подмены cwd/session, статических ссылок и недопустимых путей, неизменность bytes/mtime, отсутствие model/resume/config requests. Поддерживает `CODEX_DESK_PACKAGED`.

Чтение повторно проверяет canonical path и identity открытого файла, size/mtime/ctime перед возвратом; конкурентная правка даёт ошибку. Используются O_NOFOLLOW/O_NONBLOCK, где доступны (Windows Node их не предоставляет). Переносимый Node API не даёт атомарного openat по всей цепочке родителей: абсолютная защита от злонамеренного swap-and-restore каталога между системными вызовами не заявляется.
