# Файловые ссылки — 2026-09-17

Пользователь попросил открывать ссылки на изображение/готовый exe обычным нажатием, а по ПКМ показывать меню с пунктом «Открыть в проводнике» и выделением файла.

## Поведение и устройство

- `src/Markdown.tsx` рисует доступные с клавиатуры ссылки. ЛКМ/Enter вызывает scoped `bridge.openPath`; ПКМ локальной ссылки вызывает `bridge.showPathMenu`. Web HTTP(S) открывается в браузере. Ошибки выводятся под Markdown-сообщением (`role=alert`), а не подавляются.
- Явный `urlTransform` пропускает локальные и HTTP(S)-адреса. Это устраняет прежнюю проблему: ReactMarkdown убирал drive-letter href, а UI regex отклонял относительные пути. `javascript:`, `data:`, `vbscript:` и произвольные схемы не передаются host; HTML не исполняется.
- `electron/file-links.mjs` нормализует `E:/...`, `/E:/...`, `E:\...`, относительные пути, URL-кодирование, `file:///`, суффиксы `:line`, `:line:column` и `#Lline`. Перед действиями realpath проверяет границы текущей папки, включая junction/symlink. Сетевые и служебные пути не поддерживаются.
- `openLink` использует Electron `shell.openPath` для файла/папки: Windows выбирает приложение, exe запускается по явному клику пользователя. Это заменяет прежнее поведение `openPath`, которое только показывало расположение. Не применяется командная оболочка и не собирается строка команды из ссылки.
- `showLocalPathMenu` создаёт нативное Electron Menu с пунктом «Открыть в проводнике». Выбор повторно проверяет путь и вызывает `shell.showItemInFolder`; отмена меню ничего не открывает. IPC по-прежнему проверяет окно/вкладку, scoped preload передаёт sessionId; действие использует cwd той вкладки, в которой показана ссылка.

Номер строки влияет только на разбор ссылки: открывается сам файл, без навигации к строке. Локальные ссылки вне проекта остаются недоступны. Наличие файла и права доступа проверяются при действии пользователя; отрисовка сообщения не открывает файлы.

## «Спросить Codex» из дерева файлов — 2026-09-18

Позднее добавлен второй способ указать файл: [кнопка «+»](COMPOSER_FILES.md) выбирает любые локальные файлы и добавляет обычные документы путями, изображения — с preview. Правила открытия ссылок из ответов по-прежнему отдельные и ограничены проектом.

ПКМ / Shift+F10 на файле или папке в правой панели «Файлы» показывает «Спросить Codex» и прежний пункт проводника. Выбранный абсолютный путь добавляется отдельной строкой в конец черновика той же вкладки; после него оставляется новая строка для вопроса, фокус и каретка переходят в конец поля. Уже набранный текст и изображения сохраняются, можно добавить несколько путей. На узком экране панель закрывается, чтобы был виден ввод. Пользователь сам дописывает вопрос и отправляет сообщение обычным `turn/start`: выбор файла не создаёт модельный запрос, не читает содержимое в prompt и не добавляет скрытых инструкций.

Контракт `bridge.showPathMenu(target, {askCodex:true})` возвращает `{action:'askCodex',path}` только при выборе нового пункта; проводник и отмена возвращают `undefined`. `electron/file-links.mjs` повторно проверяет realpath, существование и границы проекта при выборе, host — generation/cwd сессии. Renderer отдельно отбрасывает запоздалый результат после смены вкладки, проекта, скрытия дерева или unmount; обновление списка файлов само по себе результат не отменяет. Обычные ссылки Markdown/WorkLog/Changes не передают опцию и сохраняют меню проводника. Legacy IPC `(target,sessionId)` поддержан рядом с `(target,options,sessionId)`.
