# Локальная диагностика

Запрос пользователя: передавать Codex Desk коллегам и разбирать ошибки по журналам. Автоматическая отправка наружу не запрашивалась и не реализована. Логи относятся к оболочке и её взаимодействию с установленным Codex; конфигурация, история и модель не меняются.

Последующее разделение [Release/Nightly](RELEASES.md) добавило `releaseChannel` в метаданные каждого журнала/отчёта. Каналы имеют отдельные журналы; версия, build ID и дата теперь видны в окне диагностики.

## Использование

Кнопка «Диагностика» внизу области проектов открывает состояние журнала, фактический каталог и действия «Открыть папку» / «Сохранить диагностику». Экспорт через native save dialog создаёт один JSON. Отмена ничего не записывает; ошибка сохранения позволяет выбрать другое место. API принадлежит окну, а не вкладке: работает без сессий, без соединения и в архиве. React ErrorBoundary показывает экран с тем же экспортом при ошибке рендера. При невозможности создать окно native error box указывает путь к журналам.

Коллеге нужно передать JSON, описание действий и примерное время проблемы. Неизвестные ошибки намеренно не содержат произвольное сообщение: иногда описание пользователя необходимо для воспроизведения. Сбои Electron до импорта main, жёсткое завершение процесса и питание не гарантируют последнюю запись. Код не снимает дампы памяти.

## Сбор и границы данных

- `electron/diagnostics.mjs`: JSONL, время UTC, run ID, строгая схема разрешённых событий и полей. Синхронные ограниченные записи оставляют след перед аварией; сбой журнала не прерывает рабочую операцию.
- `electron/main.mjs`: запуск/закрытие приложения и окон, IPC start/complete/failed с длительностью, ошибки renderer/preload и завершение дочерних процессов. Проверка sender/mainFrame предшествует обработке IPC. Renderer error ограничен 8 КиБ и 20 сообщениями в минуту на окно.
- `electron/codex-client.mjs`: запросы App Server, длительность/номер/метод, старт/конец процесса, основные события хода и ошибки. Потоковые дельты не пишутся. Отдельные соединения архива, истории и приватный MCP connection также получают logger.
- `electron/window-session.mjs`: принадлежность вкладке, запуск/завершение терминала. Сам текст терминала и команды пользователя не перехватываются.
- `src/renderer-diagnostics.ts`: window error/unhandledrejection и React errors передаются в host для классификации; сообщение/stack используются только в памяти и фильтруются до записи.

Запрещено записывать целиком RPC params/result/error.data, config, process.env, заголовки, URL, сообщения чата, изображения, команды, MCP input или сырой stderr. Regex-маскировка токенов сама по себе недостаточна: произвольные строки вообще не являются разрешёнными полями журнала. Ошибка хранится как категория/известный код, fingerprint и только допустимые места в исходниках без исходного сообщения. Папки, thread/turn/client/session ID заменяются хешами с солью текущего запуска; связь между событиями сохраняется внутри запуска, исходные значения не экспортируются. Полный конфиг/авторизация никогда не читаются ради диагностики.

## Хранение и точная сборка

Каталог — `path.join(app.getPath('userData'), 'logs')`, включая переопределение `CODEX_DESK_DATA_DIR`. Использовать путь из UI, а не предположение о `%APPDATA%`.

Один запуск ограничен пятью файлами по 2 МиБ; старые неактивные журналы очищаются при запуске/ротации в пределах общего бюджета 10 МиБ. Файлы параллельного живого процесса не удаляются; у каждого такого экземпляра собственный ограниченный бюджет. Экспорт собирает доступные новые и предыдущие записи до установленного лимита и повторно проверяет схему; посторонние файлы и ссылки пропускаются. При невозможности записи показывается состояние ошибки, а приложение продолжает работать.

`scripts/package.mjs` вычисляет SHA-256 из host/renderer файлов и версии, создаёт staged `electron/build-info.json` с `buildId` и `builtAt`. Это важно: разные поставки пока имеют одну product version `0.1.0`. Исходный каталог electron не получает сгенерированный файл. Метаданные включаются также в заголовки ротируемых журналов, чтобы старый сбой относился к своей сборке. Отчёт содержит версии Electron/Node/Chromium/Windows, архитектуру, признак packaged; версия Codex извлекается только из распознанного initialize userAgent. Установленный `0.154.0` фактически возвращает префикс **`codex_desk/0.154.0`**, а не только `codex-cli/…`; оба распознаются, полный userAgent не сохраняется. Отсутствующая версия не подменяется выдуманной. С 2026-09-19 аналогично записывается `claude.version`/`claudeVersion`: Claude CLI отвечает на control-запрос `get_binary_version` при старте (таймаут 5 с, отказ не мешает подключению), а `system/init` первого хода несёт `claude_code_version`; принимается только строка вида `major.minor.patch`. Обе версии показываются в настройках рядом с путём CLI; если установленная версия отличается от проверенной интеграцией (`src/cli-versions.ts`), выводится подсказка сравнить поведение.

## Проверки

`npm test` включает тесты logger/transport/preload, защиты данных, ротации и сбоев записи. `test:diagnostics-ui` — подставной browser bridge: экспорт, отмена, retry, архив/нулевые вкладки/отключение, ошибки окна/React. `test:diagnostics-host` — настоящий Electron/preload/IPC с отдельными profile и JSONL child, ошибки RPC/файлов/renderer, отсутствие секретных маркеров, экспорт после перезапуска. Для проверки поставки задаётся `CODEX_DESK_PACKAGED`. Эти тесты не вызывают модель и не меняют пользовательские конфиг или историю.

Поставка 2026-09-18: 137 Node-тестов, build, diagnostics UI/host, регрессии Continue/архива/resume и native host MCP/compact прошли. Готовая сборка `release/diagnostics/win-unpacked/Codex Desk.exe`, active-build обновлён. Packaged diagnostics host подтвердил сохранение координат ошибок Electron/renderer, отмену и ошибку экспорта с retry, восстановление журналов после перезапуска и принудительного renderer crash; артефакты `artifacts/diagnostics-host-Slhf6k`. Реальный read-only bootstrap проверил шесть моделей и наследование Astra/Ultra, PNG и версию Codex `0.154.0` в журнале, без model turn. Все 18 актуальных host/preload/dist файлов в app.asar сверены побайтно; parser TOML присутствует. Build ID: `a9740e42ffa7bc756d4d4b0da17a97c77193131867ca519be7ffbca7b3018ddf`.

При проверке Node 24 обнаружен нативный ленивый accessor `Error.stack`: отказ от всех getters терял полезные координаты. Разрешён только точно совпадающий встроенный getter, полученный из нового Error; произвольные getters по-прежнему не вызываются. При экспорте старых renderer кадров после смены bundle имени используется фиксированное `renderer.js` с прежними координатами, а точная сборка берётся из заголовка запуска.
