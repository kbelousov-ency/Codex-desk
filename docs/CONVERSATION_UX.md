# Работа с обсуждением и результатом — 2026-09-21

Пользователь выбрал пункты 1, 3, 5, 6 и 8 из нового обсуждения UX. Совместимые функции входят в исходники `0.5.0`; поставка и точные проверки — [RELEASES.md](RELEASES.md). Остальные предложения (шаблоны, пометки на скриншотах, наборы контекста) этим поручением не выбраны.

## Цитирование

Выделение текста внутри одного сообщения показывает «Ответить на выделенное»; также работает `Ctrl+Shift+R`. Цитата добавляется в существующий черновик обычным редактируемым Markdown blockquote. Вложения сохраняются, отправки и скрытого запроса нет. Выделение сразу нескольких сообщений или интерактивных полей вопроса не превращается в цитату; неактивные вкладки и архив не предлагают действие.

В развёрнутом и закреплённом сравнении файлов «Спросить о выделении» добавляет путь и выбранный код в видимый черновик. Номера строк интерфейса не копируются; снимок сравнения остаётся открыт при закреплении. Это обсуждение видимого снимка, не автоматическое редактирование файла.

## Оглавление

Кнопка списка в заголовке открывает «Диалог» в правой панели. Там показаны пользовательские сообщения загруженной истории, поиск по тексту и своей подписи, загрузка более ранних запросов. Выбор переводит к исходному сообщению; на узком экране панель закрывается после перехода.

Карандаш задаёт подпись этапа; пустая подпись возвращает исходный текст. Подписи сохраняются в `localStorage` профиля приложения под ключом `codex-desk:outline:` + JSON `[provider, normalizedCwd, threadId]`; для новой беседы до получения ID используется sessionId. Идентификатор сообщения служит ключом подписи. Код не меняет исходные сообщения, память агента или SQLite. Ошибка сохранения показана с сохранением введённого текста. Release/Nightly имеют независимые профили. Подписи и поиск не отправляются модели.

## Результат рядом с чатом

«Закрепить рядом» в просмотрщике файла или сравнении открывает панель справа. Текст, код, Markdown, изображения и снимки изменений используют прежние безопасные способы чтения; HTML/SVG не исполняются. Для файла доступны «Обновить файл» и поиск другого файла. «Спросить о выделении» добавляет текст в черновик и оставляет закреплённый просмотр открытым.

Сравнение закрепляет копию выбранных `ReviewSelection.edits`, включая `kind`, подписи сторон и номер запроса. Последующие события агента не подменяют снимок; Git-сравнение также сохраняет правильные стороны HEAD/index/рабочая копия. Возврат в большое окно и закрытие доступны в заголовке. Закрепление сохраняется при переключении вкладок текущего запуска; при первом создании беседы остаётся, при смене существующего диалога или папки очищается. Между перезапусками просмотр не сохраняется.

Закреплённый просмотр не захватывает фокус и не приостанавливает очередь/автопинг как модальное окно. Escape в поле сообщения его не закрывает. На ширине до 760px просмотр располагается под чатом; до 1200px боковая панель проектов скрыта, чтобы сохранить место. Обычная правая панель при открытии располагается поверх области результата. Полоса вкладок учитывается отдельно, чтобы не перекрывать кнопки просмотра. Предпросмотр локального веб-сайта оставлен отдельным следующим шагом из исходного предложения.

## Карточка результата

После последнего финального или unphased ответа хода со штатным `turnWork.status === 'completed'` показывается «Результат запроса», если есть сведения о файлах или командах. Основа — `fileChange`, `commandExecution` и `imageGeneration.savedPath` с явным `turnId`; отсутствующая принадлежность не угадывается. Карточка содержит точные статусы и код выхода, включая ошибки и неизвестный исход. Текст ответа не считается доказательством успешной проверки.

Повторные изменения одного файла остаются отдельными событиями. Для успешного переименования открывается целевой путь. Файл открывается рядом с чатом, «Посмотреть изменения запроса» выбирает этот ход в существующей панели изменений, «Событие» раскрывает исходную запись хода работы. История без подтверждения завершения и ходы без ответа карточку не получают. В архиве возможен просмотр карточки без действий изменения/отправки.

## Параллельные вкладки

Индикатор «Одна папка» рядом с вкладками появляется для нескольких независимых открытых бесед одной cwd. Показывает их состояния и даёт переход к вкладке. Архив исключён; одна беседа одного агента в нескольких вкладках считается один раз. Windows/UNC-пути сопоставляются без учёта регистра с нормализацией разделителей и `.`/`..`; разные cwd worktree остаются разными папками.

Совпадения файлов вычисляются только по успешным `fileChange.status === 'completed'` текущих выполняющихся ходов (`turnWork.status === 'inProgress'`, вкладка busy). Для rename учитываются оба пути. Завершённый ход исчезает из пересечений; старая история не возвращается при следующем запросе. Источник — публичные события, не Git status; изменения через shell/терминал могут быть неизвестны, о чём сказано в панели. Это видимость пересечения, не блокировка записи и не гарантия обнаружения всех конфликтов.

## Проверки

`test:conversation-outline`, `test:quote-results`, `test:parallel-activity`, расширенные `test:file-viewer`, `test:diff-review`, `test:git-panel` используют production renderer и подставные scoped bridges. Проверяются черновики/вложения, вкладки, сохранение подписей, навигация, точные статусы, snapshots, refresh, фокус и размеры окна. `tests/task-result.test.mjs` и `tests/parallel-activity.test.mjs` проверяют достоверную привязку событий и нормализацию путей. Это не реальные запросы Codex/Claude; авторизация и пользовательские файлы не используются.
