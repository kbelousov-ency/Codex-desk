# Исправления интерфейса и авторежима — 2026-09-17

Пользователь сообщил: нет авто режима, длинные сообщения уходят за окно без прокрутки, пустые «размышления» не дают полезной информации. Уточнено: авто означает автоматическую работу и проверку разрешений, а не выбор модели.

## Изменения и причины

- Добавлен явный `Access='auto'`, подпись «Авто» в списке доступа.
- `thread/start`/`thread/resume`: `sandbox:'workspace-write'`, `approvalPolicy:'on-request'`, `approvalsReviewer:'auto_review'`.
- `turn/start`: `workspaceWrite` с прежними writableRoots/temp/network ограничениями и теми же policy/reviewer.
- Это встроенная проверка Codex, а не автоматическое нажатие «Разрешить». Проверка может отказать; sandbox остаётся включённым. Полный доступ остаётся отдельным выбором.
- На локальном CLI `--approve-for-me` описан как automatic review с workspace-write. Старый `--full-auto` deprecated; `guardian_subagent` существует в enum, но не выбран из-за менее ясной документированной семантики.
- Авто сохраняется в настройках оболочки и применяется к следующему запросу. Глобальный config Codex не изменяется, модель/effort сохраняются.

Последующее упрощение списка: «Авто» переименовано в «Одобрять за меня», «Папка проекта» — в «Спрашивать разрешение». Протокольное поведение не изменено; [совместимость старых режимов](ACCESS.md).

## Прокрутка

Исходная ошибка: неявная строка CSS Grid и min-height:auto колонок позволяли содержимому растянуть grid за окно. При воспроизведении на 1440×900 высота main-column и нижняя граница composer достигали 23193 px; chat clientHeight совпадал со scrollHeight, поэтому локальной прокрутки не было.

Исправление в `src/styles.css`: ограниченная цепочка html/body/root/app-shell, явная строка `minmax(0,1fr)`, `min-height:0` и ограничение overflow у колонок. Чат, история и действия прокручиваются отдельно; composer закреплён. Логика `scrolledUp` сохраняет положение при чтении выше и следит за потоком, когда пользователь внизу.

Регрессия: [scripts/ui-scroll.mjs](../scripts/ui-scroll.mjs), `npm.cmd run test:scroll`. Длинная история, широкие блоки кода, 1440×900 и 940×640, колесо мыши, закреплённый ввод, возврат вниз и потоковый текст. На старом CSS воспроизведено падение, после изменения тест проходит.

## Пояснения и реальные действия

Раньше `Reasoning` создавал пустую карточку «Codex обдумывает задачу…». Она удалена: whitespace/пустые массивы ничего не рисуют. `reasoningText()` сначала берёт непустой summary, затем content; `summary:['']` больше не скрывает полезный content. Непустые карточки называются «Пояснения Codex» и доступны раскрытыми после окончания.

Последующее уточнение: отдельные карточки в чате заменены [компактным ходом работы по запросу](WORK_LOG.md), сворачиваемым перед финальным ответом. Прежнее решение сохранено выше как причина отказа от пустых заглушек; фильтрация непустых summary/content осталась.

Никакие мысли не придумываются. Не меняем summary-настройку модели, не читаем encrypted_content. Если Codex не прислал пояснений, блока нет.

`activityLabel()` показывает конкретику из событий: read/listFiles/search из commandActions, команду, изменяемые файлы, инструмент MCP, агента. В текущем индикаторе работы показывается активное действие; те же подписи видны в панели «Действия».

## Проверки и сохранённые ограничения

- Реальный `thread/start` в ephemeral-беседе принял `auto_review` + on-request + workspaceWrite и сохранил GPT-6 Astra/Ultra. Model turn не запускался, решение по конкретной эскалации в этом тесте не проверялось.
- 17 тестов транспорта/host и новая регрессия прокрутки прошли.
- UI сценарии прошли для auto start/turn/resume, сохранения режима после переподключения, возврата к ручному read-only, скрытия пустых пояснений, fallback content и меток read-действий. Fixture истории исправлен с full на legacy. Fake bridge не заменяет проверку протокола реального сервера.
- Прежние ограничения paginated history, MCP-форм и файловых ссылок остаются в [AI_CONTEXT.md](AI_CONTEXT.md).
Windows package обновлён. Проверка запуска готового .exe, загрузки реальных моделей и вставки PNG выполнена отдельно от сценариев браузера.

## Единые подсказки функций — 2026-09-21

После оформления версии пользователь попросил такой же дизайн описаний остальных функций. Все 99 нативных JSX `title` у HTML-элементов заменены на `data-tooltip`; props `title` React-компонентов (экспорт, передача задач, меню диалогов, блоки токенов) сохранены. Размеры и действия самих кнопок не меняются.

`src/TooltipLayer.tsx` подключён один раз в `main.tsx`. Portal `role=tooltip` поверх панелей/модальных окон показывает прежний текст на тёмной скруглённой плашке с обводкой и тенью; длинные пути/описания переносятся, переводы строк сохраняются. Положение ограничено окном: под целью, при нехватке места над ней. Наведение — задержка 400 мс, клавиатурный фокус — сразу; Escape, действие, прокрутка, resize и уход из окна скрывают описание. Можно перевести указатель на плашку и выделить её текст. Подсказки отключённых контролов доступны по наведению; текст причин сохранён.

Ближайший `data-tooltip` определяет описание вложенных элементов. Общий слой добавляет только свой ID в `aria-describedby` и убирает его при закрытии, сохраняя другие ID и существующие доступные имена. MutationObserver активен только при открытой подсказке, обновляет изменившееся описание и скрывает его при удалении/скрытии цели. Специальная карточка версии остаётся; событие `codex-desk:tooltip-open` не позволяет двум плашкам отображаться одновременно. Нативные всплывающие title убраны, отдельные hover-инструкции моделям не добавляются.

`scripts/ui-tooltips.mjs` проверяет реальную toolbar на fixture bridge, клавиатуру/мышь/отключённые кнопки, вложенные SVG, длинные описания, обновление/удаление цели и узкое окно. Существующие сценарии с селекторами title переведены на data-tooltip. Все проверки без запросов модели.
