# Кузьмич (Experimental 3)

2026-10-09. Отдельный канал `experimental3` с профилем «Кузьмич Experimental 3» (`electron/release-channel.mjs:6-7`, `electron/app-identity.mjs:1`), исполняемый файл `Kuzmich.exe` (`scripts/package.mjs:61,72`). Канал включает режим `routerOnly` (`electron/main.mjs:77`): все вкладки создаются с `connectionSource: 'router'` (`electron/main.mjs:398,724`), а мастер настройки подменяется на свой (`setup:state` возвращает `experimental3: routerOnly` — `electron/main.mjs:447`, ветвление — `src/SetupGate.tsx`).

Решения и фазы — [KUZMICH_PLAN.md](KUZMICH_PLAN.md). Контракт ручек портала, подтверждённый по `git show HEAD:` в Coder-Portal, — [PORTAL_COMMITTED_API.md](PORTAL_COMMITTED_API.md).

## Концепт

От пользователя — только авторизация (KUZMICH_PLAN.md, «Концепт»). Портал не меняется: используются только закоммиченные ручки прода. Всё, что портал позволяет сделать по cookie-сессии или по ключу роутера, Кузьмич делает программно; там, где портал требует человека, его показывают, а не обходят.

Выбран **путь A** — приложение само читает cookie-ручки портала и само пишет конфигурации CLI (KUZMICH_PLAN.md, «Фаза 2»). Путь B (запуск connect-скриптов портала) отвергнут после сверки контракта: скрипты интерактивны — `Read-Host` в `finally` выполняется всегда, `Confirm-Close` ждёт Y/N 60 секунд, `Enable-AppVm` поднимает UAC, `claude.ps1` ставит ещё и приложение Claude, а `target:"on"` может увести в Microsoft Store (PORTAL_COMMITTED_API.md §5a, §9). Это нарушает требование «только авторизация». Путь B остаётся пользователю через трей Боцмана и кнопки кабинета — вне Кузьмича; маркеры совместимы, конфликта нет, но наш merge обязан повторять `codexcfg.keep_foreign` и `claudecfg.CLEARED`.

## Один вход

Окно входа — `electron/portal-auth-window.mjs`. Открывается **внутри приложения**; внешний браузер не используется.

- Изолированный раздел хранения `persist:kuzmich-portal` (`electron/portal-session.mjs:1`, подключение — `electron/main.mjs:120-121`). Cookie живёт только в main process; в renderer она не попадает.
- Загрузки из окна запрещены (`will-download` → `preventDefault`, `electron/portal-auth-window.mjs:34-35`): всё нужное host скачивает сам. Разрешения (камера, геолокация и прочее) отклоняются безусловно (`:32-33`). Навигация и редиректы допускаются только по `https`, попапы складываются в то же окно, а не уходят в систему (`:38-44`).
- Стартовый адрес — `/auth/login?next=%2F` (`electron/portal-session.mjs:158`). Keycloak живёт на своём origin, поэтому межоригинные https-редиректы разрешены — без них вход не завершится.
- Успех определяется не по URL страницы портала, а по возврату на origin портала на путь вне `/auth/` (`electron/portal-session.mjs:160-162`), после чего статус перечитывается ручкой «кто я». Закрытие окна человеком — отмена, а не вечное ожидание (`:151-154`, `:159`).
- Петля входа ограничена: более трёх повторов `/auth/login` прекращают поток с сообщением «Portal повторяет вход» (`electron/portal-session.mjs:52,164-171`).

### Что именно спрашивается у портала

`PortalSessionService._refresh` вызывает `GET /api/me`, затем `GET /api/key` (`electron/portal-session.mjs:104,114`). Первая даёт почту, имя и `entitlements` по каждому продукту, вторая — состояние ключа (PORTAL_COMMITTED_API.md §2, §3). Статус кэшируется на 60 секунд (`electron/portal-session.mjs:52,132`); `/api/me` имеет побочные эффекты и для поллинга не предназначен (PORTAL_COMMITTED_API.md §2).

Состояния ключа: `approved`, `pending`, `none`, `held-elsewhere` (`electron/portal-session.mjs:86-96`). Важно: `GET /api/key` отдаёт ключ и с `approved: false`, а такой ключ не работает ни в роутере, ни в дверях релея (PORTAL_COMMITTED_API.md §3). Поэтому **сам ключ сохраняется в приватное поле `#routerKey` только при `approved: true`** (`electron/portal-session.mjs:50,90,220-223`).

В renderer уходит только снимок: `state`, `email`, `name`, `keyState`, `heldBy`, `products`, `message` (`electron/portal-session.mjs:5-7,64,109-113`). Строки проходят через `publicText` — не длиннее 512 символов, без `CR`/`LF`/`NUL` (`:9-11`). Ключ роутера и cookie в renderer не передаются никогда. Ответы портала ограничены 64 КиБ (`:3,15,26`), редиректы на запросах API запрещены (`redirect: 'error'`, `:72`), мутации несут `X-Requested-With: fetch` (`:73`) — без этого заголовка `csrf_guard` портала отвечает 403 (PORTAL_COMMITTED_API.md §0).

### Выход

`logout()` чистит **только свой раздел** (`clearStorageData`) и намеренно **не** вызывает `/auth/logout` (`electron/portal-session.mjs:229-232`): эта ручка портала гасит и SSO-сессию Keycloak, общую с другими приложениями (PORTAL_COMMITTED_API.md §1).

## Подключение (путь A)

`electron/portal-connect.mjs`. Шлюз: подключение начинается только при `state === 'signed-in'` **и** `keyState === 'approved'` (`:78-79`). Набор продуктов — запрошенные ∩ разрешённые порталом; продукт, которому портал не даёт доступ, помечается `skipped` (`:92`), неустановленный CLI — тоже `skipped` (`:94`).

Запись в конфигурации обоих CLI проходит через ту же взаимную блокировку, что остальные мутации приложения (`runMutation` → `setupService._exclusive`, `electron/main.mjs:163`, `electron/portal-connect.mjs:119-131`): активная задача, ожидающее подтверждение или открытый терминал подключение не пускают. Закрытие окна приложения отменяет и вход, и подключение (`electron/main.mjs:1442-1443`). Ключ роутера и токен Claude вычищаются из всех текстов статуса перед отдачей в renderer (`electron/portal-connect.mjs:35,53-54,87,270`).

### Codex → `config.toml`

1. Конфигурация берётся по **Bearer-ключу**: `GET /api/codex/provider` и `GET /api/codex/defaults` (`electron/router-portal.mjs:264-267`).
2. Запись идёт **через собственный config-API Codex CLI**, а не правкой файла: `config/read` с `includeLayers`, затем `config/batchWrite` (`electron/portal-config.mjs:149,215`). Принимается только слой `user` без профиля, с непустой `version` и без `disabledReason` (`:153`).
3. Перед записью создаётся резервная копия `<config.toml>.backup-<ISO>-<uuid>` с флагом `wx` и режимом `0600` (`electron/portal-config.mjs:208-209`).
4. Защита от одновременной правки: перед сохранением заново сверяются путь, `version` и SHA-256 содержимого (`:203`); расхождение прекращает запись.
5. Ключ попадает в `experimental_bearer_token` (`:50`) — Codex принимает bearer кастомного провайдера только так (PORTAL_COMMITTED_API.md §4). Поля `env_key` и `env_key_instructions` снимаются, чтобы остался один источник авторизации (`:95`).
6. Успешными считаются ответы `ok` и `okOverridden` (`:221`); во втором случае к результату добавляется предупреждение, что часть значений переопределена другим уровнем конфигурации Codex (`:225`).

Предпросмотр живёт 10 минут (`electron/portal-config.mjs:5`).

### Claude → `~/.claude/settings.json`

1. Конфигурация берётся **по cookie-сессии**: `GET /api/config/claude?scope=global` (`electron/portal-connect.mjs:268`).
2. Ответ проверяется: все значения `env` — строки, `ANTHROPIC_BASE_URL` — `https` без логина, пароля, query и фрагмента, `ANTHROPIC_AUTH_TOKEN` — непустая строка без управляющих символов, неизвестные слоты моделей отклоняются (`:18-32`).
3. Целевой файл — `settings.json` в `CLAUDE_CONFIG_DIR`, иначе в `%USERPROFILE%\.claude` (`:233-234`).
4. Если файл был, создаётся резервная копия `<settings.json>.backup-<ISO>-<uuid>` с флагом `wx` и режимом `0600` (`:239-241`). Если файла не было, копии нет — и сообщение об ошибке это прямо говорит (`:115`).
5. **Снимаются ровно шесть имён** (`electron/portal-connect.mjs:11-12`) — это `claudecfg.FOREIGN_AUTH + claudecfg.CLEARED` портала (PORTAL_COMMITTED_API.md §5a):

   | Имя | Зачем снимать |
   |---|---|
   | `ANTHROPIC_API_KEY` | Claude Code берёт его раньше подписки и перебил бы наш `ANTHROPIC_AUTH_TOKEN` |
   | `ANTHROPIC_MODEL` | устаревшее |
   | `ANTHROPIC_DEFAULT_OPUS_MODEL` | место модели должно остаться встроенным, если доступа к ней нет |
   | `ANTHROPIC_DEFAULT_OPUS_MODEL_NAME` | то же |
   | `ANTHROPIC_DEFAULT_FABLE_MODEL` | то же |
   | `ANTHROPIC_DEFAULT_FABLE_MODEL_NAME` | то же |

6. Затем накладывается `settings.env` портала; **сливается только блок `env`**, всё остальное в файле сохраняется (`:248-251`). Присланные порталом при `scope=global` `model`, `effortLevel` и `autoUpdatesChannel` намеренно **не** применяются — они перезаписали бы личные предпочтения пользователя (комментарий `:250`). Реестровая политика приложения Claude (`HKCU:\SOFTWARE\Policies\Claude`), которую пишет штатный скрипт портала, тоже не трогается (PORTAL_COMMITTED_API.md §5a).
7. Запись атомарная: временный файл + `rename`, причём перед переименованием исходный файл перечитывается и сверяется с тем, что было прочитано вначале (`:254-262`).
8. После записи подключение перечитывается из только что записанного файла (`readClaudeConnection`, `electron/boatswain-setup.mjs:60-77`) и сохраняется в `routerConnections` для вкладок (`electron/portal-connect.mjs:276-279`). Боцман для этого **не нужен**: функция читает наш собственный `settings.json`, а не агента.

### Проверка

Для каждого продукта после записи выполняется `GET {baseUrl}/models` с `Authorization: Bearer <ключ>` (`electron/portal-connect.mjs:223-225`): для Codex — по `provider.base_url` из ответа портала (`:171`), для Claude — по `ANTHROPIC_BASE_URL` и его токену (`:274`). Только после успешной проверки продукт получает состояние `done` с сообщением «Подключение проверено» (`:101`), и вкладки переподключаются (`reconnectAfterSetup`, `:173,281`).

Сообщение об ошибке после начатой записи всегда называет резервную копию и честно говорит, что записанные настройки не откатывались (`:115`).

## Что сессия Portal НЕ затрагивает

Сессия портала живёт **8 часов** (`SESSION_MAX_AGE`, PORTAL_COMMITTED_API.md §0). Это срок **только для cookie-ручек портала** — `/api/me`, `/api/key`, `/api/config/claude`.

Повседневная работа от неё не зависит: оба CLI работают по **ключу роутера**, записанному в их собственные файлы — `experimental_bearer_token` в `config.toml` (`electron/portal-config.mjs:50`) и `ANTHROPIC_AUTH_TOKEN` в `settings.json` (`electron/portal-connect.mjs:251`). Те же файлы читают терминальные `codex` и `claude` вне приложения. Истечение сессии портала не разрывает ни одну вкладку и не требует повторного входа для работы — только для нового обращения к порталу (повторного подключения, перевыпуска ключа, чтения состояния).

Лимиты в подвале composer (`RouterUsage`, `src/App.tsx:701`) тоже идут по ключу роутера: в режиме `routerOnly` ключ берётся из профиля подключения вкладки (`electron/main.mjs:422-425`) и уходит в `GET /api/relay/limits` с Bearer (`electron/portal-limits.mjs`); с 2026-10-10 из ответа релея вкладке показывается только строка её агента — «Claude» для вкладки Claude, «Codex» для остальных (`productLimits`, см. ROUTER_USAGE.md). Эта ручка относится к ветке релея и требует включённого `RELAY_ENABLED` на портале (PORTAL_COMMITTED_API.md §7) — её недоступность не означает, что подключение CLI сломано.

## Боцман — следующая волна

Боцман вынесен в отдельную фазу (KUZMICH_PLAN.md, «Фаза 3»: A5 — скачивание `/api/boatswain/setup/{token}.exe` по cookie и запуск штатного установщика с его окном; B5 — галочка и статус в мастере). В текущей сборке его нет.

Для подключения CLI он **не нужен** — это зафиксировано в плане (KUZMICH_PLAN.md, «Принятые допущения», п. 1): конфигурация берётся напрямую по cookie, а Боцман нужен для скиллов и MCP с портала и для уведомлений. Подтверждение в трее Боцмана (`POST /api/boatswain/switch`) как основной путь не используется: портал исполнит команду только после подтверждения человеком на машине (PORTAL_COMMITTED_API.md §7).

Единственное упоминание Боцмана в пути подключения — чтение нашего же записанного `settings.json` функцией `readClaudeConnection` (`electron/boatswain-setup.mjs:60-77`); установленный Боцман для неё не требуется.

## Мастер

Четыре шага: «CLI» → «Вход» → «Подключение» → «Готово» (`src/KuzmichSetupWizard.tsx`). Шаг «CLI» использует существующий bridge (`scan`/`install`/`chooseExecutable`). Шаг «Вход» показывает состояние ключа и то, какие CLI разрешает портал, рядом с тем, что установлено. Шаг «Подключение» закрыт шлюзом: без входа и без `approved` ключа вместо кнопки показывается объяснение и переход к шагу «Вход», а `portalConnect` не вызывается. Пока запись идёт, закрытие мастера и Escape заблокированы. Ошибка одного продукта не блокирует шаг и даёт кнопку «Повторить» именно для него.

Контракт между renderer и host — `src/setup-types.ts` (`PortalSessionStatus`, `PortalConnectStatus`) и `electron/preload.cjs:94-100`.

UI-тесты без портала и без CLI: `npm run test:kuzmich-setup` (`scripts/ui-kuzmich-setup.mjs`).

## Живая приёмка

Первый настоящий прогон на машине владельца. Выполняется сверху вниз. Каждый шаг: что сделать → что должно получиться → что приложить, если не получилось.

Общее правило отчёта о сбое: снимок экрана целиком (видно заголовок окна и шаг мастера), текст сообщения об ошибке дословно, и — если шаг касался файлов — пути из сообщения.

### 1. Собрать и установить сборку поверх предыдущей

```
npm run check
npm run package:experimental3
npm run package:experimental3-installer
```

- `package:experimental3` публикует канал в `release/experimental3/Kuzmich.exe` (`scripts/package.mjs:72-73`).
- `package:experimental3-installer` читает `release/experimental3`, проверяет его и кладёт установщик в `artifacts/installer-experimental3` (`scripts/installer.mjs:91`).

**Перед запуском установщика закройте уже установленный Кузьмич.** Установка идёт для текущего пользователя, без запроса прав администратора и без выбора каталога (`perMachine: false`, `allowElevation: false`, `allowToChangeInstallationDirectory: false` — `scripts/installer.mjs:63-64`), поверх прежней версии; профиль и настройки сохраняются (канал `experimental3` имеет свой профиль и маркер `.experimental3-profile-initialized.json` — `electron/release-channel.mjs:71`).

**Ожидается:** на экране приветствия — «Установим Кузьмич и подключим Router через Portal…» (`scripts/installer.mjs:55`), на финальном — «Откройте Кузьмич, чтобы подключить Router через Portal…» (`scripts/installer.nsh:62-64`).

**Если не получилось:** приложите вывод упавшей команды целиком. `package:experimental3-installer` падает, если канал `release/experimental3` не собран или не проходит проверку — в этом случае сначала повторите `package:experimental3`.

### 2. Открыть мастер

Оставьте галочку «Открыть Кузьмич» на финальном экране установщика — он запускает приложение с `--setup`, и мастер открывается сам (`scripts/installer.mjs:55`, `electron/main.mjs:1377`).

Если приложение уже было открыто или мастер закрыли: **Настройки → «Установка и настройка агентов» → «Открыть мастер»** (`src/App.tsx:732`).

**Ожидается:** в боковой колонке бренд «Кузьмич» и четыре шага: CLI, Вход, Подключение, Готово.

**Если не получилось** (открылся обычный мастер «Настроим ваше рабочее место» с пятью шагами): это значит, что канал определился не как `experimental3`. Приложите снимок бокового списка шагов и строку версии из Настроек (блок сведений о сборке).

### 3. Шаг «CLI»

Проверьте, что Codex CLI и Claude Code CLI отмечены как «Установлен». Если какой-то не найден — либо «Установить и продолжить», либо «Указать путь» к уже имеющемуся exe.

**Ожидается:** оба CLI со статусом «Установлен», затем «Продолжить».

**Если не получилось:** снимок карточки агента с текстом ошибки под ней. Подключение к такому CLI будет помечено `skipped` — это ожидаемо, а не отдельный сбой.

### 4. Вход через окно Keycloak

Нажмите «Войти в Portal». Откроется окно **внутри приложения** — внешний браузер открываться не должен. Пройдите вход Keycloak.

**Ожидается:** окно закрывается само, в карточке появляется ваша почта и «Вход выполнен».

**Если не получилось:**
- окно не открылось или сразу закрылось — снимок карточки с сообщением (например «Не удалось открыть окно входа в Portal»);
- вход зацикливается — ожидается сообщение «Portal повторяет вход. Закройте окно и попробуйте снова» после трёх повторов (`electron/portal-session.mjs:164-171`); приложите снимок;
- открылся системный браузер — это дефект, приложите снимок и сообщите; окно обязано быть внутри приложения.

### 5. Состояние ключа

**Ожидается для учётной записи владельца: «Ключ роутера активен»** (`approved`) — администраторы и суперадмины портала получают активный ключ сразу (PORTAL_COMMITTED_API.md §3).

Другие исходы и что делать:
- «Ключ ждёт одобрения администратора портала» (`pending`) — паузу снимает администратор портала; после этого «Проверить снова». Подключение на этом шаге будет закрыто шлюзом — это правильное поведение, а не ошибка;
- «Ключ роутера пока не выдан» (`none`) — «Получить ключ»; новый ключ может попасть на паузу;
- «Ключ роутера выдан на другую почту» — в сообщении будет указана почта; войдите под ней.

Проверьте строки доступа: для каждого CLI видно «Portal разрешает» или «Portal не даёт доступ» и рядом «установлен»/«не установлен».

**Если ожидается `approved`, а показано иное:** снимок карточки целиком (почта + состояние ключа + строки доступа). Доступ к продуктам решает control plane роутера, а не портал (PORTAL_COMMITTED_API.md §10) — поэтому «Portal не даёт доступ» к Claude при активном ключе возможно и не является дефектом приложения.

### 6. «Подключить» оба CLI

На шаге «Подключение» нажмите «Подключить».

**Ожидается:** по каждому CLI строка проходит «Подключаем…» → «Подключён через роутер», под ней — путь записанного файла и, если файл существовал раньше, путь резервной копии. В конце — «Подключение завершено». Пока идёт запись, «Продолжить», «Назад» и закрытие мастера заблокированы — это ожидаемо.

Ожидаемые пути:
- Codex — `%USERPROFILE%\.codex\config.toml` (или в каталоге `CODEX_HOME`, если он задан);
- Claude — `%USERPROFILE%\.claude\settings.json` (или в каталоге `CLAUDE_CONFIG_DIR`).

**Если не получилось:** снимок карточки сбойного CLI с полным текстом ошибки — он содержит путь резервной копии и фразу о том, откатывались ли настройки. Нажмите «Повторить» для этого CLI; если ошибка повторяется, приложите оба снимка. Сообщение «Завершите текущие задачи, подтверждения и работу в терминале …» означает занятость приложения — закройте активные диалоги и терминалы и повторите.

Пройдите на «Готово» и проверьте сводку: по каждому CLI есть строка «Подключение Codex» / «Подключение Claude» с итогом.

### 7. Проверка ВНЕ приложения: терминальные CLI

Откройте **новое** окно терминала (переменные среды и файлы читаются при запуске).

```
codex
claude
```

Задайте каждому короткий вопрос (например «ответь одним словом: привет»).

**Ожидается:** оба отвечают. Это подтверждает, что запрос уходит через роутер по записанному ключу — те же файлы читают и терминальные CLI, и приложение.

Дополнительно, без обращения к модели, можно сверить сами файлы:
- в `config.toml` должны быть `model_provider = "router"`, таблица `[model_providers.router]` и в ней `experimental_bearer_token` (PORTAL_COMMITTED_API.md §4);
- в `settings.json` в блоке `env` должны быть `ANTHROPIC_BASE_URL` и `ANTHROPIC_AUTH_TOKEN`, и **не должно быть** `ANTHROPIC_API_KEY`.

**Внимание:** оба файла содержат ваш персональный ключ роутера. Не прикладывайте их содержимое к отчёту целиком и не пересылайте — присылайте только имена ключей и затёртые значения.

**Если не получилось:** снимок терминала с текстом отказа CLI. Отдельно сообщите, отвечает ли при этом вкладка в самом приложении: если в приложении работает, а в терминале нет — дело в файлах CLI, если не работает нигде — в ключе или доступе на роутере.

### 8. Проверка ВНЕ приложения: резервные копии

Рядом с каждым конфигурационным файлом должна лежать копия прежнего:

```
%USERPROFILE%\.codex\config.toml.backup-<дата>-<uuid>
%USERPROFILE%\.claude\settings.json.backup-<дата>-<uuid>
```

Формат имени — `<путь>.backup-<ISO-время>-<uuid>` (`electron/portal-config.mjs:208`, `electron/portal-connect.mjs:239`).

**Ожидается:** копия есть для каждого файла, который существовал до подключения. Если файла раньше не было, копии не будет — это нормально и сообщение об ошибке в таком случае прямо пишет «не создана — файла раньше не было».

**Ручное восстановление, если нужно вернуть как было:**
1. закройте приложение и все терминальные `codex` / `claude`;
2. скопируйте файл резервной копии обратно на имя исходного (перезаписав его);
3. если резервной копии нет, потому что файла до подключения не существовало, — просто удалите созданный файл;
4. откройте новое окно терминала и проверьте, что CLI ведёт себя как до подключения.

Штатный способ отменить подключение на стороне портала — «Вернуть подписку» в кабинете или в трее Боцмана (`target=off`, PORTAL_COMMITTED_API.md §5): он снимает роутер из конфигурации агента. Это путь B, вне Кузьмича (KUZMICH_PLAN.md, «Фаза 2»).

**Если копий нет, а файлы существовали:** это дефект — приложите список файлов в обоих каталогах (имена, без содержимого) и снимок карточки «Подключение» с указанными в ней путями.

### 9. Проверка: лимиты в подвале приложения

Откройте вкладку агента и посмотрите в подвал composer, рядом с индикатором кэша.

**Ожидается:** блок лимитов роутера с остатком в процентах и временем сброса.

**Если лимитов нет:** это **не обязательно** дефект подключения. Ручка `GET /api/relay/limits` принадлежит ветке релея и требует включённого `RELAY_ENABLED` на портале (PORTAL_COMMITTED_API.md §7); при выключенном релее лимиты недоступны законно. Приложите снимок подвала и текст подсказки, если она появляется; сверьте с тем, видны ли те же лимиты в личном кабинете портала.

### 10. Проверка: сессия портала не влияет на работу

Через час-другой работы (или после перезапуска приложения) просто продолжите работать во вкладках.

**Ожидается:** вкладки работают без повторного входа в Portal. Сессия портала нужна только для обращений к порталу; CLI работают по ключу роутера из своих файлов. Если при открытии шага «Вход» появится «Сессия Portal истекла. Войдите снова» — это ожидаемо после 8 часов и не должно ломать работу вкладок.

**Если вкладки перестали работать вместе с истечением сессии портала:** это дефект разделения; приложите снимок вкладки с ошибкой и снимок шага «Вход».
