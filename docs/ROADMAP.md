# Идеи развития Codex Desk — 2026-09-19

Идеи предложены после чтения документации и исходников. Сначала пользователь поручил сохранить список и реализовать пункты **1 и 2**. Затем согласовал дальнейшее развитие по предложенному плану, оставив порядок разработки на усмотрение ИИ: ближайший этап — **пункт 3, уведомления**. Последующие этапы — проверка изменений, поиск истории/закладки, просмотр файлов, изоляция задач и действующие настройки. Уже существующие вкладки, история, поиск названий, дерево файлов, MCP, diff, переход в терминал и диагностика служат основой.

Пункты 1 и 2 реализованы в исходниках 2026-09-19 и прошли проверки renderer/host. Поставка — Nightly по обычному процессу; перенос в Release требует отдельного подтверждения. Факты поставки отмечаются в тематических заметках.

1. **Восстановление рабочего места.** Автосохранение вкладок, активного диалога, черновиков, изображений, настроек и позиции чтения после обычного закрытия или сбоя. Основа — снимок обновления Nightly; прежде он применялся только при специальном перезапуске. Поручено 2026-09-19; реализация и проверки — [WORKSPACE_STATE.md](WORKSPACE_STATE.md).
2. **Уточнения и очередь сообщений.** Два явных действия: уточнить текущую задачу через `turn/steer` и отправить следующий запрос после завершения. Видимая очередь с редактированием, отменой и паузой; после восстановления она приостановлена. Прежний UI блокировал отправку при busy, хотя адаптер уже разрешал steer. Поручено 2026-09-19; детали — [MESSAGE_QUEUE.md](MESSAGE_QUEUE.md).
3. **Уведомления.** Реализованы в исходниках 2026-09-19: завершение задачи, вопрос, запрос разрешения, потеря соединения; переход к вкладке, непрочитанный результат, список внимания, настройки звука/событий. Исходной основой были индикаторы вкладок. Проверки и ограничения — [NOTIFICATIONS.md](NOTIFICATIONS.md).
4. **Проверка изменений.** Реализованы [сравнение до/после](CHANGES.md), номера строк, фильтр по запросу, поиск файлов, навигация фрагментов и большой просмотр. Добавлен отдельный [Git status/diff](GIT.md): события правок из диалога не гарантируют совпадения с итоговой рабочей папкой. Следующий этап — выборочный откат с проверкой последующих и ранее существовавших пользовательских изменений.
5. **Поиск содержимого всей истории и закладки.** Фрагмент совпадения, фильтр проекта, переход к сообщению, собственные подписи закладок. Сейчас общий поиск ищет названия, Ctrl+F — содержимое открытого чата. Локальный индекс строить через поддерживаемое чтение истории, не редактируя SQLite Codex.
6. **Просмотр файлов внутри приложения.** Ctrl+P, текст/код/Markdown/картинки, переход к строке, «Спросить о выделении» с видимым текстом в composer. Сейчас «Спросить Codex» добавляет полный путь, открытие файла использует внешнее приложение.
7. **Изоляция задач одного проекта.** Отдельная папка и ветка через Git worktree, просмотр и перенос результатов. Процессы вкладок независимы, но одинаковая cwd означает общие файлы. Более крупная задача, особенно полезная для параллельной разработки.
8. **Действующие настройки и возможности.** Модель, effort, провайдер, доступ, версия CLI и источник каждого значения; доступные навыки, состояние MCP и формы дополнительных данных. Сейчас формы MCP можно только отклонять. Поддержку возможностей проверять по установленному CLI, не обещая универсального discovery API.

Дополнительные идеи:

- Панель подагентов: задачи, состояние, ошибки и переход к полученному результату; агентские события частично уже отображаются.
- Ответвление беседы для другого подхода. Копирование истории не создаёт отдельную копию файлов; совместимость штатного метода проверяется отдельно.
- Палитра Ctrl+K, Ctrl+Tab, восстановление закрытой вкладки, закрепление и перетаскивание.
- Экспорт беседы в Markdown/HTML, выбор переписки или хода работы; собственные шаблоны вставляются в поле ввода перед отправкой.
- Переподключение к текущему диалогу одной кнопкой с сохранением видимой истории и черновика. Обработка writer-lock и повтор resume уже существуют; обходить их нельзя.
- Явное состояние неподтверждённой отправки при RPC timeout и сверка `clientUserMessageId`, чтобы не повторить принятую задачу. Timeout сам по себе не доказывает отказ сервера.

Предложенный порядок после первых двух пунктов: уведомления → проверка изменений и поиск содержимого истории. Приоритеты можно пересматривать по использованию. Сохраняем App Server, настройки терминального Codex, видимость всех пользовательских запросов; скрытые инструкции модели не добавляем.
