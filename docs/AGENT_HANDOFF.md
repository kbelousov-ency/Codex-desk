# Передача задачи между агентами

Кнопка «Передать задачу другому агенту» в шапке открытого диалога переносит задачу с контекстом в обе стороны: Codex → Claude Code и Claude Code → Codex. Принимающий агент получает новую вкладку в той же рабочей папке; файлы проекта общие. Исходная беседа сохраняется. Для отдельной копии файлов предусмотрены [изолированные задачи](WORKTREE.md).

В окне передачи поле «Задача для…» первоначально содержит текст исходного черновика, а при пустом черновике — видимую просьбу продолжить задачу с контекстом. По умолчанию выбрана «Переписка и ход работы»: сообщения пользователя, ответы агента, комментарии, планы, команды, результаты, ошибки и изменения файлов. «Переписка» оставляет сообщения пользователя и итоговые либо старые ответы без `phase`; исключение хода работы прямо указано в собранном тексте. Структурированные вопросы `agentMessage.questions` сохраняются в обоих составах вместе с текстом сообщения, заголовками и строковыми вариантами, даже при пустом `text` и `phase:commentary`. В сообщение также входят агент-источник, название и ID беседы, рабочая папка. Исторические команды обозначены как запись уже прошедшей работы.

Полный текст доступен в редактируемом предпросмотре. До ручной правки изменение задачи или состава контекста автоматически пересобирает сообщение. После ручной правки поле сохраняет введённый вариант; кнопка «Обновить текст» явно заменяет его заново собранным сообщением из выбранной задачи и состава. В новую вкладку попадает именно текущий текст предпросмотра. «Создать черновик в Claude Code» / «Создать черновик в Codex» открывает вкладку с заполненным полем ввода: пользователь проверяет настройки, при необходимости добавляет файлы и отправляет сообщение обычной кнопкой чата. Подготовка и создание черновика не отправляют запрос модели. Отмена не создаёт вкладку; ошибка чтения или создания остаётся в окне с возможностью повторить действие.

Настройки принимающего агента берутся из его собственных сохранённых значений и CLI. Модель, глубина и доступ агента-источника между провайдерами не копируются. Исходные черновик и вложения остаются на месте; очередь при открытии передачи ставится на паузу и сохраняет свои записи, в том числе после отмены. Продолжить её можно вручную. Пока окно передачи открыто, очередь и автопинг не отправляют новые сообщения. Полученный черновик сохраняется обычным механизмом [рабочего места](WORKSPACE_STATE.md) и восстанавливается после перезапуска.

## Полнота истории и ограничения

`useCodex.readFullHistory()` читает отдельный снимок всей истории, сохраняя загруженные сообщения и позицию чтения исходного чата. Для paginated Codex последовательно вызывается `thread/items/list` с `limit:100`, `sortDirection:'desc'` и курсорами до конца; записи объединяются по `turnId:item.id`, затем разворачиваются в хронологический порядок. Legacy Codex и Claude читаются через `thread/read` с `includeTurns:true`. Вызовы чтения не запускают модель, повторный `thread/resume` для передачи не нужен.

Ошибка API, неполная запись, повторившийся курсор либо страница без новых идентификаторов при продолжающейся пагинации блокируют создание черновика. Передать лишь незаметно загруженный фрагмент нельзя. Чтение проверяет ID и жизненный цикл исходной беседы, готовность подключения, выполнение, авторизацию, терминал, неподтверждённую отправку и ожидающие запросы. Кнопка передачи недоступна во время работы. Если после открытия окна начинается новый ход, загрузка, авторизация, работа в терминале либо теряется подключение, окно закрывается; смена вкладки или исходного диалога также закрывает его. Для новой попытки история читается заново.

`MAX_AGENT_HANDOFF_CHARACTERS = 2_000_000` соответствует пределу текстового черновика и входа Claude; это количество символов JavaScript-строки, а не токены и не размер контекстного окна модели. Превышение блокирует создание, сохраняя полный текст в предпросмотре без обрезки. Можно явно выбрать «Переписка» или сократить текст вручную. Даже допустимое по этому пределу сообщение может превышать контекстное окно выбранной модели; её ответ об ошибке обрабатывается обычным путём отправки.

Вложения представлены именами, путями и доступными ссылками. Изображения, аудио и двоичные результаты инструментов, включая `imageGeneration.result`, MCP resource blobs и оба формата output content Codex, заменяются текстовыми маркерами. Bitmap/base64 в сообщение не встраиваются. Нужные изображения и другие двоичные файлы следует прикрепить в новой вкладке заново; это относится и к неотправленным вложениям исходного черновика. Обычные пути к файлам в тексте сохраняются, содержимое файлов автоматически не копируется.

Reasoning/thinking, `hookPrompt`, `encrypted_content`/`encryptedContent`, `redacted_thinking`, signatures и скрытые вложенные поля не передаются. Комментарии `agentMessage.phase='commentary'` сохраняются при выборе хода работы. Нельзя включать `reasoning.summary` как обычное пояснение: адаптер Claude записывает туда thinking. Используется явный набор публичных полей [экспорта беседы](EXPORT.md), а не сериализация исходных событий целиком. История заключена в Markdown fence длиннее встречающихся в её содержимом; инструкции продолжения полностью видны в предпросмотре и обычном пользовательском сообщении.

Полнота означает всё, что вернул существующий интерфейс истории. Нативное чтение Claude через SDK уже отказывает для истории свыше 128 МиБ / 100 000 сообщений. В существующем адаптере `claudeTaskItem.summary` ранее ограничен 100 000 символами; передача не восстанавливает отброшенный до неё хвост. Это ограничение источника, а не дополнительная обрезка при передаче. Авторизация, конфигурация CLI и внутренние SQLite-базы не изменяются.

## Код и проверки

- `src/agent-handoff.ts` — сборка текста, фильтрация публичных полей, маркеры вложений, лимит и причины блокировки.
- `src/AgentHandoff.tsx`, `src/agent-handoff.css` — окно, выбор состава, редактирование и пересборка, ошибки и создание черновика.
- `src/useCodex.ts` — полное чтение; `src/App.tsx` — доступность действия и пауза очереди; `src/Workspace.tsx` — отдельная вкладка принимающего агента.

`node --test tests/agent-handoff.test.mjs` проверяет сохранение задачи, ограничений, порядка и результатов, оба направления, исключение reasoning/скрытых полей, типы вложений, выбор состава, блокировки неполной/активной истории, полный хвост текста сверх лимита и устойчивые Markdown fences. Девять тестов прошли, включая структурированные вопросы в обоих составах; вместе с `tests/conversation-export.test.mjs` проверено сохранение прежнего экспорта. TypeScript-проверка также прошла.

`node scripts/ui-agent-handoff.mjs` прошёл на production renderer с подставным bridge: обе стороны, полная paginated/legacy история, состав и ручная правка, отмена, повтор после ошибки чтения/создания, повтор курсора, отдельные настройки провайдеров, сохранение исходного состояния и нового черновика после перезапуска. Отправка проверяется одним явным `turn/start` после обычной кнопки чата. Реальных запросов модели нет. Скриншот: `artifacts/agent-handoff-drafts.png`.
