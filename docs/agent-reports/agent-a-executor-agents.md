# Агенты-исполнители вместо «сабдиалогов»

Дата: 2026-10-10. Коммиты и публикации не выполнялись.

## Что сделано

**1. Создание без fork.** Исполнитель — обычный новый пустой диалог той же папки:
`open(cwd, undefined, provider, undefined, { childOf: parentThreadId, childLabel })`.
Удалены модалка выбора модели/глубины (`child-model-dialog`), событие
`codex-desk:create-child` и fork-путь создания сабдиалога (`createChildThread`,
параметр `child` у `forkThread`). Сам `thread/fork` функции «Ответвить» не тронут:
`forkThread` по-прежнему передаёт `fork: { lastTurnId }`, а `useCodex.resume`
не изменён вовсе. Модель и глубину пользователь выбирает в композере исполнителя.
Провайдер наследуется от родителя.

**2. Три точки входа.**
- Кнопка на активной вкладке родителя: `CornerDownRight` 12px заменён на `Bot` 15px,
  кнопка получила рамку и фон, подпись «Новый агент-исполнитель». Блокировка оставлена
  только по `opening`/`actionBusy`: занятость/ожидание родителя больше не блокируют,
  потому что чистый диалог его не трогает.
- «+ Исполнитель» в конце ряда — стиль `.child-tab-create` был написан, но не отрисован;
  теперь отрисован и показывается только у родителя.
- Команда палитры Ctrl+K «Новый агент-исполнитель» (`data-command-id="executor"`),
  отключена у исполнителя с пояснением «У агента-исполнителя своих исполнителей нет».

**3. Терминология.** «Агент-исполнитель», caption ряда — «Исполнители», счётчик в дереве —
«N агентов-исполнителей» с русскими числительными. Слова «сабдиалог» в пользовательских
строках не осталось (проверяется прогоном по `document.body.innerHTML`).

**4. Имена по умолчанию.** «Агент A», «Агент B», … — следующая свободная латинская буква
среди исполнителей этого родителя, по связям и открытым вкладкам. Логика вынесена в
`src/executor-agents.ts` (чистая, без React и IPC): после Z идёт AA, освободившаяся буква
переиспользуется, произвольное название буквы не занимает, регистр не важен.
До первой отправки имя живёт подписью вкладки; получив `threadId`, оболочка записывает его
названием диалога через существующий `manageThread` `rename` и в новое поле `label` связи.
**Важно:** `ThreadManagement.assertIdle` отклоняет rename работающего диалога, поэтому
переименование выполняется при первом отчёте, где исполнитель уже освободился, а при ошибке
отметка снимается и попытка повторяется. Имя при этом уже сохранено в `label`, поэтому ряд
подписан правильно даже если rename не прошёл.

**5. Ряд «Исполнители».** Текст 11px (было 9–10px), высота ряда 38px, вкладки 28px, цвета по
`Kuzmich_Design_System.md`: фон `#171A19` (bg-primary), разделитель `#3A413D` (border-subtle),
активный `#303A34` (bg-surface-muted) с подчёркиванием `#9BB6A4`, значки `#82968A`/`#9BB6A4`,
текст `#AAB4AD`/`#D5E0D8`. Оранжевых акцентов и свечений нет. Ряд виден у родителя и у
открытого исполнителя, активный подсвечен; на ширине ≤700px у кнопки «+» остаётся только значок.

**6. Глубина строго 1.** У исполнителя нет ни кнопки на вкладке (его вкладки нет в основном
ряду), ни «+» в ряду, ни активной команды палитры.

**7. Восстановление.** Ряд собирается `childThreadsFor` из `childLinks` (`loadThreadChildLinks`
читает `thread-child-links.json` для каждой зарегистрированной папки) плюс открытые вкладки.
Вкладка, ещё не получившая `threadId`, раньше просто исчезала из интерфейса — теперь она
представлена записью с `sessionId` и выбирается обратно по сессии. Поэтому `App` получил проп
`executorOf`: исполнитель знает своего родителя до первой отправки.

## Что проверяет renderer-прогон

`scripts/ui-executor-agents.mjs` — production renderer в Edge с подставным scoped bridge,
без Electron IPC и без запросов модели:

- исполнитель не отправляет ни `thread/fork`, ни `thread/resume`; транскрипт родителя в нём
  отсутствует;
- кнопка на вкладке активна при работающем родителе, значок ≥14px;
- исполнители не попадают в основной ряд вкладок; caption «Исполнители»; размер шрифта ряда ≥11px;
- у исполнителя нет «+», команда палитры отключена; у родителя обе доступны;
- «Агент A» → «Агент B» → «Агент C» по трём точкам входа; имя записано и в `label` связи,
  и названием диалога через `rename`;
- повторный клик по открытому исполнителю активирует его вкладку, а не открывает копию;
- после перезагрузки ряд собирается из связей; исполнитель, ничего не отправивший, не
  восстанавливается и не выдумывается; счётчик в дереве показывает 2;
- в `document.body.innerHTML` нет слова «сабдиалог».

## Известные ограничения

- Вкладку исполнителя нельзя закрыть мышью: в основном ряду её нет, а в ряду «Исполнители»
  крестика не предусмотрено. Закрытие доступно командой палитры «Закрыть текущую вкладку».
  Отдельная кнопка закрытия в ряду не добавлялась — это за пределами задачи.
- Переименование в «Агент A» выполняется, только когда исполнитель освободился. Если первый
  ход завершился ошибкой и диалог остался занятым, название останется прежним, а подпись в
  ряду возьмётся из `label`.
- Если пользователь переименует исполнителя вручную, его буква всё равно считается занятой:
  она записана в `label` связи. Это сознательно — иначе следующий исполнитель получил бы
  букву, которая уже была выдана.
- Прогон выполнен на подставном bridge. Живого запуска с настоящими Codex/Claude CLI и
  реальными запросами модели в этой работе не было.
