### Контекст и диагностика (уже выполнена, перепроверь якоря)

- Ряд «Исполнители» рендерится в `src/App.tsx:703-719`; крестик подвкладки — `src/App.tsx:716`, рисуется **только** при `child.sessionId` (то есть только для открытой вкладки). Записи ряда, собранные из сохранённых связей `thread-child-links.json` без открытой вкладки (`childThreadsFor`, `src/Workspace.tsx:839-854`), крестика не имеют вовсе.
- Закрытие вкладки **не** удаляет связь родитель→потомок, поэтому после закрытия запись «Агент A» остаётся в ряду уже без крестика — это главная причина жалобы «крестик не работает». Это поведение задумано (ряд переживает перезагрузку), менять хранение связей не нужно — нужен честный UX.
- Путь закрытия: `executorAction('close')` → `requestClose` (`src/Workspace.tsx:705-710`): при `terminalOpen` — молчаливый выход; при `busy || loading || pending` — модалка «Закрыть работающий диалог?» (`Workspace.tsx:1118-1121`); `close()` (`Workspace.tsx:646-669`) молча выходит при `closingTab/actionPending/pendingOpen`.
- После «Стоп» флага «останавливается» нет; `busy` сбрасывается только по `turn/completed` (`src/useCodex.ts:529-534`, остановка — `useCodex.ts:1231-1254`).
- Верхний ряд вкладок: `src/Workspace.tsx:1025-1058`, вкладки с `childOf` отфильтрованы (`:1027`), поэтому при активной подвкладке **ни одна** вкладка верхнего ряда не подсвечена. Родитель виден только в хлебных крошках (`src/App.tsx:680, 720`).
- Индикаторы верхних вкладок (образец для переноса): спиннер вместо иконки при `busy`, точка `.tab-state` (`waiting` > `running` > `error`), точка непрочитанного `.tab-unread` — `src/Workspace.tsx:1046-1050`, стили `src/styles.css`, `src/notifications.css:34-35`, тема `src/kuzmich-theme-colors.css:921-929`.
- Модель состояний уже существует: `SessionSummary {busy, pending, pendingDelivery, connection, loading, terminalOpen}` (`src/App.tsx:65`, репорт `:326-335`) и attention-события `'question' | 'approval' | 'completed' | 'error'` (`src/useCodex.ts:458-460`, хранение `src/Workspace.tsx:86, 184-189`). Но `childThreadsFor` (`Workspace.tsx:848`) читает `summariesRef` и выбрасывает `busy/pending` — для индикаторов на подвкладках эти поля нужно пробросить.
- `src/child-tabs.css` — hardcoded hex без вариантов `[data-theme=kuzmich]`; новые стили делай по `Kuzmich_Design_System.md` и добавь тему, как у `.session-tab`.

### Задача 1. Крестик подвкладки: честное закрытие

Решение владельца: у работающего исполнителя крестик открывает диалог с **двумя** действиями.

1. **«Остановить и закрыть»** — текущее поведение модалки: прервать ход и закрыть вкладку.
2. **«Дождаться и закрыть»** — отложенное закрытие: вкладка помечается «закроется по завершении» и закрывается автоматически, когда ход завершился (`turn/completed`, любой итог). Если агент по пути задал вопрос или запросил разрешение (`pending > 0`), автозакрытие **не** срабатывает: вкладка остаётся, показывает индикатор «ждёт ответа» (задача 3) и попадает в колокольчик — молча закрывать диалог с неотвеченным вопросом нельзя. Пометка живёт в памяти приложения; потерю пометки при перезапуске явно задокументируй. Пометку видно на подвкладке (например, приглушённый крестик-таймер с подсказкой «Закроется по завершении»), повторный клик по крестику предлагает отменить отложенное закрытие или остановить сразу.

Дополнительно в рамках той же задачи:

3. **Записи ряда без открытой вкладки** (только из связи, без `sessionId`) получают свой крестик со смыслом «Убрать из ряда» — то же действие, что пункт меню «Отвязать от родителя» (`ThreadChildLinkStore.manage({action:'unlink'})`), с его же блокировками. Подсказка крестика должна отличаться: «Убрать из ряда (диалог останется в папке)».
4. **Никаких молчаливых отказов.** Каждая ветка, где закрытие невозможно (`terminalOpen`, `closingTab`, `actionPending`, `updateWaiting` и т.п.), даёт видимую причину: подсказка на задизейбленном крестике (как у верхнего ряда: «Сначала закройте терминал этого диалога») или сообщение. Сними лишний дизейбл крестика подвкладки на `preparingUpdate/savingBeforeClose/updateWaiting`, если верхний крестик в этих состояниях работает — поведение двух крестиков должно совпадать.

Приёмка: сценарий «создал исполнителя → отправил задачу → Стоп → крестик» закрывает вкладку максимум за два понятных клика и не оставляет в ряду безымянного призрака без крестика; «Дождаться и закрыть» закрывает вкладку после реального завершения хода; ни один клик по активному крестику не заканчивается «ничем».

### Задача 2. Подсветка родительской вкладки

Когда активна подвкладка исполнителя:

1. Родительская вкладка в верхнем ряду получает состояние «полуактивна»: фон активной вкладки, но акцентная полоска мягче/другого оттенка, чем у `.session-tab.active` (сейчас `inset 0 2px #afd1bd`, тема Кузьмича `#a4bdaf`). Новый класс вида `child-active`; цвета — из палитры дизайн-системы, с вариантом для `[data-theme=kuzmich]`.
2. На родительской вкладке появляется маленькая метка открытого исполнителя: иконка `Bot` + короткое имя («A» от «Агент A», иначе первые символы имени). Метка декоративная (`aria-hidden`), доступное имя вкладки дополняется текстом вида «, открыт исполнитель Агент A».
3. Клик по полуактивной родительской вкладке переключает на родителя — существующее поведение, не менять.

Приёмка: при активной подвкладке в верхнем ряду всегда ровно одна визуально выделенная вкладка (родитель, стиль отличим от полностью активной); скриншоты обоих состояний в артефактах.

### Задача 3. Индикаторы состояния исполнителей

1. Проброс данных: `childThreadsFor` (`src/Workspace.tsx:839-854`) дополнительно отдаёт `busy`, `pending`, `loading`, `connection`, `terminalOpen` из `summariesRef` и признак непрочитанного из `attention` по `sessionId`. Записи без открытой вкладки живого статуса не имеют — для них отдельное состояние «вкладка закрыта».
2. На подвкладке — те же индикаторы, что у верхних вкладок: спиннер вместо иконки `Bot` при `busy`; точка состояния с приоритетом `waiting` (жёлтая) > `running` (зелёная) > `error` (красная); точка непрочитанного по attention. Для записи «вкладка закрыта» — серая точка и подсказка.
3. Различение вопроса и разрешения: если последнее attention/ожидание — `'question'`, вместо жёлтой точки показывается значок «?» (бейдж). `'approval'` остаётся жёлтой точкой. Эту разницу добавь только на подвкладках исполнителей; верхний ряд не трогай без необходимости.
4. Сводный сигнал на родителе: если хоть один исполнитель родителя `pending > 0` или имеет непрочитанный вопрос, родительская вкладка в верхнем ряду получает жёлтую метку (совмести с меткой из задачи 2, не плодя третий значок). Подсказка перечисляет, кто именно ждёт: «Агент A ждёт ответа».
5. Подсказка подвкладки при наведении показывает слово-статус: «Работает» / «Ждёт вашего ответа» / «Готов» / «Ошибка подключения» / «Вкладка закрыта» — те же формулировки, что в подсказках верхнего ряда, где применимо.

Приёмка: во время реального хода исполнителя на его подвкладке виден спиннер; вопрос агента даёт «?» на подвкладке и жёлтую метку на родителе из любой другой вкладки; после завершения в фоне — точка непрочитанного.
