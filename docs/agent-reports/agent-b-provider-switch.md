# Agent B — смена агента в текущей вкладке (пустой диалог)

Дата: 2026-10-10. Коммиты и публикации не делались.

## Что сделано

В пустом диалоге (ни одного сообщения) селектор «Агент» больше не открывает новую вкладку: вкладка
переключается на месте. Диалог с сообщениями по-прежнему принадлежит своему агенту — для другого агента
открывается отдельная вкладка с прежним текстом отказа.

### 1. Хост: `electron/window-session.mjs`

- `setSettings` при смене `provider` вызывает новый `_startProviderSwitch` вместо безусловной ошибки.
  Проверка источника подключения перенесена выше, чтобы некорректный `connectionSource` отвергался всегда.
- `_startProviderSwitch` разрешает смену только когда `currentThreadId == null` и внедрён `providerDefaults`;
  иначе — прежняя ошибка «Смена агента открывает отдельный диалог.». При занятости
  (`pendingBoots/pendingMutations/requests/activeThreadTurns/compactingThreads`) — «Дождитесь завершения работы
  и подтверждений перед сменой агента.». Терминал и вход в Claude отсекает прежний `assertLocalControl`.
- Настройки нового агента берутся из `settingsStore.snapshotProvider(provider)` (инжектируется как
  `providerDefaults`): модель, усилие, доступ и источник — его собственные, от прежнего агента не переносится
  ничего; сохраняется только рабочая папка. Полный доступ в Claude понижается до «Разрешать правки» — так же,
  как при создании новой вкладки Claude.
- Общий конвейер: `_switchConnectionSource` и смена агента используют один `_switchRunningClient`
  (валидация профиля → `stopAndWait` → сохранение → подмена `settings`/`preparedConnectionProfile`),
  с прежними флагом `switchingSource`, проверками `generation` и статусом ошибки при неудаче после отключения
  процесса. У смены агента текст статуса свой: «Не удалось сменить агента. Переподключите диалог и повторите.»
- Смена агента ничего не пишет в настройки: значения только что прочитаны из хранилища, а папку сохраняет
  ближайший `_boot` — уже в профиль нового агента.

### 2. Грабля с `persistSettings` (`electron/main.mjs`)

`addSession` сохранял патчи в профиль, захваченный замыканием при создании сессии. Теперь профиль читается
в момент сохранения: `settingsStore.updateProvider(session.settings.provider || 'codex', patch)`. Setup-пути
не затронуты: другие `new WindowSession` (мастер настройки, история) собственный `persistSettings` не имеют.

### 3. Renderer

- `src/useCodex.ts` — новый `selectProvider(value)`: ждёт завершения текущего подключения вкладки, проверяет,
  что диалога/очереди/запросов нет, вызывает `bridge.setSettings({ provider })` и переподключается
  (`connect(..., { refreshModels: true })`) по образцу `selectConnectionSource`. Возвращает, произошла ли смена.
  Отказ хоста — не ошибка: вызывающий открывает отдельную вкладку, как раньше. Ошибка запуска нового агента
  остаётся в этой вкладке.
- `src/App.tsx` — `selectProvider` выбирает путь по состоянию вкладки (`thread`, `pendingMessage`, очередь,
  запросы, `sending`, редактирование) и обновляет подсказку композера; иначе прежний `workspace.newChat`.
  Селектор «Агент» дополнительно заблокирован во время смены и подключения.
- Подпись в настройках: «В пустом диалоге агент меняется на месте; в диалоге с сообщениями другой агент
  откроется в отдельной вкладке.»
- `report` теперь всегда передаёт провайдера (раньше — только Claude), иначе вкладка после смены
  Claude → Codex сохраняла значок и summary прежнего агента. Проверено: без этой правки новая UI-проверка падает.

Возможности, каталог моделей, модель/усилие/доступ, история, лимиты плана и плейсхолдер меняются сами —
их пересобирает `connect()`.

### 4. Кузьмич (routerOnly)

`connectionSource` остаётся `router`: `cleanSettings(..., routerOnly)` принудительно ставит router и в
`snapshotProvider`, и в подготовленных настройках. Если Claude не подключён к роутеру,
`buildClaudeConnectionProfile` бросает «Подключите Claude к роутеру в настройках.» на этапе валидации — до
остановки процесса, поэтому вкладка остаётся на Codex и рабочей, а renderer открывает вкладку Claude с той же
самой ошибкой (источник ошибки один и тот же). Вернуться к Codex можно прямо в этой пустой вкладке.
Проверено по коду; отдельный прогон Кузьмича в этой сессии не делался.

## Замеченное попутно

- При очень быстром клике сразу после готовности вкладки хост мог ответить «Дождитесь завершения работы…»:
  сразу за первым подключением вкладка успевает начать ещё одно (повторный запуск эффекта renderer’а).
  Лечится ожиданием завершения подключения в `selectProvider`; именно из-за этого реальный хост-тест сначала
  открывал новую вкладку вместо смены на месте.
- Остаточный край: если диалог был сброшен в renderer без переподключения (например, выбор доступа
  «Настройки CLI» после отправки сообщения), хост всё ещё помнит `currentThreadId`, отказывает — и вкладка
  открывается новая. Поведение совпадает с прежним, данные не теряются.
- `docs/CLAUDE.md` в рабочем дереве хранится в двойной кодировке (мохибейк), поэтому документацию по агентам
  не трогал — правка там испортила бы файл ещё сильнее.
