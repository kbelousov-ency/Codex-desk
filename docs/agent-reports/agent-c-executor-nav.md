Ниже — только то, что доделал я.

## 1. Кнопка «Отправить агенту»

Логика уже работала, я её не переписывал. Проверил и зафиксировал прогоном: кнопка стоит рядом с
«Копировать» в `markdown-code-header`, переносит текст блока черновиком через `open(..., { draft })`,
активирует вкладку нового исполнителя и **ничего не отправляет** — у новой сессии в транскрипте
запросов нет ни `turn/start`, ни `thread/fork`, ни `thread/resume`.

Границы видимости: нет в архиве (`ArchiveView` не передаёт проп), нет у исполнителя (глубина 1),
нет на сообщениях пользователя, нет в неактивной вкладке. Проброс — пропом, глобального состояния
не добавлялось.

## 2. Хлебные крошки исполнителя

`src/App.tsx`: между папкой и заголовком появляется кнопка `.breadcrumb-parent` с именем родителя.
Имя даёт новый контрол `threadTitle(threadId, cwd)` — имена из `manageThread`, загруженная история
папки, заголовок открытой вкладки. Клик (`openParentThread`) активирует вкладку родителя, если она
открыта; иначе открывает диалог заново обычным путём. `thread/fork` не запрашивается, связи не
трогаются. У родителя крошки прежние.

## 3. Контекстное меню подвкладки

Новый `src/ExecutorTabMenu.tsx` — портал, стрелки/Home/End/Escape, фокус на первый доступный пункт.
Открывается ПКМ и с клавиатуры (`ContextMenu`, `Shift+F10`). Блокировки те же, что в `ThreadMenu`:
`opening || actionBusy || threadLocked(threadId)`.

| Пункт | Что делает |
| --- | --- |
| Переименовать | обычный `manageThread` `rename` + запись имени в `label` связи |
| Отвязать от родителя | удаление записи связи и только её; `manageThread` не вызывается |
| В архив | обычный архив; связь при этом удаляется |
| Закрыть вкладку | единственный доступный пункт у исполнителя без диалога |

Исполнитель, который ещё ничего не отправил, адресуется по `sessionId` и диалога не имеет — поэтому
первые три пункта у него отключены, а не делают вид, что работают.

**Решение по архиву, о котором стоит знать:** архивируя исполнителя, я удаляю и его связь. Иначе ряд
«Исполнители» показывал бы безымянную строку диалога, которого в папке уже нет. Цена — восстановленный
из архива диалог возвращается обычным, а не исполнителем. Выбрал предсказуемость интерфейса.

## 4. Дерево проекта

Исполнитель — обычный диалог той же папки, поэтому приходит той же страницей истории, что и родитель.
Переписал рендер: страница дедуплицируется по `id`, исполнители вкладываются под родителя с отступом и
направляющей (`.folder-thread-children`), раскрытость — по ключу `projectKey|parentId`.

Детей раскрывает **бейдж-счётчик** у родителя: по требованию владельца это он, а не отдельная
стрелка. Чтобы разметка осталась валидной, бейдж вынесен из кнопки строки в саму строку и стал
кнопкой с `aria-expanded` и подписью «Развернуть N агентов-исполнителей диалога …». Из-за этого
поправлен один селектор в `scripts/ui-executor-agents.mjs` (бейдж теперь сосед, а не потомок
`.folder-thread`); смысл проверки прежний, счётчик по-прежнему показывает 2.

Исполнитель, родителя которого нет на загруженной странице, остаётся в плоском списке — из дерева
ничего не пропадает молча. В режиме множественного выбора список плоский, область выбора прежняя:
загруженная история папки (вернул туда исполнителей, предыдущая правка их исключала).

## 5. Отвязка, архив, удаление

- Хранилище: `ThreadChildLinkStore.manage({ action: 'unlink' | 'relabel' })`, IPC
  `host:manageThreadChildLink` (добавлен и в список каналов, запрещённых во время настройки агента).
- Локальная копия связей чистится вместе с вызовом хоста, поэтому отвязанный, заархивированный и
  удалённый исполнитель исчезает из ряда и из дерева сразу, без перечитывания папки.
- Отвязанная вкладка теряет `childOf` и возвращается в основной ряд вкладок.
- Существующее предупреждение при удалении родителя не изменялось.

## Что проверяет renderer-прогон

`scripts/ui-executor-nav.mjs` — production renderer в Edge с подставным scoped bridge, без Electron
IPC и без запросов модели:

- в header промт-блока ровно две кнопки, в порядке «Отправить агенту», «Копировать»;
- клик создаёт исполнителя, промт приходит черновиком композера, запросов к модели нет, кнопки
  «Остановить выполнение» нет — автоотправки не происходит;
- у сообщения пользователя промт-блока нет;
- в ответе самого исполнителя блок рисуется, а кнопки нет — глубина 1;
- крошка исполнителя показывает «Диалог 1» и активирует вкладку родителя без повторного `resume`;
  у родителя крошки родителя нет;
- меню подвкладки: четыре пункта в заданном порядке; у исполнителя без диалога доступно только
  «Закрыть вкладку», остальные отключены; закрытие убирает вкладку, ряд остаётся верным;
- дерево: исполнители не лежат плоско рядом с родителем, бейдж «2» с `aria-expanded=false` и
  подписью «Развернуть 2 агента-исполнителя диалога Диалог 1», клик раскрывает и сворачивает,
  дети с отступом;
- переименование меняет подпись в ряду, строку в дереве и `label` связи;
- отвязка убирает исполнителя из ряда и из вложенности, делает его корневой вкладкой, счётчик
  становится «1», и за всю работу не было ни одного `manageThread`, кроме переименований;
- архив убирает ряд и счётчик и не оставляет связи;
- архивный просмотр рисует промт-блок с «Копировать», но без «Отправить агенту».

## Известные ограничения

- Архивирование исполнителя удаляет связь безвозвратно (см. решение выше): восстановленный диалог
  возвращается обычным.
- Крошка родителя показывает «Родительский диалог», если родителя нет ни среди открытых вкладок, ни
  на загруженной странице истории папки. Имя подтягивается, как только папка раскрыта.
- Прогон выполнен на подставном bridge. Живого запуска с настоящими Codex/Claude CLI и реальными
  запросами модели в этой работе не было.
