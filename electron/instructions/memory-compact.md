# Сжатие проектной памяти без потери знаний

Сжать свою проектную память: индекс и тяжёлые заметки. Ничего не терять, резать только объём. Эти правила применяются при работе с памятью; полную компакцию не нужно запускать автоматически в каждой сессии.

Память растёт при дописывании. Держи постоянно загружаемый индекс кратким, тела заметок читай выборочно. В исходном примере постоянно загружаемый `MEMORY.md` разросся до 6–8 тысяч токенов до первой строки задачи; это пример стоимости контекста, а не обещание, что любой агент автоматически загружает любой `MEMORY.md`. В Codex используй реальные инструкции и документацию проекта; не меняй внутренние SQLite-базы памяти.

## Правило номер один

**Не удаляй заметки и не выбрасывай записи из индекса.** «Мёртвое» по тексту определить нельзя: слова «ПОХОРОНЕН», «ЗАКРЫТ», «заменено» описывают принятое решение, а не состояние кода. Проверка на реальном примере исходной инструкции: индекс уверял, что god-object распилен — файл вырос с 1685 до 2306 строк; уверял, что Trello вытеснена — в коде 977 упоминаний в 101 файле. Три догадки подряд оказались неверны. Эти числа — сохранённый пример, а не утверждение о текущем проекте.

Если всё же считаешь запись мёртвой — **сначала сверься с кодом**: поиск по упомянутым идентификаторам (`rg`, `Grep`), чтение файла (`Read`), `git log` по коммиту. Не подтвердилось — оставляй и сжимай как остальное.

## Шаги

### 1. Найти свою память

Сначала установи фактическое расположение памяти или документации проекта и её индекса. Для Codex не считай `MEMORY.md` автоматически загружаемым индексом и не используй Claude-пути по умолчанию: проверь инструкции текущего проекта и существующие файлы. Подходящей проектной памяти нет — скажи об этом и закончи, не создавая вымышленной памяти.

Для Claude Code каталог автоматической памяти обычно находится в `~/.claude/projects/<slug>/memory`; при заданном `CLAUDE_CONFIG_DIR` проверяй соответствующий фактический каталог. Точный slug установи по существующим каталогам, не полагайся только на вычисление. Исходный пример поиска для стандартного каталога использует путь текущей папки, где `:`, `\` и `/` заменены на `-`. Литерал обратного слэша в однострочнике не пиши — он рвётся в шелле, бери `chr(92)`:

```
python -c "import os;cwd=os.getcwd();s=''.join('-' if c in ':/'+chr(92) else c for c in cwd);d=os.path.expanduser('~/.claude/projects/')+s+'/memory';print(s,d,os.path.isdir(d))"
```

Не нашлось — ищи по имени репы среди фактических `projects/*/memory`. Памяти нет вообще — скажи об этом и закончи.

В исходном окружении у `~/.claude-acct-*` каталог `projects` был junction на ту же папку: это ОДНА память, видимая по двум путям, а не две. В текущем окружении сначала проверь разрешённые пути/junction; одну и ту же память обрабатывай один раз.

### 2. Снять мерку и сделать копию

Скопируй папку памяти рядом в `memory.bak-<ГГГГММДД>` (например, `projects/<slug>/memory.bak-<ГГГГММДД>` для Claude Code), не во временный каталог — его могут чистить между вызовами. Существующую копию не затирай: добавь время или уникальный суффикс. Затем посчитай: размер индекса (`MEMORY.md`, если он используется), число заметок, размеры тел по убыванию, накопленный процент, файлы без строки в индексе и строки индекса без файла.

Ориентир: строка индекса длиннее ~150 символов и медиана тел больше ~4 КБ — работа нужна. В исходном наблюдении половина всех байт обычно лежала в первых 10–16 заметках; проверь распределение в текущей памяти.

### 3. Переписать индекс

Каждая запись остаётся, включая осиротевшие файлы — им строку **добавить**. Цель: ≤110 символов на строку, где это возможно без потери смысла.

Вынеси статусы в метки, легендой одной строкой сверху:

```
Метки: ⛔ не задеплоено · 🔨 не построено · ✖ отменено · ⚠ грабли
```

Убери из индекса: избыточные хеши коммитов (их держит git), даты, если не несут смысла, номера тестовых прогонов, повторы вроде «НЕ закоммичено/нужен рестарт» в каждой второй строке. Нужные для поиска, решения или ссылки хеши и даты сохрани в тематической заметке.
Сохрани: ⚠-грабли, имена компонентов и идентификаторы в точном написании, ссылки на файлы.

```
БЫЛО:  - [Token economics / ledger](x.md) — EconomicsService+spend.jsonl (!spend, дашборды); срезка
       queryable через record_strip. ⚠️ total_cost_usd = кумулятив ⇒ старые $ ×2.9; починено 28.08,
       историю чинить tools/repair_cumulative_spend.py --apply. Компакт: 🪙 0 в футере, реально $0.4–0.85.
СТАЛО: - [Token economics](x.md) — леджер+!spend; ⚠ total_cost_usd кумулятив, чинить repair_cumulative_spend.py
```

Это пример сокращения строки индекса: факты `×2.9`, `$0.4–0.85`, `EconomicsService`, `spend.jsonl`, `record_strip` и точную команду `tools/repair_cumulative_spend.py --apply` сохрани в заметке, если они относятся к памяти проекта. Пример не является указанием запускать эту команду.

### 4. Сжать тяжёлый хвост тел

Иди по размеру сверху вниз, пока не наберёшь ~половину всех байт. Остальные не трогай без необходимости.

Крупная заметка часто оказывается журналом сборки: два десятка абзацев «коммит X, TDD, сетка 1174, НЕ закоммичено, нужен рестарт». Это материал для сокращения, если в нём нет самостоятельного знания.

**Сохраняй:**
- решения и почему они приняты, особенно «решили НЕ делать, потому что…» — их переигрывают чаще всего;
- ⚠-грабли целиком: чем дороже далась находка, тем дословнее;
- имена модулей, ключи конфига, id, скоупы, пороги, регулярки;
- утверждения, подтверждённые замером или живой пробой.

**Убирай повторы и лишний объём:**
- хронику по коммитам и счётчики тестов;
- пересказ того, как шло обсуждение с человеком;
- промежуточные состояния, отменённые следующим абзацем, сохраняя причины решений и отвергнутых подходов;
- то, что и так читается из кода: структуру пакета, списки файлов, сигнатуры, если это не нужно для сохранения решения или ограничения.

Язык заметки не меняй: русскую оставляй русской, английскую английской. Идентификаторы — в точном написании. `[[ссылки]]` сохраняй и добавляй недостающие.

Остановись, когда очередная заметка жмётся меньше чем на треть, — значит пошли плотные живые факты.

### 5. Проверить целостность

Сверь все заметки на диске со ссылками в индексе; битых ссылок, дублей и осиротевших заметок быть не должно. В простой схеме одна заметка — одна запись число заметок равно числу ссылок; при иной схеме проверь покрытие, не удаляя нужные записи ради равенства. Отдельно проверь, что все `[[имена]]` в телах разрешаются в существующие файлы. Намеренная ссылка на будущую заметку — метка «написать потом», а не ошибка; сохраняй её узнаваемой, новых случайных оборванных ссылок не создавай.

Только после успешной проверки целостности можно удалить созданную для этой задачи копию из шага 2. Не удаляй чужие или старые резервные копии.

### 6. Отчитаться

Коротко и числами: индекс было/стало в символах, байтах и токенах; сколько заметок сжато и на сколько процентов; что сохранено дословно; какие утверждения проверял по коду и что нашёл. Измеренные токены отделяй от оценок: если подходящий токенизатор не использовался, прямо назови число оценкой. Если нашёл расхождение памяти с кодом — назови его отдельной строкой.
