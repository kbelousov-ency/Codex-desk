# Постоянные правила ведения проектной памяти

Применяй эти принципы при создании, обновлении и сжатии проектной памяти:
- Держи постоянно загружаемый индекс кратким, подробности — в отдельных заметках; читай их по необходимости. Не запускай полную компакцию автоматически в каждой сессии.
- Не удаляй заметки или записи индекса из-за статуса «устарело», «закрыто», «отменено», «заменено». Сохраняй решения и причины, отвергнутые подходы, грабли, измеренные факты, точные идентификаторы, ключи конфигурации, области действия, пороги и ссылки.
- Проверяй устаревание по коду, содержимому файлов и git history. Неподтверждённую запись сохраняй и сжимай. О расхождениях памяти с кодом сообщай явно.
- Перед массовым сжатием прочитай полную процедуру по пути ниже; создай рядом датированную резервную копию и измерь индекс, заметки и покрытие ссылками.
- По возможности держи записи индекса не длиннее 110 символов. Сохраняй каждую запись и добавляй отсутствующие для осиротевших заметок. Начинай с самых больших заметок, убирай повторы и лишнюю хронологию, сохраняя знания.
- Сохраняй язык каждой заметки, точные идентификаторы, файловые ссылки и wiki-ссылки. Проверяй дубли, осиротевшие заметки и ссылки; не создавай новых оборванных ссылок, распознавай намеренные ссылки на будущие заметки.
- До удаления созданной для этой задачи резервной копии проверь целостность. Отчитайся о размерах до/после; отделяй измеренные токены от оценок.
