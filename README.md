# Codex Desk

Локальное Windows-приложение для установленного Codex CLI. Выбор проекта, чат с картинками, модель и глубина рассуждений, режим доступа, потоковые пояснения, команды и изменения файлов.

Поддерживается также **Claude Code CLI**. В поле **«Агент»** выберите Codex или Claude Code: откроется отдельная вкладка в текущей папке, прежний диалог и черновик останутся на месте. У каждого агента свои модель, глубина и настройки. Claude должен быть установлен и авторизован; используются его текущие настройки и подключения. Подробнее — [Claude Code](docs/CLAUDE.md).

Claude поддерживает чат, изображения и файлы, очередь, инструменты, вопросы/разрешения, остановку, нативную историю и продолжение в терминале. Уточнение выполняющейся задачи и кнопка сжатия для Claude пока недоступны — используйте очередь или терминал. Архив и поиск названий в левой панели пока относятся к Codex. «Разрешать правки» у Claude означает его режим acceptEdits; это отличается от автоматической проверки разрешений Codex.

## Запуск

Для установки на другой компьютер передайте **`Codex Desk Setup 0.1.0.exe`** из `release/installer`. Получателю достаточно запустить этот файл: программа установится без прав администратора, создаст ярлыки и откроется. Node.js и исходники не нужны. Для работы с моделью на компьютере должен быть установлен и настроен Codex CLI; личная авторизация и корпоративные настройки в установщик не входят.

Дважды нажмите **Codex Desk.lnk** или **Start Codex Desk.vbs** для проверенной Release. Для новых функций и проверки исправлений используйте **Codex Desk Nightly.lnk** или **Start Codex Desk Nightly.vbs**. Бейдж рядом с логотипом показывает канал; версия, номер и дата сборки доступны при наведении и в «Диагностике».

Постоянные папки: `release/stable` и `release/nightly`. Для передачи коллегам копируйте **всю папку stable**, а не только `.exe`. Новая Nightly не заменяет Release до проверки и подтверждения. Хранится не более одной предыдущей Release для отката.

**Nightly спрашивает перед закрытием:** после `npm run package` над полем сообщения появляется уведомление с кнопками **«Закрыть»** и **«Отмена»**. «Закрыть» дожидается завершения задач, сохраняет вкладки и черновики с изображениями, применяет сборку и открывает приложение снова. «Отмена» оставляет приложение работать; обновление применится после вашего ручного закрытия, без автоматического запуска. Если в открытой старой версии ещё нет такого уведомления, для первого перехода закройте её вручную. Для обновления Release его окно по-прежнему нужно закрыть.

Настройки оболочки и журналы Release/Nightly разделены. При первом запуске Nightly получает копию списка проектов и настроек Release. Авторизация, история, MCP и конфигурация установленного Codex остаются общими. Не открывайте одну беседу одновременно для записи в обоих каналах.

Приложение ищет Codex в PATH и в расширении OpenAI для VS Code. Если не найдёт, можно выбрать `codex.exe` в интерфейсе. Используются существующие авторизация, провайдер, конфигурация Codex и инструкции проекта. Модель и доступ оболочка хранит в собственных настройках; импорт MCP по явному нажатию сохраняет подключения в пользовательский `config.toml` Codex.

Выберите папку проекта, напишите задачу и нажмите Enter. Shift+Enter добавляет строку. Изображения можно вставить Ctrl+V, перетащить или выбрать кнопкой вложений. Удалить вложение можно до отправки.

Ваши сообщения расположены справа, ответы Codex — слева. Изображения, Markdown, код, файловые ссылки и сворачиваемый ход работы сохраняются.

Рабочее место сохраняется автоматически: открытые вкладки, активный диалог, черновики и картинки, настройки и место чтения возвращаются после перезапуска. Перед обычным закрытием приложение дополнительно сохраняет последние изменения. При аварийном завершении используется последний успешный снимок; выполнение задачи автоматически не продолжается. Очередь возвращается на паузе, явный полный доступ при обычном запуске снова требует выбора.

Пока Codex работает, кнопка **«Уточнить»** передаёт набранный текст и картинки в текущий запрос. **«В очередь»** добавляет их в видимую очередь над полем ввода. Обе кнопки находятся рядом с остановкой в одной строке с моделью; при пустом сообщении они видны, но неактивны. В тесном окне очередь обозначена иконкой с подсказкой. Записи можно изменить, удалить или поставить всю очередь на паузу. После успешного завершения отправляется следующий запрос; остановка, ошибка или потеря соединения приостанавливают очередь. Если отправка не подтверждена, сообщение сохраняется для проверки истории и ручного решения о повторе.

Идеи дальнейших улучшений и выбранные приоритеты собраны в [списке развития](docs/ROADMAP.md).

Колокольчик справа от вкладок открывает **«Требуют внимания»**: новые результаты, ошибки и диалоги с вопросами или запросами разрешения. У фоновой вкладки появляется отметка непрочитанного, которая снимается при просмотре. Ожидающий ответа диалог остаётся в списке до ответа.

**Уведомления Windows** сообщают о завершении, вопросах, разрешениях и ошибках, когда нужная вкладка не просматривается. Нажатие открывает её. Соседняя кнопка **«Настройки уведомлений»** позволяет отключить системные уведомления, выбрать события и включить звук (изначально выключен). Отметки во вкладках работают при любых настройках. Показ и звук также зависят от настроек уведомлений Windows.

У отправленного сообщения есть **«Редактировать»**: текст и доступные изображения переносятся в поле ввода. Исправленный вариант отправляется **новым запросом** в том же диалоге; прежняя история сохраняется. «Отмена» возвращает ваш предыдущий черновик; он также возвращается после успешной отправки исправления.

Чтобы убрать каталог из списка слева, откройте **⋮ у названия проекта → «Закрыть проект»** (также доступно по ПКМ). Его открытые вкладки закроются после подтверждения. Файлы и история Codex сохраняются; проект можно снова добавить через «Новый проект».

Рядом с вашими сообщениями — пиксельный аватар. После остановки задачи в уведомлении доступна кнопка **«Продолжить»**: она отправляет видимое сообщение «Продолжай» в тот же диалог. Вводить текст вручную не нужно; черновик и прикреплённые изображения остаются в поле ввода.

Кнопка **«Поиск в чате»** в верхней панели или **Ctrl+F** открывает поиск по текущему диалогу. Совпадения подсвечиваются; Enter/Shift+Enter и стрелки переключают их, Escape закрывает поиск. Поиск учитывает текст сообщений, код и полученный ход работы, раскрывая нужный блок. Если часть истории ещё не загружена, кнопка **«Искать в более ранних сообщениях»** подгружает предыдущую страницу. Поиск доступен и в архивных диалогах.

Поле **«Найти диалог…»** в области проектов ищет по названиям бесед во всей истории текущего Codex, группируя результаты по папкам. В архиве есть отдельное поле поиска по архивным названиям. Это поиск названий, а содержимое открытого диалога ищется через Ctrl+F.

Модель и глубина рассуждений берутся из локального Codex; их можно изменить. Под сообщением доступны три режима подтверждения действий:

- **Спрашивать разрешение** — работа в проекте; дополнительный доступ к файлам вне проекта и сети требует подтверждения пользователя.
- **Одобрять за меня** — дополнительные запросы проверяет сам Codex. Автоматическая проверка может отклонить действие, ограничения проекта сохраняются.
- **Полный доступ** — доступ к файлам и сети без запросов подтверждения.

Для новой установки выбран режим «Спрашивать разрешение». Полный доступ включается после подтверждения; при следующем подключении снова выбирается ручной режим. Старые явно сохранённые «Как в Codex» и «Только чтение» продолжают действовать до выбора одного из трёх режимов и честно показаны в кнопке. В новом списке этих пунктов нет. Изменения применяются к следующему запросу текущей вкладки. Во время выполнения модель, проект и доступ заблокированы. Кнопка остановки прерывает текущий запрос.

Модель и глубина выбираются во всплывающих меню с отметкой текущего значения. Списки поддерживают стрелки, Home/End, Enter и закрытие по Escape или нажатию снаружи. Доступные модели и уровни глубины берутся из установленного Codex.

Справа три вкладки: **«Файлы»**, **«Действия»**, **«Изменения»**. Во «Файлах» раскрывается дерево текущей рабочей папки; нажатие открывает файл. Нажмите ПКМ на файл или папку и выберите **«Спросить Codex»**: полный путь добавится в поле сообщения, где можно дописать вопрос и отправить его. Набранный текст сохраняется; можно добавить несколько путей. Меню также открывается через Shift+F10 и содержит пункт «Открыть в проводнике». «Обновить дерево файлов» перечитывает папки. Большие каталоги загружаются страницами.

В «Изменениях» одна карточка соответствует одному файлу. Она показывает путь относительно проекта и статус словами; внутри сохранены отдельные правки с количеством добавленных/удалённых строк. Длинные строки переносятся. Сводный diff текущего запроса доступен внизу списка. Блоки «Пояснения Codex» появляются только при получении текста; пустые размышления скрыты. Некоторые модели и задачи не присылают пояснений, интерфейс их не придумывает.

Выберите запрос в фильтре **«Показать изменения»** или найдите файл по части пути. **«Развернуть»** открывает большое сравнение **«До / после»** с переключением на единый diff и стрелками перехода между фрагментами. Номера строк отображаются, когда они достоверно заданы в патче; для других форматов сохраняется исходный текст. Это полученные правки из диалога — текущий файл на диске мог измениться позже.

Переключатель **«Git»** в этой же панели показывает текущую ветку и состояние файлов выбранной папки: **«Подготовлено к коммиту»**, **«Не подготовлено»**, **«Новые файлы»** и конфликты. Нажатие на файл открывает сравнение; один файл может иметь разные правки в индексе и рабочей папке. Список можно обновить кнопкой и отфильтровать по пути. Для работы нужен установленный Git. Просмотр не создаёт коммиты, не меняет индекс и не откатывает файлы.

В разделе **«Не подготовлено»** у изменённого или удалённого отслеживаемого файла есть отдельная кнопка отката. Она сначала показывает результат, затем **«Отменить изменения файла»** возвращает рабочую версию к индексу Git и сохраняет резервную копию. Подготовленные изменения остаются. Отменяются все неподготовленные правки выбранного файла, включая ручные. В **«Недавних откатах»** можно вернуть сохранённые изменения, в том числе после перезапуска; новые изменения файла или индекса после отката блокируют автоматическую отмену.

Кнопка **«+» в поле сообщения** выбирает любые локальные файлы, до 20 за один раз. Изображения PNG, JPEG, WebP и GIF добавляются с превью (до 10 по 20 МБ, всего до 60 МБ); PDF, документы, исходники, архивы и другие файлы — видимыми путями в текст сообщения. Допишите вопрос и отправьте: Codex сможет читать их доступными ему инструментами. Файлы не копируются, права доступа не меняются. **Ctrl+V** для изображений сохранён. Через дерево проекта по-прежнему работает «ПКМ → Спросить Codex».

Пояснения, комментарии и действия каждого запроса объединены в компактный **ход работы**. Пока Codex работает, он раскрыт; перед итоговым ответом сворачивается в строку вроде **«Работал 5 мин 2 с»**. Нажатие раскрывает весь полученный ход работы, а команды и результаты можно раскрыть отдельно. Итоговый ответ остаётся снаружи. Если у старой беседы нет данных о времени, показано «Ход работы». Списки проектов, файлов и действий используют уменьшенные вертикальные отступы.

В раскрытом ходе работы заголовок со словом **«Свернуть»** остаётся доступным сверху при прокрутке. В конце есть ещё кнопка **«Свернуть ход работы»**, поэтому возвращаться к началу длинного блока не требуется.

## Несколько проектов одновременно

Кнопка **«История и закладки»** в левой панели ищет текст сообщений Codex и Claude Code в выбранном проекте. Можно выбрать агента, открыть найденное сообщение и продолжить поиск кнопкой **«Искать дальше»**. Архив Codex открывается только для чтения. Рядом с сообщениями есть **«В закладки»**; во вкладке закладок можно задать свою подпись и вернуться к источнику. Закладки сохраняются после перезапуска. Подробности — [история и закладки](docs/HISTORY_LIBRARY.md).

**Ctrl+P** или **«Найти файл»** в панели файлов открывают просмотр внутри приложения: текст и код с номерами строк, Markdown с предпросмотром, изображения. Кнопка просмотра доступна и рядом с файлом в дереве. Выделите текст и нажмите **«Спросить о выделении»** — путь и фрагмент добавятся в ваш черновик; отправка остаётся за вами. Большие файлы показываются с ограничением и предупреждением. Подробности — [просмотр файлов](docs/FILE_VIEWER.md).

Слева показан компактный список рабочих папок. Нажмите на название или стрелку, чтобы раскрыть её диалоги. Можно раскрыть несколько папок одновременно; загрузка истории не переключает текущую вкладку. Кнопка **«+» рядом с папкой** создаёт новый диалог именно в этой папке, в том числе если она пустая и истории ещё нет. Кнопка **«+ Новый проект» под логотипом** открывает выбор новой рабочей папки. Список папок сохраняется после перезапуска.

Открытые диалоги находятся во **вкладках сверху**. Например, в одной вкладке можно разрабатывать проект, а в другой — исправлять постпроцессор. Переключение не останавливает работу: каждая вкладка имеет свой процесс Codex, черновик, вложения, модель, глубину рассуждений и доступ. Индикатор вкладки показывает выполнение или ожидание ответа на подтверждение.

**«+» после вкладок сверху** открывает новый диалог в текущей папке, в том числе пока другая задача выполняется. Нажатие на беседу внутри папки открывает её вкладку или переключает на уже открытую. Закрытие работающей вкладки требует подтверждения и останавливает только её процесс. Папка и история остаются доступны. Закрытие всего окна сохраняет рабочее место и завершает его процессы; после перезапуска вкладки восстанавливаются, очередь остаётся на паузе. Закрытые отдельно беседы доступны в истории. Повторный запуск ярлыка показывает текущее окно.

Новая вкладка получает начальные настройки текущей, затем они меняются независимо. Общими остаются аккаунт Codex, его история и лимиты провайдера.

## Продолжить в терминале

Кнопка **«Терминал»** под полем сообщения открывает текущий диалог в терминальном Codex с его историей, рабочей папкой, выбранными моделью, глубиной и доступом. Она доступна после начала диалога и завершения текущей операции.

В строке под сообщением сначала расположен выбор доступа, затем кнопка терминала.

Пока терминал открыт, отправка в этой вкладке приостановлена. Другие вкладки работают независимо. После выхода из Codex или закрытия терминала приложение автоматически обновляет историю и позволяет продолжить здесь. Черновик и изображения остаются в поле сообщения. Настройки выбора модели/глубины в оболочке сохраняются; изменение этих настроек командой внутри терминала не меняет селекторы оболочки.

Терминал запускает тот же установленный `codex.exe` командой `resume` с точным ID беседы. Кнопка не отправляет черновик. Закрытие Codex Desk не закрывает уже открытый внешний терминал.

## Управление диалогами и архив

В конце каждой строки диалога есть **⋮** с командами **«Переименовать»**, **«В архив»**, **«Удалить»**. Переименование обновляет название в списке и открытой вкладке. Удаление требует подтверждения: Codex удаляет историю диалога и связанные дочерние диалоги без возможности восстановления; файлы проекта остаются. Для работающего диалога действия недоступны до завершения задачи и закрытия его терминала.

Кнопка **«Архив» внизу списка проектов** раскрывает панель поверх проектов и кнопки «Новый проект». Внутри только папки, в которых есть архивированные диалоги, в том числе из папок, не открытых сейчас. Архив принадлежит самому Codex и сохраняется между запусками.

Архивный диалог открывается во вкладке **только для чтения**: можно читать сообщения, раскрывать ход работы и переходить по файловым ссылкам. Поля отправки, compact, пинга и терминала здесь нет. Меню **⋮** предлагает **«Удалить»** и **«Восстановить»**. Восстановленный диалог возвращается в историю своей папки, и его можно продолжить как обычно. Стрелка «К проектам» возвращает обычный список.

## Ссылки на файлы

Нажатие на файловую ссылку в ответе открывает файл в приложении Windows по умолчанию: изображение — в просмотрщике, документ — в соответствующей программе, `.exe` — запускается. Нажатие правой кнопкой мыши открывает меню **«Открыть в проводнике»**: проводник показывает папку и выделяет указанный файл. Веб-ссылки открываются в браузере.

Поддерживаются абсолютные и относительные пути, пробелы, кириллица, `file:///` и ссылки с номером строки. Номер строки удаляется перед открытием файла; переход к строке в редакторе пока не реализован. Локальные пути проверяются относительно папки своей вкладки. Если файл отсутствует или находится за её пределами, под сообщением появляется ошибка.

## Кэш и автопинг

Наведите курсор на количество токенов, чтобы увидеть подробности; нажмите на счётчик, чтобы **закрепить** панель. Она показывает последний запрос и накопленные расходы диалога: входные, чтение и запись кэша, выходные и токены рассуждений. Кэш уже входит во входные токены, рассуждения — в выходные, поэтому эти строки нельзя складывать повторно. Данные относятся к выбранной вкладке. Панель закрывается крестиком, Escape или нажатием снаружи.

Состав кэша по конкретным файлам/сообщениям Codex не передаёт. Панель показывает доступные счётчики и объясняет их смысл. Внизу есть кнопка **«Сжать контекст /compact»**, которая запускает штатное сжатие текущей беседы. Наведение и закрепление только показывают данные.

## Команды

Введите `/` в поле сообщения или нажмите кнопку **«Команды Codex»** рядом с выбором модели. Доступные команды:

| Команда | Действие |
| --- | --- |
| `/compact` | Сжать контекст текущего диалога через Codex. |
| `/new` | Открыть новый диалог в текущей папке. |
| `/status` | Закрепить окно подробностей токенов. |
| `/model` | Открыть выбор модели. |
| `/permissions` | Открыть выбор доступа. |
| `/resume` | Показать историю текущей папки для продолжения диалога. |
| `/help` | Показать меню поддерживаемых команд. |

Команды вводятся отдельной строкой без аргументов; регистр не важен (`/Compact` тоже работает). В подсказках выбор перемещается стрелками, Enter или Tab запускает выбранную команду, Escape закрывает меню. Обычные сообщения и пути вроде `/src/file.ts` отправляются как текст.

Compact доступен в существующем свободном диалоге. Пока Codex сжимает контекст, повторный запуск и отправка сообщения заблокированы; кнопка остановки прерывает операцию. История сообщений остаётся видимой, черновик и вложения при запуске кнопкой сохраняются. Команда не отправляется модели как пользовательское сообщение. Точный результат по токенам показывается, только если Codex прислал новые данные; заранее оценить экономию протокол не позволяет.

Под полем сообщения, в строке с доступом перед токенами, показан **«Кэш»** с обратным отсчётом. Нажатие на сам счётчик открывает его настройки. Это оценка времени после последнего ответа Codex: точное время удаления кэша провайдер не сообщает. По умолчанию срок — **1 час**, в настройках можно выбрать от 2 минут до 24 часов. При открытии старой беседы отсчёт продолжается от сохранённого времени завершения последнего успешного запроса: ответ 20 минут назад означает около 40 оставшихся минут. Дата и время показаны в настройках кэша. Если час уже прошёл, отображается «Кэш: возможно остыл»; если время неизвестно, новый час не назначается. Автопинг при открытии беседы остаётся выключенным.

Там же доступны фактические входные токены последнего запроса: **«Из кэша»**, **«Без кэша»**, а при наличии данных — запись нового кэша. Нулевое значение и отсутствие данных различаются. Некэшированные токены сами по себе не доказывают, что весь кэш остыл.

Включите **«Автопинг за 1 минуту до срока»** в нужной вкладке. Перед отправкой можно увидеть и изменить текст сообщения. Оно отправляется в ту же беседу с её текущими моделью, глубиной рассуждений и доступом; ответ остаётся в истории. Черновик и вложения не отправляются вместе с пингом. Кнопка **«Пинг сейчас»** отправляет его вручную.

Автопинг работает и в фоновой вкладке. Он не отправляет сообщения во время задачи, загрузки истории или ожидания подтверждения. Остановка, ошибка, переподключение и изменение модели/глубины/доступа выключают автопинг. Если срок пропущен, например после сна компьютера, догоняющие запросы не отправляются. Каждая новая вкладка начинает с выключенным автопингом; его состояние, срок и текст действуют в пределах открытой вкладки.

Пинг — настоящий запрос модели: расходует токены и лимиты, а сохранение кэша зависит от провайдера и не гарантируется. Для завершения автопинга снимите флажок или закройте вкладку.

## MCP-серверы

Откройте **«Настройки» → «MCP-серверы» → «Добавить из текста»**. Вставьте JSON с объектом `mcpServers` либо TOML-блоки `[mcp_servers.имя]` и нажмите **«Проверить текст»**. Формат определяется автоматически; поддерживаются несколько серверов, HTTP-подключения и локальные серверы через `command`/`args`.

JSON из инструкции можно вставить целиком: `type: "http"` проверяется, `headers` переводится в `http_headers`, а `mcpServers` — в `mcp_servers`. Поддержаны также `type: "streamable-http"` и `type: "stdio"`; без `type` подключение определяется по `url` или `command`. Значения заголовков и переменных сохраняются без подстановок. Конфликтующие поля и неподдерживаемые типы отклоняются. Итоговый файл Codex остаётся в формате TOML.

Предпросмотр показывает имена, адреса и названия заголовков; значения токенов и переменных скрыты, поле исходного текста очищается. Нажмите **«Сохранить MCP»**. При совпадении имени нужно отметить **«Обновить существующие серверы»**: указанный сервер целиком заменяется вставленным описанием, остальные разделы остаются прежними. Отмена не меняет файл.

Фактический путь конфига сообщает используемый Codex, поэтому учитывается нестандартный `CODEX_HOME`. Перед записью создаётся резервная копия рядом с конфигом; её путь показывается после сохранения. Если файл успел измениться, нужно заново проверить вставленный блок. Текст передаётся локальному Codex для записи настроек и не отправляется модели. Секреты сохраняются в конфиге; копия предыдущего конфига также может содержать секреты.

Новые сессии читают настройки автоматически. Для открытой вкладки нажмите **«Применить в этой сессии»** после завершения текущей задачи. Обновление MCP не перезапускает диалог и не меняет модель. **«Проверить подключение»** запрашивает у Codex статусы и количество доступных инструментов; сами инструменты и модель не вызываются. Работающий запрос, compact, подтверждение или открытый терминал откладывают применение до повторного нажатия. Другие вкладки можно обновить отдельно.

Раздел показывает MCP пользовательского конфига; настройки профиля/проекта могут их переопределять. Неизвестные поля, другие разделы конфигурации и некорректный TOML не импортируются.

## Диагностика ошибок

Журнал включён автоматически. Если возникла проблема, нажмите **«Диагностика» внизу слева → «Сохранить диагностику»** и выберите место для JSON-файла. Передайте этот файл вместе с описанием действий и примерным временем ошибки. Отчёт включает доступные записи предыдущих запусков, поэтому его можно сохранить и после перезапуска.

Записываются версии приложения, Windows и Codex, операции и их длительность, категории ошибок и места сбоев в коде. Тексты сообщений, файлы проекта, изображения, пароли, заголовки авторизации и полный конфиг в журнал не копируются. Названия проектов и идентификаторы диалогов заменяются техническими обозначениями. Произвольный текст ошибки также исключается: для неизвестной ошибки иногда потребуется дополнительное описание.

Данные остаются на компьютере; автоматической отправки нет. **«Открыть папку»** показывает журналы в проводнике. Точный путь указан в окне диагностики — это каталог `logs` внутри данных Codex Desk. Старые записи заменяются новыми; обычный предел — 10 МиБ. Отдельные одновременно запущенные экземпляры имеют собственный лимит.

Кнопка работает без подключения к Codex и без открытых диалогов. При ошибке отображения React приложение показывает отдельный экран, с которого также можно сохранить диагностику. Если окно совсем не открывается, путь к журналам указывается в сообщении об ошибке запуска. Сбои до загрузки основного кода приложения и внезапное отключение питания могут не попасть в журнал.

UI-тест проверяет настоящее окно Electron и сценарии интерфейса; синтетические события отделены от проверки реального соединения.

## Устройство

- React + TypeScript + Vite — интерфейс.
- Electron main — выбор папки, хранение вложений, управление собственным процессом Codex.
- `codex app-server --listen stdio://` — официальный двунаправленный JSONL-протокол, без HTTP-сервера и разборов текста терминала.
- `protocol/` — справочные схемы, сгенерированные установленным Codex `0.154.0-alpha.6.2`. Код адаптера использует ограниченный набор методов; схемы не включаются в приложение.
- История бесед хранится самим Codex и читается через его API. Внутренние SQLite-базы не редактируются.

Окно работает с изолированным контекстом, без Node.js в renderer. IPC ограничен списком методов. Markdown не исполняет HTML. Файловые ссылки открываются только по действию пользователя; ПКМ позволяет показать файл в проводнике. Выбор полного доступа действует только после явного подтверждения в интерфейсе; режим не включает его автоматически при следующем запуске.

Настройки оболочки, список папок (`workspace.json`) и изображения хранятся в каталоге Electron `userData` (обычно `%APPDATA%/Codex Desk`). Вложения сохраняются для ссылок в истории; автоматическое удаление пока не реализовано. Беседы и авторизация остаются в хранилище Codex. Закрытие окна завершает процессы App Server всех его вкладок; для продолжения откройте беседу из истории.

## Ограничения первой версии

- Это самостоятельный клиент Codex, а не встраивание его терминального экрана. Одинаковые модель, effort и инструкции помогают сохранить поведение CLI, но идентичность ответов не гарантируется.
- App Server развивается; после обновления Codex может потребоваться обновить адаптер. Документация: https://developers.openai.com/codex/app-server
- Просмотр изменений отражает события Codex в беседе. Отдельного редактора файлов, Git staging и отката изменений пока нет.
- Формы сторонних MCP-подключений можно отклонить; полноценный UI таких форм пока не реализован.
- Первая версия использует настроенный CLI-вход/провайдер. Отдельный мастер входа в аккаунт не реализован.
- Сборка локальная, без подписи и автообновления.

Проверено на этом компьютере: 17 тестов транспорта/обработки вложений; реальное окно Electron с моделями и вставкой PNG; сценарии потоковых сообщений, подтверждений, diff и остановки; реальный ответ Codex на картинку с восстановлением беседы и картинки после перезапуска. Реальный сервер здесь использует legacy history; ветка paginated проверена по схемам, но не живой беседой.
